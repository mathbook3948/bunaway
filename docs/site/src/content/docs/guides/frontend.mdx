bunaway UI는 WebView에서 실행할 HTML, CSS, JavaScript 자산입니다.
현재 CLI는 vanilla와 Vite 기반 TypeScript 템플릿을 제공합니다.
`--template vite`, `react`, `vue`, `svelte`로 UI 프레임워크를 선택합니다.

## 권장 시작점

처음에는 [vanilla 첫 앱](/start/quickstart/)으로 명령과 정책을 살펴보고
CSS HMR이 필요하면 [Vite 템플릿](/guides/development/)을 사용합니다.
어떤 UI 도구를 사용하든 백엔드는 공통 app.ts에 작성합니다.

## 기존 웹 도구 연결

UI 도구를 바꿀 때 아래 항목을 연결합니다.

| 설정 | 확인할 것 |
| --- | --- |
| UI 프로덕션 빌드 | 로컬 앱에 포함할 정적 자산 출력 |
| build.frontend | 실제 웹 출력 디렉터리 |
| app.home | 출력 안의 시작 HTML에 대응하는 로컬 자산 URL |
| dev.command | 개발 서버의 실행 파일, 인자 배열 |
| dev.url | 정확한 loopback URL, 고정 포트, HTTP 준비 |
| SDK | 앱 정의의 타입을 지정한 client.invoke, client.listen 호출 |

네이티브 프로덕션 빌드 전에 웹 자산을 빌드합니다. 최종 앱은 정적 출력물을 사용하며 Next.js의 SSR 서버는 포함하지 않습니다.
React, Vue, Svelte 생성 앱에는 위 설정이 포함됩니다. 기존 웹 프로젝트에도 같은 설정을 연결할 수 있습니다.

## 화면에서 명령 호출과 이벤트 구독

모든 UI는 앱 정의의 타입을 지정한 클라이언트를 만들고 재사용합니다. vanilla, Vite, React, Vue, Svelte와 기존 웹 프로젝트에 같은 원칙을 적용합니다.
`client.invoke`는 백엔드에 작업을 요청하고 결과를 받습니다. `client.listen`은 이벤트가 발생할 때마다 콜백을 실행합니다.

```ts
import { createClient } from "@bunaway/client";
import type { CommandsOf, EventsOf } from "@bunaway/backend";
import type { app } from "../src-bunaway/app.ts";

async function start() {
  const client = createClient<CommandsOf<typeof app>, EventsOf<typeof app>>();
  const unlisten = await client.listen(
    "message.saved",
    (event) => console.log("저장된 내용:", event.payload),
    { onError: console.error },
  );
  try {
    await client.invoke("message.save", "안녕하세요");
    const text = await client.invoke("message.read", null);
    console.log(text);
    return { client, unlisten };
  } catch (error) {
    await unlisten();
    throw error;
  }
}
```

UI 초기화 훅에서 `start()`를 호출하고 반환한 클라이언트와 해제 함수를 보관합니다. 생성 오류와 초기 호출 실패를 UI에서 처리합니다.
클라이언트는 컴포넌트와 이벤트 핸들러에서 재사용합니다.
UI 컴포넌트를 제거할 때는 `await unlisten()`으로 해당 구독을 해제합니다.
React나 Vue, Svelte에서도 컴포넌트의 정리 시점에 이 해제 함수를 호출합니다.
컴포넌트마다 공유 클라이언트를 닫지 않습니다. 기본 연결은 페이지 종료 때 자동으로 정리됩니다.
클라이언트 생성은 브라우저의 마운트나 초기화 시점에 실행하고 SSR이나 컴포넌트 렌더 함수에서는 실행하지 않습니다.
[타입과 입력 검증](/guides/types-and-validation/)에서 타입 추론 범위를 확인하세요.

## 브라우저와 WebView

일반 브라우저에는 네이티브 브리지가 없습니다.
SSR 코드에서도 SDK를 import할 수 있습니다.
기본 API를 실제로 호출하면 `UNSUPPORTED`로 실패합니다. 백엔드 호출은 실제 네이티브 창에서 확인합니다.
브라우저 미리보기에서 앱 기능을 시험하려면 [사용자 정의 클라이언트](/reference/client/transport/)에 테스트 어댑터를 전달합니다. 권한 검사는 실제 WebView에서 확인합니다.
백엔드 코드, 비밀 설정은 프런트엔드 번들에 넣지 않습니다.

## 자산과 CSP

템플릿 HTML의 CSP를 유지하고 UI 의존성에 필요한 출처를 검토합니다.
Vite 기반 템플릿은 개발 페이지에서만 CSS 갱신과 해당 loopback HMR WebSocket을 허용합니다.
React 템플릿은 Fast Refresh에 필요한 인라인 스크립트도 개발 페이지에서만 허용합니다.
프로덕션은 `script-src 'self'; style-src 'self'`를 유지하고 이미지는 로컬 파일로 출력합니다.
production 정책에 HTTP 개발 origin을 추가하지 않습니다.
배포한 앱의 UI와 백엔드는 호스트 브리지로 통신합니다.
