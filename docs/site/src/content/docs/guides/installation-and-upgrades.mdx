bunaway 개발 의존성은 앱의 package.json, bun.lock으로 관리합니다.
SDK와 CLI는 node_modules에 설치합니다. 설치 버전은 bun.lock에 기록합니다.
첫 설치 명령은 [첫 앱](/start/quickstart/)에 있습니다.

## 현재 배포 방식

공개 패키지 레지스트리에는 아직 배포하지 않았습니다. 관리자가 `bun run framework:pack --local`로
같은 버전의 CLI, SDK 묶음을 준비하고 create의 `--package-dir`로 연결합니다.
`--local`의 의존성은 묶음의 절대 경로라서 묶음을 다른 위치로 옮기면 그 위치에서 다시 만들어야 합니다.
다시 설치할 때도 같은 파일을 사용하도록 tarball 묶음을 보관합니다.

## 설치하는 패키지

| 패키지 | 역할 |
| --- | --- |
| @bunaway/client | WebView 클라이언트 |
| @bunaway/backend | 앱 정의, 명령, 이벤트 타입 |
| @bunaway/core | 공통 실행 계층 |
| @bunaway/runtime-bun | 앱 백엔드 실행 |
| @bunaway/protocol | 메시지, 정책, Host API 계약 |
| @bunaway/packaging | 배포 채널별 패키징 |
| @bunaway/cli | 생성, 검증, 개발, 빌드, 패키징과 플랫폼 입력 |

앱이 직접 설치한 SDK와 다른 패키지가 의존하는 SDK는 같은 정확한 릴리스를 사용해야 합니다.

## 재현 설치

앱 소스, 설정, package.json, bun.lock을 커밋하고 아래로 설치합니다.

```sh
bun install --frozen-lockfile
```

node_modules, .bunaway, dist, web-dist는 생성물입니다.
SDK는 같은 릴리스로 함께 설치해야 합니다. overrides/resolutions나 TS aliases로 일부 SDK 버전만 바꾸면 검증에 실패할 수 있습니다.

## 업그레이드와 되돌리기

1. 새 릴리스의 로컬 묶음을 준비합니다.
2. 같은 묶음으로 만든 참조 앱과 @bunaway 의존성 선언을 비교해 모두 갱신합니다.
3. `bun install`로 lockfile을 갱신합니다.
4. 앱의 typecheck, validate, doctor를 실행한 뒤 dev와 build로 기존 기능이 동작하는지 확인합니다.
5. 실패하면 이전 package.json, bun.lock을 복원하고 frozen install합니다.

Vite에서는 validate, build 전에 웹 프로덕션 빌드가 필요합니다.
이전 tarball도 보관해야 롤백 설치가 가능합니다.
현재 이전 vendor/분리 설정으로의 자동 마이그레이션이나 fallback은 없습니다.

개발 도구를 준비할 때는 다운로드가 필요합니다. 배포한 앱은 포함된 런타임과 자산을 사용합니다.
