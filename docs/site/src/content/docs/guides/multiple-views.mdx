Windows 호스트를 개발할 때 참고하는 여러 창과 뷰의 구현 계약입니다.
CLI로 만드는 앱은 창과 뷰 하나를 사용합니다. 앱 개발 지원 상태는 [지원 범위](/reference/platforms/)에서 확인하세요.

## 연결 구조

```text
main 창   → main 정책   → main 세션
editor 창 → editor 정책 → editor 세션
reader 창 → reader 정책 → reader 세션
                 ↓
        공통 앱 백엔드, 명령, 상태
```

명령 구현과 플러그인, 앱 메모리 상태는 공유합니다.
요청 결과와 이벤트 구독은 각 창의 연결에 속합니다.

## 정책, 이벤트, 종료

reader에 읽기 명령과 Host 읽기 권한을 주고 editor에는 쓰기 권한도 추가하는 식으로 설정합니다.
broadcast 이벤트는 이벤트가 허용된 뷰의 활성 구독에 전달합니다.
한 창을 닫으면 그 창의 연결이 끝나고 다른 창과 백엔드는 계속 실행합니다.
기본값은 마지막 창 닫기로 앱을 종료하는 것입니다. `desktop.beforeQuit`로 종료를 취소하거나
`desktop.closeBehavior: "hide"`와 트레이를 설정해 창과 연결을 유지할 수 있습니다.

동적 창 생성 공개 명령, 닫힌 창 재생성, 이전 세션 복원, 뷰의 창 간 이동은 현재 제공하지 않습니다.
macOS는 단일 창과 뷰입니다.
[창과 뷰의 정책](/concepts/views-and-policy/)과 [수명주기](/guides/sessions-and-lifecycle/)를 함께 참고하세요.
