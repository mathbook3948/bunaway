**Windows 런타임은 여러 창과 뷰를 지원합니다. CLI로 만드는 앱은 창 하나와 뷰 하나를 사용합니다.**
이 페이지에서는 런타임 내부의 연결 구조와 설정을 설명합니다.

## 연결 구조

```text
main 창   → main 정책   → main 세션
editor 창 → editor 정책 → editor 세션
reader 창 → reader 정책 → reader 세션
                 ↓
        공통 앱 백엔드, 명령, 상태
```

각 창의 WebView 환경, 브라우저 데이터 디렉터리, 활성 문서 세대는 분리합니다.
명령 구현과 플러그인, 앱 메모리 상태는 공유합니다.
요청과 구독은 세션마다 관리하므로 다른 세션에서 같은 요청 ID를 사용해도 응답이 섞이지 않습니다.

## 실제 런타임 설정

내부 Windows app.json은 windows 배열의 각 창에 view, home, title, window를 지정합니다.
view는 정책의 id를 선택하고 중복된 창 view ID를 허용하지 않습니다.
현재 런타임은 창을 최대 128개까지 설정합니다. 이전 C++ 구현은 최대 8개였으므로 옛 실행 기록을 읽을 때 이 차이를 확인하세요.
세 창의 실제 검증 fixture는 다음 위치에 있습니다.

- [창 설정](https://github.com/mathbook3948/bunaway/blob/main/tests/fixtures/desktop/host/app.json)
- [뷰별 정책](https://github.com/mathbook3948/bunaway/blob/main/tests/fixtures/desktop/host/policy.json)

CLI가 만든 app.json은 자산 해시에 포함됩니다. 직접 수정하면 무결성 검사가 실패합니다.
CLI의 bunaway.json은 현재 단일 창 형식이며 windows 필드를 받지 않습니다.

## 정책, 이벤트, 종료

reader에 읽기 명령과 Host 읽기 권한을 주고 editor에는 쓰기 권한도 추가하는 식으로 설정합니다.
broadcast 이벤트는 이벤트가 허용된 뷰의 활성 구독에 전달합니다.
한 창을 닫으면 그 세션을 폐기하고 다른 창과 백엔드는 계속 실행합니다.
마지막 창 종료가 앱 종료입니다.

동적 창 생성 공개 명령, 닫힌 창 재생성, 이전 세션 복원, 뷰의 창 간 이동은 현재 제공하지 않습니다.
macOS는 단일 창과 뷰입니다.
[창, 뷰 정책](/concepts/views-and-policy/)과 [수명주기](/guides/sessions-and-lifecycle/)를 함께 참고하세요.
