Windows 호스트를 개발할 때 참고하는 창과 뷰의 구현 계약입니다.
CLI의 `app` 설정은 이 구조에 창을 연결합니다. 앱에서 사용하는 공개 API와 설정은
[창 만들기와 제어](/guides/windows/)에서 확인하세요.

## 연결 구조

```text
main 창 → main 정책 → main 세션
               ↓
      공통 앱 백엔드, 명령, 상태
```

앱은 창 하나와 WebView 하나를 가집니다. 정책에는 뷰 하나를 선언하며 호스트는 호출 출처를 그 뷰로 인증합니다.
명령 구현과 플러그인, 앱 메모리 상태는 백엔드가 소유합니다. 요청 결과와 이벤트 구독은 창의 연결에 속합니다.

## 정책, 이벤트, 종료

뷰의 정책이 호출할 명령과 받을 이벤트, Host API 권한을 정합니다.
이벤트는 허용된 뷰의 활성 구독에 전달합니다.
창을 닫으면 그 창의 연결이 끝납니다.
기본값은 창 닫기로 앱을 종료하는 것입니다. `desktop.beforeQuit`로 종료를 취소하거나
`desktop.closeBehavior: "hide"`와 트레이를 설정해 창과 연결을 유지할 수 있습니다.
`"keep-alive"`는 창과 연결을 정리한 뒤에도 백엔드를 유지합니다.
시작 창을 생략하는 설정과 나중의 창 생성은 [창 없는 시작](/guides/windows/#창-없는-시작)을 따릅니다.

공개 `windows.create`, `windows.recreate`는 설정한 창을 생성합니다.
재생성은 이전 세션을 폐기하고 네이티브 정리 완료 후 새 세션을 만들며 같은 프로필을 유지합니다.
교체 중에는 다른 생성 요청을 거부하고 창 종료 통지를 보류합니다.
닫힌 창의 COM 핸들러는 정리 후 해제해 반복 재생성 시 계속 쌓이지 않게 합니다.
이전 세션 복원은 제공하지 않습니다.
macOS도 단일 창과 뷰입니다.
[창과 뷰의 정책](/concepts/views-and-policy/)과 [수명주기](/guides/sessions-and-lifecycle/)를 함께 참고하세요.
