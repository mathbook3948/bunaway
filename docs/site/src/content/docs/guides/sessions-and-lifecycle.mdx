---
title: 세션과 수명주기
description: 앱이 시작되고 문서가 다시 연결되거나 창이 닫힐 때의 처리 과정.
---

앱은 여러 세션을 관리하며 요청은 세션 안에서 실행합니다.
같은 뷰 ID로 다시 연결하면 새 세션을 만듭니다.

## 시작

프레임워크가 앱 정의와 정책을 읽고 명령, 이벤트, 상태를 등록합니다.
플러그인은 의존 순서대로 setup을 실행합니다. 모두 끝나면 코어가 준비됩니다.
호스트는 실제 문서의 출처와 frame을 확인하고 새 호출 컨텍스트와 세션을 만듭니다.
웹 클라이언트는 hello로 협상한 뒤 ready가 완료되면 명령을 호출하고 이벤트를 구독합니다.

## 수명별 소유 데이터

| 단위 | 소유하거나 구분하는 것 |
| --- | --- |
| 앱 백엔드 | 명령 구현, 공통 메모리 상태, 플러그인 |
| 창 | OS 창과 WebView 자원 |
| 뷰 | 접근 정책 |
| 문서, 세션 | 협상, 요청 ID, 구독, 호스트 컨텍스트 |
| 요청 | 입력, 기한, 취소 신호, 컨텍스트에 묶인 Host 작업 |

요청 ID가 같아도 서로 다른 세션의 응답은 독립입니다.
같은 세션에서는 요청 ID를 재사용하지 않습니다.
HostContext와 런타임 세대는 호스트가 관리하며 프런트엔드가 만들지 않습니다.

## 탐색, 렌더러 복구, 개발 재시작

문서가 교체되거나 호스트가 렌더러를 복구하면 오래된 세션을 폐기합니다.
새 클라이언트가 협상한 뒤 이벤트를 구독하고 상태를 다시 읽습니다.
Windows에서는 복구가 필요한 뷰만 새 세션을 만들고 다른 뷰와 백엔드는 계속 실행합니다.

CLI의 백엔드 재시작은 새 앱 실행과 메모리 상태를 만듭니다.
Vite HMR이 UI만 갱신할 때는 백엔드가 계속 실행됩니다.
백엔드가 재시작되면 진행 중 요청과 구독을 정리합니다. 이전 요청은 자동으로 다시 보내지 않습니다.

## 종료

클라이언트 close는 해당 연결의 대기 작업과 전송을 정리합니다.
호스트의 창 닫기는 해당 뷰 세션을 폐기합니다.
현재 Windows에서 마지막 창을 닫으면 코어, Worker, WebView 자원을 정리하고 앱을 종료합니다.
플러그인 StopHook은 역순으로 실행합니다.

코어 정리는 core.stop()이 맡고 자식 프로세스의 종료 확인은 호스트가 맡습니다.
종료에는 기한이 있으므로 중요한 데이터는 사용자가 작업하는 동안 저장합니다.
