title: 세션과 수명주기
description: 앱이 시작되고 문서가 다시 연결되거나 창이 닫힐 때의 처리 과정.
---

세션은 웹 UI가 백엔드에 연결된 동안의 요청과 구독을 구분합니다.
같은 뷰 ID로 다시 연결해도 이전 요청과 구독은 이어지지 않습니다.

## 시작

앱 정의를 default export하고 policy.json에 사용할 기능을 허용합니다.
플러그인의 setup이 끝나면 명령을 처리할 준비가 됩니다. UI에서는 createClient로 연결하고 client.ready로 준비 상태를 확인합니다.

## 수명별 소유 데이터

| 단위 | 소유하거나 구분하는 것 |
| --- | --- |
| 앱 백엔드 | 명령 구현, 공통 메모리 상태, 플러그인 |
| 창 | OS 창과 WebView 자원 |
| 뷰 | 접근 정책 |
| 문서, 세션 | 클라이언트 연결, 진행 중 요청, 이벤트 구독 |
| 요청 | 입력, 기한, 취소 신호, 컨텍스트에 묶인 Host 작업 |

## 탐색, 렌더러 복구, 개발 재시작

문서가 교체되거나 호스트가 렌더러를 복구하면 오래된 세션을 폐기합니다.
새 클라이언트를 만들고 이벤트를 구독한 뒤 상태를 다시 읽습니다.
Windows에서는 복구가 필요한 뷰만 새 세션을 만들고 다른 뷰와 백엔드는 계속 실행합니다.

CLI의 백엔드 재시작은 새 앱 실행과 메모리 상태를 만듭니다.
Vite HMR이 UI만 갱신할 때는 백엔드가 계속 실행됩니다.
백엔드가 재시작되면 진행 중 요청과 구독을 정리합니다. 이전 요청은 자동으로 다시 보내지 않습니다.

## 종료

클라이언트 close는 해당 연결의 대기 작업과 전송을 정리합니다.
호스트의 창 닫기는 해당 뷰 세션을 폐기합니다.
현재 Windows에서 마지막 창을 닫으면 앱이 종료됩니다.
플러그인 StopHook은 역순으로 실행합니다.

종료에는 기한이 있으므로 중요한 데이터는 사용자가 작업하는 동안 저장합니다.
