title: 여러 창 만들기
description: 창 설정을 작성하고 앱 명령에서 보조 창을 생성하고 제어합니다.
---

Windows 앱은 `src-bunaway/bunaway.json`의 `app.windows`에 사용할 창을 정의합니다.
기본 템플릿의 단일 창 설정에서 `view`, `home`, `window`를 제거하고 아래처럼 작성하세요.
`app.title`은 앱 이름이며 각 창의 제목은 배열 항목의 `title`입니다.

```json
{
  "appId": "app.notes",
  "title": "Notes",
  "windows": [
    {
      "view": "main", "title": "Notes",
      "home": "https://app.bunaway.local/index.html",
      "window": { "width": 800, "height": 600 }
    },
    {
      "view": "editor", "title": "Editor", "startup": false,
      "home": "https://app.bunaway.local/editor.html",
      "window": { "width": 600, "height": 500, "minWidth": 480, "minHeight": 360 }
    }
  ]
}
```

위 예제는 `app` 필드에 작성합니다. `build`와 `bundle` 등 기존 최상위 설정은 유지합니다.
`editor.html`을 웹 자산에 추가하고 `policy.json.views`에 `main`, `editor` 정책을 선언합니다.
main에서 editor를 여는 명령을 호출하려면 main의 `commands`에 `editor.open`과
`editor.prepareClose`를 추가하고 host.permissions에 `windows:list`와 `{ "identifier": "windows:control", "allow": [{ "view": "editor" }] }`를 허용하세요. 먼저 `@bunaway/plugin-windows`를 설치합니다.
editor에는 필요한 명령과 이벤트, 저장 권한만 선언할 수 있습니다.

```ts
import { defineApp, defineModule } from "@bunaway/backend";
import { windows, windowsPlugin } from "@bunaway/plugin-windows";

const editor = defineModule("editor")
  .command("open", { input: { const: null }, output: { const: null } }, async () => {
    const configured = await windows.list();
    if (!configured.find((window) => window.view === "editor")?.open) {
      await windows.create({ view: "editor" });
    }
    await windows.show({ view: "editor" });
    return null;
  })
  .command("prepareClose", { input: { const: null }, output: { const: null } }, async () => {
    await windows.setCloseConfirmation({ view: "editor", message: "편집 창을 닫을까요?" });
    return null;
  });

export default defineApp({ modules: [editor], plugins: [windowsPlugin] });
```

프런트엔드는 초기화한 클라이언트로 창을 연 뒤 닫기 확인을 설정합니다.

```ts
await client.invoke("editor.open", null);
await client.invoke("editor.prepareClose", null);
```

[프런트엔드 가이드](/guides/frontend/)처럼 `CommandsOf`와 `EventsOf`로 타입을 연결하는 것을 권장합니다.
동시에 창을 여는 요청이 겹치면 `BUSY`를 처리하세요.

`startup`을 생략하면 앱 시작 때 엽니다. `false`인 창은 API로 생성합니다.
닫은 보조 창을 다시 열 때도 `create`를 사용합니다. 새 문서로 다시 시작하려면
`recreate`를 사용하고 기존 창의 정리가 완료될 때까지 기다립니다.
모든 창을 닫으면 앱이 종료되므로 보조 창을 다시 열려면 주 창을 유지하세요.

개발 서버를 사용하면 각 창의 `home` 경로와 query를 같은 loopback 서버에 연결합니다.
위 예제에서는 `/index.html`, `/editor.html`을 각각 제공해야 합니다.
`dev.url`은 서버의 준비 확인 주소이며 프로덕션 `home`은 그대로 둡니다.

초기 창 크기 제약, 권한, 전체화면과 포커스, 닫기 확인과 재생성 수명은
[windows API](/reference/host/windows/)에서 확인할 수 있습니다.
Windows에서 현재 입력 포커스를 유지하며 보조 창의 숨김만 해제하려면
`windows.showInactive({ view: "editor" })`를 사용합니다. 최소화와 최대화 상태는 유지합니다.
표시된 비최소화 창으로 전환할 때는 `windows.activate({ view: "editor" })`를 호출하고
반환된 boolean으로 전경 여부를 확인합니다. 숨김이나 최소화도 해제하려면 `focus`를
사용하고 `BUSY`를 처리하세요. `windows.blur({ view: "editor" })`는 설정 순서에서
제어 권한이 있는 표시된 비최소화 창을 골라 전환합니다. 다음 창이 없거나 전환 후에도
editor가 전경이면 `false`입니다. 호출자 권한과 후보 선택은 위 API 계약을 따릅니다.
창 생성과 기본 제어는 Windows와 macOS를 지원합니다. 위 `prepareClose`처럼 닫기
확인을 설정하는 작업은 Windows만 지원합니다. macOS는 뷰별 임시 프로필을 앱 실행 중 유지합니다.

Windows에서 내용 영역의 위치와 크기를 한 번에 바꾸려면 명령 핸들러에서
`windows.setContentBounds({ view: "editor", x: 100, y: 120, width: 800, height: 600, unit: "logical" })`를 호출합니다.
내용 위치만 바꿀 때는 `setContentPosition`, 제목 표시줄과 테두리를 포함한 크기와 영역은
`setOuterSize`, `setOuterBounds`를 사용합니다. 기본 단위는 물리 픽셀입니다.
숨긴 창은 표시하지 않으며 최소화나 최대화 중에는 일반 복원 영역을 변경합니다.
전체화면은 먼저 해제해야 합니다. 크기 제약을 적용한 결과는 같은 단위의 geometry 조회로 확인하고
변경 알림은 `windows.changed`로 구독하세요. 입력 범위, 반올림과 오류는 위 API 문서를 따릅니다.

## 숨김 준비와 splashscreen 전환

Windows에서는 준비 전에 화면을 표시하지 않으려면 창 항목에 `visible: false`를 지정합니다.
문서만 기다린 뒤 자동으로 표시하려면 `showWhenReady: "document"`, SDK도 기다리려면 `"sdk"`를 씁니다.
앱 데이터를 기다리는 splashscreen 흐름에는 자동 표시를 생략하고 앱이 전환 시점을 결정하세요.

```json
{
  "windows": [
    {
      "view": "splash", "title": "준비 중",
      "home": "https://app.bunaway.local/splash.html",
      "window": { "width": 400, "height": 300 }
    },
    {
      "view": "main", "title": "Notes", "visible": false,
      "home": "https://app.bunaway.local/index.html",
      "window": { "width": 800, "height": 600 }
    }
  ]
}
```

두 창을 시작 창으로 만들면 splash가 표시되는 동안 숨긴 주 창에서 앱을 준비합니다.
주 창을 나중에 만들 때는 `startup: false`를 추가하고 splash나 백엔드에서 `windows.create({ view: "main" })`를 호출합니다.
주 창이 준비되기 전에 splash를 따로 닫지 마세요. 주 창에서 필요한 데이터 로드와 UI 초기화를 마친 뒤
`windows.completeSplashscreen({ view: "main", splash: "splash" })`를 호출합니다.
이 호출은 주 창이나 백엔드에서 실행하세요. splash 창에서 호출하면 `INVALID_ARGUMENT`가 반환되고 전환하지 않습니다.
이 API가 주 창을 먼저 표시하고 splash를 닫으므로 마지막 창 종료로 앱이 중간에 종료되지 않습니다.
닫기 확인으로 `false`가 반환되면 두 창은 유지되므로 앱에서 재시도를 제공할 수 있습니다.

main 정책의 `commands`에 `plugin.windows.getReadiness`, `plugin.windows.completeSplashscreen`을,
`events`에 `windows.readiness`를 추가합니다. `host.permissions`의 `windows:control`에
main과 splash를 모두 허용해야 전환할 수 있습니다.
준비 알림을 splash에서도 받으려면 splash의 events와 대상 창 제어 권한도 허용하세요.

```ts
import { createClient } from "@bunaway/client";
import type { CommandsOf, EventsOf } from "@bunaway/backend";
import { windows, type WindowOutput } from "@bunaway/plugin-windows";
import type { app } from "../src-bunaway/app.ts";

// UI 초기화 함수에서 실행합니다. initializeUi는 앱이 소유한 데이터와 화면 초기화 작업입니다.
const client = createClient<CommandsOf<typeof app>, EventsOf<typeof app>>();
await client.ready;
await initializeUi();
let transitioning = false;
async function finish(state: WindowOutput<"windows.getReadiness">): Promise<void> {
  if (state.viewId !== "main" || transitioning) return;
  if (state.error) throw new Error(state.error.message);
  if (state.document !== "ready" || state.sdk !== "ready") return;
  transitioning = true;
  try {
    const closed = await windows.completeSplashscreen({ view: "main", splash: "splash" });
    if (!closed) console.log("전환 창의 닫기를 취소했습니다.");
  } finally {
    transitioning = false;
  }
}
const release = await client.listen("windows.readiness", (event) => {
  void finish(event.payload).catch(console.error);
}, { onError: console.error });
try {
  // 구독 전에 완료된 단계도 조회로 확인합니다.
  await finish(await windows.getReadiness({ view: "main" }));
} catch (error) {
  await release();
  throw error;
}
// 컴포넌트 정리 때 await release()를 호출하고 공유 client는 유지합니다.
```

이벤트와 조회를 화면 상태에 함께 저장하는 앱은 현재 창 ID와 revision으로 오래된 상태를 제외하세요.
새 탐색과 창 재생성, 기한, 취소 및 단계별 정확한 완료 조건은 [창 준비](/reference/host/windows/#창-준비)를 따릅니다.
