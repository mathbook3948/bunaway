---
title: 창 만들기와 제어
description: 창 설정을 작성하고 앱 명령에서 창을 생성하고 제어합니다.
---

앱은 창 하나와 WebView 하나를 가집니다. `src-bunaway/bunaway.json`의 `app`에 창을 설정하며
`view`를 생략하면 정책의 유일한 뷰를 사용합니다. `app.title`은 앱 이름이자 창 제목입니다.

```json
{
  "appId": "app.notes",
  "title": "Notes",
  "home": "https://app.bunaway.local/index.html",
  "window": { "width": 800, "height": 600 }
}
```

위 예제는 `app` 필드에 작성합니다. `build`와 `bundle` 등 기존 최상위 설정은 유지합니다.
창을 앱 명령에서 제어하려면 먼저 `@bunaway/plugin-windows`를 설치하고 앱의 `plugins`에 등록합니다.
뷰의 `commands`에 호출할 앱 명령을 추가하고 `host.permissions`에는 사용할 작업 이름
(`windows.isOpen`, `windows.create`, `windows.show`, `windows.setCloseConfirmation` 등)을
각각 문자열로 허용합니다.

```ts
import { defineApp, defineModule } from "@bunaway/backend";
import windows from "@bunaway/plugin-windows";

const window = defineModule("window")
  .command("reopen", { input: { const: null }, output: { const: null } }, async () => {
    if (!(await windows.isOpen())) {
      await windows.create();
    }
    await windows.show();
    return null;
  })
  .command("prepareClose", { input: { const: null }, output: { const: null } }, async () => {
    await windows.setCloseConfirmation({ message: "창을 닫을까요?" });
    return null;
  });

export default defineApp({ modules: [window], plugins: [windows] });
```

프런트엔드는 초기화한 클라이언트로 명령을 호출합니다.

```ts
await client.invoke("window.prepareClose", null);
```

[프런트엔드 가이드](/guides/frontend/)처럼 `CommandsOf`와 `EventsOf`로 타입을 연결하는 것을 권장합니다.
동시에 창을 여는 요청이 겹치면 `BUSY`를 처리하세요.

`startup`을 생략하면 앱 시작 때 창을 엽니다. `startup: false`이면 창을 API로 생성합니다.
창 입력은 대상 창을 고르는 필드를 받지 않으며 제거한 `view`, `windowId` 등을 전달하면 `INVALID_ARGUMENT`입니다.
생성 API는 `{ options? }`를 받습니다. 제목, 부분 크기와 제약,
표시와 준비 후 표시를 이번 생성에만 바꿀 수 있습니다. 자세한 값과 해제 방법은
[창 API](/reference/host/windows/)를 따릅니다.
창이 열려 있으면 `create`는 `BUSY`입니다. 닫은 창을 다시 열 때는 `create`를 사용하고,
새 문서로 다시 시작하려면 `recreate`를 사용하세요. `recreate`는 기존 창의 정리가 완료될 때까지 기다리며
창이 없으면 새로 만듭니다. 창이 열려 있는지는 `windows.isOpen`으로 확인합니다.
기본 종료 설정에서는 창을 닫으면 앱이 종료됩니다. 계속 실행하려면 아래 desktop 설정을 사용하세요.

## 창 없는 시작

트레이를 사용하려면 @bunaway/plugin-tray를 설치하고 아래처럼 등록하세요. desktop.tray 설정만 있으면 시작을 거부합니다.

Windows에서는 `app.startup`을 `false`로 지정합니다.
앱 정의에는 `desktop.tray` 또는 `desktop.closeBehavior: "keep-alive"`를 지정해야 합니다.
나중에 창을 열려면 `windows.create`를 호출합니다.
macOS는 트레이와 창 없는 시작을 지원하지 않습니다. `desktop.closeBehavior: "keep-alive"`를 지정해도 `startup: false`이면 호스트가 시작할 때 `UNSUPPORTED`로 거부합니다.

```ts
import { defineApp } from "@bunaway/backend";
import tray from "@bunaway/plugin-tray";

export default defineApp({
  modules: [],
  plugins: [tray],
  desktop: {
    closeBehavior: "keep-alive",
    tray: { tooltip: "Notes" },
    async onOpen(request, desktop) {
      if (request.argv.includes("--quit")) {
        await desktop.quit();
      }
    },
    beforeQuit() {
      return true;
    },
  },
});
```

초기 실행은 창을 만들지 않습니다. 트레이 클릭 또는 Open으로 창을 엽니다.
열린 창이 있으면 표시하고 최소화를 복원하며 최대화 상태와 기존 세션을 유지합니다.
`closeBehavior: "keep-alive"`는 창을 닫아도 백엔드를 유지합니다.
다음 Open은 정리한 창을 새 HWND와 세션으로 생성하고 표시합니다. 두 번째 실행도 같은 방식으로 새로 만든 창을 표시합니다.
`"hide"`와 트레이를 함께 쓰면 닫기에서 창과 세션을 유지한 채 숨깁니다.
`"quit"` 또는 생략은 창 닫기로 종료를 요청합니다.

`build.app`, `build.frontend`와 정책 파일 등 프로젝트의 필수 입력은 그대로 필요합니다.
트레이 없는 상주 앱에서는 위 `onOpen`을 유지하고 `tray`만 생략할 수 있습니다.
실행 파일에 `--quit`을 전달하면 같은 앱으로 전달된 요청에서 명시적 종료를 요청합니다.
`beforeQuit`가 `false`를 반환하거나 실패하면 종료를 취소하므로 다시 요청할 수 있습니다.
상주 앱에서 창이 닫힌 시점은 `desktop.onAllWindowsClosed`로 받습니다.

백엔드에서 창을 열려면 `@bunaway/plugin-windows`를 등록하고
플러그인 setup의 실행 컨텍스트로 `context.host.call`을 사용합니다.
backend 정책에 windows.create를 허용해야 합니다.
`onOpen` 자체는 Host 호출 컨텍스트를 제공하지 않습니다.
`DesktopContext.show()`는 공개 창 플러그인 없이도 창의 표시를 요청할 수 있습니다.
개발 CLI 중단과 재시작은 창이 없거나 종료 훅이 대기 중이어도 앱 정리를 요청합니다.
OS 강제 종료는 앱 훅을 실행하지 않습니다. 자세한 결과와 실패는
[데스크톱 앱 동작](/reference/backend/app-definition/#데스크톱-앱-동작)을 따릅니다.

개발 서버를 사용하면 창의 `home` 경로와 query를 같은 loopback 서버에 연결합니다.
`dev.url`은 서버의 준비 확인 주소이며 프로덕션 `home`은 그대로 둡니다.

초기 창 크기 제약, 권한, 전체화면과 포커스, 닫기 확인과 재생성 수명은
[windows API](/reference/host/windows/)에서 확인할 수 있습니다.
현재 입력 포커스를 유지하며 창의 숨김만 해제하려면
`windows.showInactive()`를 사용합니다. Windows와 macOS에서 사용할 수 있으며
최소화한 창은 최소화 상태로 남습니다. `activate`는 Windows만 지원합니다.
표시된 비최소화 창으로 전환할 때는 `windows.activate()`를 호출하고
반환된 boolean으로 전경 여부를 확인합니다. 숨김이나 최소화도 해제하려면 `focus`를
사용하고 `BUSY`를 처리하세요.
창 생성과 기본 제어는 Windows와 macOS를 지원합니다. 위 `prepareClose`처럼 닫기
확인을 설정하는 작업은 Windows만 지원합니다. macOS는 앱의 임시 프로필을 앱 실행 중 유지합니다.

Windows에서 내용 영역의 위치와 크기를 한 번에 바꾸려면 명령 핸들러에서
`windows.setContentBounds({ x: 100, y: 120, width: 800, height: 600, unit: "logical" })`를 호출합니다.
내용 위치만 바꿀 때는 `setContentPosition`, 제목 표시줄과 테두리를 포함한 크기와 영역은
`setOuterSize`, `setOuterBounds`를 사용합니다. 기본 단위는 물리 픽셀입니다.
숨긴 창은 표시하지 않으며 최소화나 최대화 중에는 일반 복원 영역을 변경합니다.
전체화면은 먼저 해제해야 합니다. 크기 제약을 적용한 결과는 같은 단위의 geometry 조회로 확인하고
변경 알림은 `windows.changed`로 구독하세요. 입력 범위, 반올림과 오류는 위 API 문서를 따릅니다.

## 숨김 준비

Windows와 macOS에서 준비 전에 화면을 표시하지 않으려면 `app`에 `visible: false`를 지정합니다.
문서만 기다린 뒤 자동으로 표시하려면 `showWhenReady: "document"`, SDK도 기다리려면 `"sdk"`를 씁니다.
앱 데이터를 기다린 뒤 직접 표시하려면 자동 표시를 생략하고 앱이 표시 시점을 결정하세요.

```json
{
  "appId": "app.notes",
  "title": "Notes",
  "home": "https://app.bunaway.local/index.html",
  "window": { "width": 800, "height": 600 },
  "visible": false
}
```

창을 숨긴 채 시작하고 필요한 데이터 로드와 UI 초기화를 마친 뒤 `windows.show()`를 호출합니다.
`startup: false`로 창을 나중에 만들 때는 백엔드에서 `windows.create()`를 호출합니다.

뷰의 정책에서 `commands`에 `plugin.windows.getReadiness`, `plugin.windows.show`를,
`events`에 `windows.readiness`를 추가합니다. `host.permissions`에는
`"windows.getReadiness"`와 `"windows.show"` 작업 이름을 추가합니다.

```ts
import { createClient } from "@bunaway/client";
import type { CommandsOf, EventsOf } from "@bunaway/backend";
import windows, { type WindowOutput } from "@bunaway/plugin-windows";
import type { app } from "../src-bunaway/app.ts";

// UI 초기화 함수에서 실행합니다. initializeUi는 앱이 소유한 데이터와 화면 초기화 작업입니다.
const client = createClient<CommandsOf<typeof app>, EventsOf<typeof app>>();
await client.ready;
await initializeUi();
let shown = false;
async function finish(state: WindowOutput<"windows.getReadiness">): Promise<void> {
  if (shown) return;
  if (state.error) throw new Error(state.error.message);
  if (state.document !== "ready" || state.sdk !== "ready") return;
  shown = true;
  await windows.show();
}
const release = await client.listen("windows.readiness", (event) => {
  void finish(event.payload).catch(console.error);
}, { onError: console.error });
try {
  // 구독 전에 완료된 단계도 조회로 확인합니다.
  await finish(await windows.getReadiness());
} catch (error) {
  await release();
  throw error;
}
// 컴포넌트 정리 때 await release()를 호출하고 공유 client는 유지합니다.
```

이벤트와 조회를 화면 상태에 함께 저장하는 앱은 현재 창 ID와 revision으로 오래된 상태를 제외하세요.
새 탐색과 창 재생성, 기한, 취소 및 단계별 정확한 완료 조건은 [창 준비](/reference/host/windows/#창-준비)를 따릅니다.
