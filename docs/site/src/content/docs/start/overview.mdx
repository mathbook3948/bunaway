bunaway 앱은 **웹 UI + TypeScript 앱 백엔드 + 네이티브 호스트 + 번들 Bun**으로 구성됩니다.
앱 백엔드는 사용자 기기에서 번들 Bun으로 실행합니다.

## 무엇을 직접 작성하나요?

| 작성할 곳 | 하는 일 | 예시 |
| --- | --- | --- |
| `src/` | 화면과 사용자 입력 처리 | 입력 상자, 저장 버튼, 저장 결과 표시 |
| `src-bunaway/app.ts` | 기능 모듈 조립과 앱 상태, 플러그인 설정 | `defineApp({ modules: [message] })` |
| `src-bunaway/message/module.ts` | 메시지 명령과 이벤트 등록 | `message.save`, `message.read`, `message.saved` |
| `src-bunaway/bunaway.json` | 소스 위치, 앱 ID, 창, 빌드 설정 | 시작 페이지, 창 크기 |
| `src-bunaway/policy.json` | 뷰, 백엔드의 접근 정책 | 저장 명령 허용, `messages/` 읽기, 쓰기 |

Windows와 macOS 모두 같은 앱 정의를 사용합니다. 앱 개발자는 화면과 기능을 작성하고 플랫폼별 시작 과정은 프레임워크에 맡깁니다.

## 화면과 앱 기능 연결하기

**웹 UI**는 WebView에서 실행합니다. `@bunaway/client` SDK로 명령을 호출하고 이벤트를 구독합니다.
파일 작업은 SDK로 백엔드 명령을 호출해 처리합니다.

**앱 백엔드**는 `@bunaway/backend`의 `defineModule()`로 기능별 명령과 이벤트를 등록합니다.
`defineApp()`으로 모듈을 조립하거나 기존 `command()`와 객체형 앱 정의를 사용할 수 있습니다.
명령에서 파일을 저장하거나 앱 상태를 바꾸고, 이벤트로 화면에 변경을 알립니다.

**네이티브 호스트**는 웹 UI를 운영체제의 창에 표시합니다.
파일이나 운영체제 기능을 사용하려면 명령 안에서 **Host API**를 호출합니다. 사용할 명령과 파일 범위는 policy.json에 허용해야 합니다.

**번들 Bun**은 최종 앱 패키지에 들어가는 런타임입니다.
개발할 때는 Bun을 설치합니다. 배포한 앱은 패키지에 포함된 Bun을 사용합니다.

명령을 호출하려면 앱에 구현을 등록하고 뷰의 정책에도 허용해야 합니다.
`app.ts`에 `message.save`가 있어도 뷰의 `commands`에 없다면 실행 전에 거부됩니다.
명령을 허용했더라도 파일 쓰기에는 `host.storage`의 저장 권한이 필요합니다.

## 뷰가 여러 개라면

여러 뷰가 있는 앱은 하나의 앱 백엔드를 공유합니다.
명령 구현과 앱 상태는 공유합니다. 각 뷰의 정책은 호출할 명령과 받을 이벤트, Host API의 접근 범위를 정합니다.
기본 템플릿은 창 하나와 뷰 하나를 사용하며 Windows에서는 `app.windows`로 여러 창을 정의합니다. 지원 범위는 [창과 뷰의 정책](/concepts/views-and-policy/)에서 설명합니다.
