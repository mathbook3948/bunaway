정책은 버전 1의 `{ version, views, backend }`입니다.
세 필드가 모두 필수이며 추가 필드는 허용하지 않습니다.
정책에 선언하지 않은 권한은 거부합니다.
입문 설명과 전체 템플릿은 [창과 뷰의 정책](/concepts/views-and-policy/)에 있습니다.

## views

스키마에서 최대 128개입니다. 현재 CLI 생성 앱은 정확히 하나만 허용합니다.
각 항목은 아래 필드를 모두 요구하며 추가 필드를 거부합니다.

| 필드 | 제약 | 의미 |
| --- | --- | --- |
| `id` | 1–128자, 영숫자, `_ . : -` | 정책 단위 ID. 파일 전체에서 중복 금지 |
| `origins` | 최대 16개, 중복 금지 | 정확한 HTTP(S) origin 문자열 |
| `commands` | 최대 256개, 중복 금지 | 정확한 앱 명령 이름 |
| `events` | 최대 256개, 중복 금지 | 정확한 이벤트 이름 |
| `host` | log, storage 필수 | 해당 뷰에서 시작한 작업의 네이티브 기능 범위 |

배열이 비어 있으면 그 기능은 허용하지 않습니다. 와일드카드 origin, 명령은 지원하지 않습니다.
명령, 이벤트 이름은 id와 같은 식별자 규칙입니다.
핸들러와 이벤트는 `app.ts`에 등록하고 창은 앱 설정에 정의합니다. 정책에는 사용할 수 있는 이름을 선언합니다.

## origins

`https://app.bunaway.local`이나 `https://example.com:8443`처럼 origin을 지정합니다.
경로, query, fragment, 사용자 정보 없이 origin만 지정합니다.
스키마는 소문자 호스트 형태, 최대 256자, 포트 1–5자리 패턴을 검사합니다.
현재 CLI는 정책의 HTTP origin을 거부하고 프로덕션 home의 로컬 origin을 요구합니다.
개발 서버의 정확한 loopback origin은 CLI가 개발 산출물에만 적용합니다.

호스트는 실제 최상위 문서와 frame, 활성 세션을 확인해 출처를 결정합니다.
payload에 origin이나 view ID를 넣어도 출처는 바뀌지 않습니다.

## host와 backend

둘은 같은 HostPermissions 구조입니다.

| 필드 | 제약 | 의미 |
| --- | --- | --- |
| `log` | 필수 boolean | log.write 허용 |
| `storage` | 필수 배열, 최대 128개 | 파일 범위 grant |

UI 명령의 context.host는 뷰의 host 권한을 유지합니다.
플러그인 setup 등 backend 자체 작업은 루트의 backend 권한을 사용합니다.
backend.storage가 빈 배열이어도 뷰에 허용한 저장은 동작합니다.

## storage grant

| 필드 | 제약 |
| --- | --- |
| `scope` | appData 또는 temp |
| `pathPrefix` | 빈 문자열 또는 `/`로 나눈 이름 디렉터리. 각 이름은 영숫자, `_ -`. 최대 256자 |
| `access` | read, write 중 최소 하나, 최대 두 개, 중복 금지 |

세 필드가 모두 필수입니다. pathPrefix가 빈 문자열이면 지정한 scope 전체에 접근할 수 있습니다.
`messages`는 지정한 scope의 messages 디렉터리와 그 하위 경로에만 적용됩니다.
같은 범위의 여러 grant가 각 access를 제공할 수 있습니다.
실제 파일 접근은 경로 탈출, 링크, 핸들 대상까지 호스트에서 다시 검사합니다.

## 집행 위치와 실패

브리지에서 명령, origin, 세션을 검사하고, 코어에서 명령, 이벤트, 입력 계약을 검사합니다.
Host operation은 실행 직전에 출처, 현재 권한, 저장 범위를 다시 검사합니다.
스키마를 위반하거나 ID가 중복되면 정책 파싱에 실패합니다. 허용되지 않은 기능을 호출하면 `PERMISSION_DENIED`를 반환합니다.

직접 파싱하려면 `@bunaway/protocol`의 `parsePolicy(text)`를 사용합니다.
`policySchema`는 생성된 네이티브 스키마의 원본이지만 중복 view ID 같은 파일 단위 검사는 파서도 수행합니다.
이 정책은 UI에서 시작한 요청과 Host API 호출에 적용됩니다. OS 권한은 운영체제에서 관리하며 신뢰된 백엔드가 직접 실행하는 Bun 코드는 이 정책으로 격리하지 않습니다.
