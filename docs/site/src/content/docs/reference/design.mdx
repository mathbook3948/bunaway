## 코드 스타일

저장소의 코드 포맷은 루트 `biome.json`을 따릅니다. 공백 2칸으로 들여쓰고
줄 너비는 80으로 설정합니다. JS/TS 객체와 배열, JSX 속성은 여러 줄로 펼칩니다.
조건문과 반복문에는 본문이 한 문장이어도 중괄호를 씁니다.

초기화, 검증, 실행, 정리처럼 역할이 바뀌는 지점에는 빈 줄을 한 줄 두세요.
Biome은 논리 단위 사이의 빈 줄을 자동으로 추가하지 않으므로 작성과 리뷰 때
구분해야 합니다.

`mise run format`은 기존 코드에 포맷을 적용하고 `mise run format:check`는
포맷만 검사합니다. 중괄호 규칙은 `mise run lint`에서 검사합니다.
공식 프런트엔드 템플릿의 `src`와 `public`은 기존 Biome 제외 설정을 유지합니다.

## 커밋 전 검사

저장소 루트에서 `mise install`과 `mise run install`을 실행한 뒤
`mise run hooks:install`로 Lefthook 훅을 설치하세요. Lefthook 버전은
`mise.toml`에 2.2.1로 고정되어 있습니다. 새 clone마다 훅 설치가 필요합니다.

pre-commit 훅은 stage한 파일의 Biome 포맷과 린트, 공백 오류와 충돌 마커를
검사합니다. 기존 `biome.json`의 제외 규칙을 따르며, 자동 수정이나 다시 stage하는
작업은 하지 않습니다. 부분적으로 stage한 파일의 나머지 변경은 검사 중 잠시
숨기고 완료 후 복원하므로 커밋할 내용만 검사합니다.

포맷 오류는 `mise run format`으로 수정하세요. 린트, 공백 오류와 충돌 마커는
직접 해결한 뒤 수정한 파일을 다시 stage하고 커밋하세요.
`mise run check:staged`로 stage한 파일의 포맷과 린트를 직접 확인할 수도 있습니다.
이 명령을 훅 밖에서 실행하면 해당 파일의 작업 트리 내용을 검사합니다.
pre-push 훅은 사용하지 않습니다. CI에서 전체 타입 검사, 테스트, 문서 빌드와
플랫폼 검증을 수행합니다.

## 테스트 실행

`mise run check`는 포맷, 린트, 타입과 계약 테스트를 확인합니다.
Windows에서 `mise run host:windows`를 실행하면 실제 WebView2와 이동한 독립 CLI 앱의 저장, 종료와 패키징을 검증합니다.
독립 CLI 앱에 추가한 테스트용 UI 코드도 앱의 타입 검사에 포함하며, 검사에 실패하면 창을 실행하기 전에 중단합니다.

Windows의 진단 로그는 전용 슬롯이 가득 차면 생략되고, 다음 전달 로그의
`droppedDiagnostics`에 생략한 개수가 기록됩니다. 권한 거부와 잘못된 메시지의
통합 검사는 페이지가 받은 오류 코드와 금지된 명령의 미실행을 보고 파일로 확인합니다.
필수 검사 이름이 누락되거나 실패하면 통합 검사가 실패합니다.

## 문서 기여

개발자용 설명은 `docs/site/src/content/docs/`의 MDX에서 작성합니다.
설계 결정은 기존 `docs/decisions/`, 용어는 `docs/GLOSSARY.md`, 실행 기록은 `docs/architecture/`에 유지합니다.
앱 개발 가이드에는 사용법과 결과, 권한, 오류를 설명합니다. Worker 구성이나 내부 메시지 처리 과정은 이 기여 자료와 설계 문서에 작성합니다.

이 사이트의 앱 정의, 정책, 설정, UI 예제는 실제 CLI 템플릿을 빌드 시 읽어 표시합니다.
템플릿의 이름이나 동작을 바꾸면 주변 설명과 지원 범위도 함께 갱신하세요.
