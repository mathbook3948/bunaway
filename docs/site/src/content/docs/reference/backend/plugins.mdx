설치한 플러그인은 `defineApp({ modules, plugins })`의 plugins 배열에 등록합니다.
일반 TypeScript 플러그인은 명령과 이벤트, setup을 제공할 수 있습니다.
네이티브 플러그인은 필요한 패키지를 개별 설치합니다.

| 필드 | 필수 | 의미 |
| --- | --- | --- |
| `name`, `version` | 예 | 플러그인 이름과 설치 패키지 버전 |
| `dependencies` | 아니요 | 먼저 초기화할 플러그인 이름 배열 |
| `platforms` | 아니요 | windows, macos, linux, android, ios 중 실행 허용 플랫폼 |
| `requiredPermissions` | 아니요 | backend.permissions에 명시해야 할 권한 식별자 배열 |
| `native` | 아니요 | operations와 permissions 계약 |
| `commands`, `events` | 아니요 | 앱과 공유하는 명령과 이벤트 |
| `setup(context)` | 아니요 | 초기화. 선택적 StopHook 반환 |

requiredPermissions는 식별자의 명시 여부를 검사합니다. 실제 리소스 접근은 호출할 때
allow와 deny 범위를 검사합니다. 등록만으로 권한을 부여하지 않습니다.
네이티브 작업에는 `plugin.<이름>.` 명령을 자동 등록합니다. 이 접두사는 일반 앱 명령에 예약되어 있습니다.

중복 이름, 없는 의존성과 의존 순환은 `INVALID_ARGUMENT`입니다.
미지원 플랫폼은 `UNSUPPORTED`, 필요한 backend 권한의 누락은 `INVALID_ARGUMENT`입니다.
현재 개별 네이티브 어댑터는 Windows를 지원합니다.

setup은 의존성 순서로 실행하고 StopHook은 역순으로 실행합니다.
초기화 실패에서도 이미 시작한 플러그인을 정리합니다. 코어 종료 기한은 2초입니다.
초기화와 종료 훅의 오류는 플러그인 이름과 단계, 원래 오류를 개발 터미널에 기록합니다.
Windows에서는 `plugin-failed` 진단 로그에도 남깁니다. 종료 훅 하나가 실패해도 나머지 훅은 실행합니다.
앱 종료 시 Host 호출을 먼저 취소하므로 StopHook에서는 타이머와 연결 등 자체 자원을 정리합니다.
