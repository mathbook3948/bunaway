저장, 로그와 기능 조회는 개별 설치하는 선택 패키지입니다. 사용할 패키지를 설치한 뒤
앱의 `plugins` 배열에 등록하세요. 현재 네이티브 플러그인 어댑터는 Windows를 지원합니다.
Windows 창 제어는 `@bunaway/backend`의 `windows` API가 제공합니다. 별도 플러그인 등록은 필요하지 않으며,
호출 출처의 `host.windows` 또는 `backend.windows`에 제어할 뷰 ID를 허용해야 합니다.
예제의 `editor` 창은 앱 설정 `app.windows`에 정의하고 정책의 `views`에도 추가해야 합니다.

```ts
import { defineApp, defineModule, windows } from "@bunaway/backend";

import { storage, storagePlugin } from "@bunaway/plugin-storage";

const memo = defineModule("memo").command("save", {
  input: { type: "string" }, output: { const: null },
}, text => storage.writeText({ scope: "appData", path: "notes/memo.txt", text }));
const editor = defineModule("editor").command("open", {
  input: { const: null }, output: { const: null },
}, async () => { await windows.create({ view: "editor" }); return null; });
export default defineApp({ modules: [memo, editor], plugins: [storagePlugin] });
```

뷰 정책에는 `memo.save`와 `storage:write-text`의 `appData/notes` 허용 범위가 필요합니다.
`editor.open`을 호출하는 뷰의 `commands`에는 해당 명령을, `host.windows`에는 `editor`를 지정합니다.
패키지 설치나 플러그인 등록으로 권한을 부여하지 않습니다.

## 개별 API

| 패키지 | 앱 등록 | 백엔드 API |
| --- | --- | --- |
| `@bunaway/plugin-storage` | `storagePlugin` | `storage.readText({ scope, path }): Promise<string>`, `storage.writeText({ scope, path, text }): Promise<null>` |
| `@bunaway/plugin-log` | `logPlugin` | `log.write({ level, message, details? })`, `log.debug`, `log.info`, `log.warn`, `log.error` |
| `@bunaway/plugin-capabilities` | `capabilitiesPlugin` | `capabilities(): Promise<Capabilities>` |
| `@bunaway/backend` | 등록 불필요 | `windows.list`, `windows.create`, `windows.recreate`, `windows.show`, `windows.hide`, `windows.focus`, `windows.close`, `windows.setSize`, `windows.setPosition`, `windows.setFullscreen`, `windows.setCloseConfirmation` |

로그의 모든 함수는 `Promise<null>`을 반환합니다. `level`은 debug, info, warn, error이며
메시지는 최대 1,024자, `details`는 선택적 JSON 값입니다.
저장 scope는 appData 또는 temp이며 path는 범위 안의 상대 경로입니다.
[저장 읽기](/reference/host/storage-read-text/), [쓰기](/reference/host/storage-write-text/),
[로그](/reference/host/log-write/)에 입력과 오류를 설명합니다.

화면과 백엔드에서 같은 패키지를 import하고 같은 기능 이름을 사용합니다.
예를 들어 둘 다 `import { storage } from "@bunaway/plugin-storage"`로 가져옵니다.
프런트엔드 빌드에서는 화면 함수를, Bun에서는 백엔드 함수를 선택합니다.
화면 호출에는 `plugin.storage.readText`처럼 정확한 명령 허용과 해당 Host 권한이 모두 필요합니다.
화면 API는 기본 WebView 연결을 사용합니다. 생성 앱의 typecheck는 화면과 백엔드를
각각 검사하므로 실행 환경에 맞는 인자와 반환 타입을 확인합니다.
화면의 `storage.readText(input, options?)`, `storage.writeText(input, options?)`,
`log.write(input, options?)`, `capabilities(options?)`는 `InvokeOptions`를 받습니다.
로그 수준별 함수는 `log.info(message, details?, options?)` 형태입니다.
options의 signal은 호출 취소 신호이고 deadline은 Unix epoch 밀리초의 절대 기한입니다.
이미 취소된 신호는 `CANCELLED`, 지난 기한은 `TIMEOUT`으로 실패합니다.
진행 중 취소도 지원하며 완료된 저장이나 로그를 되돌리지는 않습니다.

## host.call

공통 SDK는 `host.call(contract, input)`과 `context.host.call(contract, input)`을 제공합니다.
`HostOperationContract<I, O>`의 name, input, output, permission으로 작업을 선언하며
결과는 출력 schema에서 추론합니다. 플러그인 작성자는 등록한 `native.operations` 계약을
사용합니다. 호출자가 넘긴 다른 schema나 permission으로 등록한 계약을 바꾸지 못합니다.
작업이 등록되지 않았다면 `UNSUPPORTED`, 입력이 잘못됐다면 `INVALID_ARGUMENT`입니다.

## 실행 범위와 권한

`command()`와 `defineModule().command()`로 작성한 핸들러 안에서 사용할 수 있습니다.
`defineApp()`에 직접 전달한 명령과 플러그인 명령도 지원합니다.
핸들러가 호출한 서비스와 `await` 이후에도 원래 요청의 권한과 취소 신호를 사용합니다.
동시에 실행하는 다른 명령이나 다른 앱의 권한으로 바뀌지 않습니다.

뷰 명령은 해당 뷰의 Host 정책을 사용합니다.
`defineApp({ modules, plugins })`로 연결한 플러그인의 `setup`과
setup에서 시작한 비동기 작업은 `policy.backend` 권한을 사용합니다.
이 작업의 Host API는 앱이 종료될 때까지 사용할 수 있습니다.
앱 종료 시 Host 호출은 취소되므로 StopHook에서는 타이머와 연결을 정리합니다.

명령이 완료되거나 실패한 뒤 실행하는 타이머나 비동기 작업에서는 사용할 수 없습니다.
명령에서 필요한 Host 호출을 `await`하고 결과를 반환하세요.
모듈 최상위나 실행 범위 밖에서 호출하면 `INVALID_ARGUMENT`,
완료한 명령이나 취소된 요청, 종료된 앱의 작업에서 호출하면 `CANCELLED`로 거부합니다.
모든 함수는 Promise를 반환하며 실행 범위 오류도 Promise의 거부로 전달합니다.

[context.host.call](/reference/backend/context/)도 지원합니다.
SDK의 `command()`와 `defineApp()`을 사용하지 않는 객체형 정의에서는 이 명시적 API를 사용하세요.
권한 부족은 `PERMISSION_DENIED`, 입력 오류는 `INVALID_ARGUMENT`,
지원하지 않는 기능은 `UNSUPPORTED` 등 기존 Host operation의 오류를 그대로 전달합니다.
입력과 호스트 결과의 검증도 기존 Host API와 같습니다.

정책은 이 API로 요청하는 작업에 적용합니다. 신뢰된 백엔드가 직접 호출하는 Bun API는 이 정책으로 제한하지 않습니다.
`storage`는 백엔드 전체의 파일 접근을 격리하는 샌드박스가 아닙니다.

## 창

`windows`는 프레임워크에 포함된 Windows 전용 창 제어 API입니다. 선택 플러그인처럼 설치하거나 등록하지 않습니다.
호출 뷰의 `host.windows`, 또는 setup의 `backend.windows`에 대상 뷰를 허용해야 합니다.
메서드와 권한은 [windows 레퍼런스](/reference/host/windows/)를 확인하세요.
