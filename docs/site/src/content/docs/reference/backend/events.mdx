```ts
context.events.emit(name, payload, target): Promise<void>
```

앱 또는 플러그인의 `events`에 선언한 알림을 발행합니다.

```ts
await context.events.emit("message.saved", text, { kind: "broadcast" });
await context.events.emit("message.saved", text, { kind: "view", viewId: "main" });
```

## 인자

| 인자 | 의미 |
| --- | --- |
| `name` | 등록된 이벤트 이름 |
| `payload` | 이벤트 Schema와 일치하는 JSON 데이터 |
| `target` | broadcast 또는 정확한 view ID |

대상 인자는 필수이며 자동 기본 대상은 없습니다.
발신 `source`는 호출 컨텍스트가 정합니다. 뷰에서 시작한 요청은 그 뷰 ID이고 백엔드 작업은 backend입니다.

## 전달 대상

`broadcast`는 허용된 모든 활성 구독을 대상으로 합니다.
`view`는 지정한 뷰로 좁히며 그 뷰의 `events` 정책과 활성 구독 검사를 그대로 적용합니다.
이벤트를 허용하지 않거나 구독하지 않은 뷰에는 전달하지 않습니다.
알 수 없는 대상 뷰, 미등록 이벤트, 잘못된 payload는 실패합니다.

Promise는 이벤트 발행 처리가 끝나면 완료됩니다. UI 콜백의 완료나 반환값을 기다리지 않습니다.
이벤트 전달이 실패하면 구독의 onError로 오류를 처리합니다.

## 수명과 상태 복원

이벤트는 활성 구독에 전달하며 저장하거나 재전송하지 않습니다. 취소되거나 종료된 요청의 이벤트는 새 세션에 전달하지 않습니다.
플러그인 `setup`에서 받은 컨텍스트는 앱 백엔드의 수명을 따릅니다. 앱 종료로 `signal`이 취소되면 `events.emit`은 `CANCELLED`로 실패합니다. `abort` 콜백 안에서 발행하거나 종료 뒤 보관한 컨텍스트로 발행해도 이벤트를 전달하지 않습니다.
보관할 데이터는 파일이나 앱 상태에 저장합니다. 새 UI는 읽기 명령으로 현재 값을 가져옵니다.
구독 쪽 세부 동작은 [listen](/reference/client/listen/)을 참고하세요.
