## 자동으로 검사하는 것

`bun run docs:check`와 `bun run docs:build`는 다음을 검사합니다.

- 일곱 공개 패키지 진입점의 실행 시 export와 재수출이 레퍼런스에 매핑되어 있는지
- Client, HostAPI, StateStore, EventEmitter, Core, CoreSession, RuntimeServices, Transport 멤버 누락
- CLI 명령과 Host operation이 각 문서에 있는지
- Schema 키워드와 policy, CLI, 패키징의 허용 설정 필드가 문서에 있는지
- 매핑한 페이지가 실제로 존재하고 해당 API 이름이 본문에 있는지
- 생산 빌드의 내부 페이지 링크, 목차 anchor가 유효한지

export, 메서드, 설정 키를 추가하면 문서 매핑, 설명이 없을 때 검사가 실패합니다.
키워드가 있다는 사실만으로 설명의 정확성을 자동 증명하지는 않습니다.
기존 API의 동작을 바꾸는 변경은 소스, 계약, 예제를 함께 검토해야 합니다.

## 검사 범위 밖

모든 private helper, 분기, 내부 구현을 사용자 API로 문서화하지는 않습니다.
TypeScript의 모든 보조 타입 alias도 개별 페이지 대상으로 세지 않습니다.
주요 타입은 관련 API 페이지에서 설명합니다.
실제 Windows/macOS 실행 결과와 배포 시험은 각 플랫폼 실행 기록을 확인합니다.
문서 빌드가 성공한 것과 네이티브 앱 실행 검증은 다릅니다.
