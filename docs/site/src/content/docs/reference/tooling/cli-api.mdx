프로젝트 생성과 빌드를 코드로 자동화할 때 사용하는 `@bunaway/cli`의 공개 API입니다.
프로젝트 디렉터리는 문자열로 전달합니다. Promise가 실패하면 호출한 코드에서 오류를 처리하세요.

## 프로젝트 생성과 검증

| 함수 | 반환 |
| --- | --- |
| `createProject(directory, options?)` | 생성한 프로젝트 경로 `Promise<string>` |
| `validateProject(directory, options?)` | 해석한 `Promise<Project>` |
| `doctor(directory)` | 환경 검사 성공 여부 `Promise<boolean>` |

create는 `packageDirectory?: string`과 `template?: Template`를 받습니다. 기본 템플릿은 vanilla입니다.
`Template`은 `"vanilla" | "vite" | "react" | "vue" | "svelte"`입니다.
공개된 `templateNames` 배열은 이 다섯 템플릿 이름을 순서대로 제공합니다.
기존 디렉터리는 덮어쓰지 않습니다. 생성 후 의존성은 별도로 설치하세요.
create의 `packageDirectory`는 CLI의 `--package-dir`에 대응하며, 반환값은 생성된 프로젝트의 절대 경로입니다.
validate는 `development?: boolean`을 받으며 기본값은 false입니다.
개발 검증에서는 외부 개발 서버가 있을 때 프로덕션 UI 파일이 없어도 되며 개발 URL을 검증합니다. validateProject는 build.command를 실행하지 않습니다.

Project에는 `root`, `frameworkRoot`, `appEntry`, `frontend`, `app`, `policy`,
선택적 `bundle`, `dev`, `buildCommand`, `backendDependencies`가 있습니다. `backendDependencies`는 검증한 앱 정의가 import한 프로젝트 내부 파일의 프로젝트 상대 경로 목록입니다. 파일 경로는 해석된 경로입니다. `buildCommand`는 설정의 `build.command` 실행 파일과 인자 배열입니다.
구체적인 검증 기준은 [validate](/reference/cli/validate/)를 따릅니다.

## 네이티브 준비와 빌드

| 함수 | 반환 |
| --- | --- |
| `currentTarget()` | `windows-x64` 또는 `macos-arm64`; 그 외 환경은 예외 |
| `prepareNative(target?, root?)` | `Promise<NativeInputs>` |
| `buildProject(directory, options?)` | `Promise<BuiltPackage>` |

prepareNative의 target 기본값은 currentTarget(), root 기본값은 frameworkRoot입니다.
고정 Bun 버전, 대상을 검사하고 플랫폼 준비 도구를 실행합니다.
NativeInputs는 `target`, `host`, `bun`, `licenses`, 선택적 `loader`입니다.

build는 `development?: boolean`과 `native?: NativeInputs`를 받습니다.
프로덕션에서는 build.command를 매번 실행한 뒤 자산을 검증하고 앱을 빌드합니다. development가 true이면 웹 프로덕션 빌드 명령을 실행하지 않습니다.
프로덕션 빌드 중 SIGINT나 SIGTERM을 받으면 실행한 명령을 정리하고 잠금을 해제한 뒤 Promise가 실패합니다.
NativeInputs를 전달하면 현재 플랫폼에서 준비한 결과를 재사용합니다.
BuiltPackage는 `output`, `package`, `executable`, `arguments: string[]`입니다.
앱을 실행할 때는 반환한 `executable`과 `arguments`를 함께 사용합니다.
전체 빌드 과정과 실패 시 산출물 처리 방법은 [build](/reference/cli/build/)에서 확인할 수 있습니다.

## 개발과 패키징

`devProject(directory): Promise<void>`는 파일 감시와 창 실행을 시작하고 종료 후 정리가 끝날 때까지 기다립니다.
`packageProject(directory, channelName, { build?: boolean } = {}): Promise<PackageReport>`는
채널을 해석하고 검증한 뒤 패키징 보고서를 반환합니다.
반환된 보고서의 `ok`로 성공 여부를 확인하세요. 사전 검증에 실패하면 예외가 발생합니다.
build가 true이면 웹 빌드를 포함한 buildProject 경로를 한 번 실행합니다. false이면 앱 소스와 웹 출력 없이도 기존 앱 산출물을 검증해 패키징합니다.

## RestartController

```ts
import { RestartController } from "@bunaway/cli";
const controller = new RestartController({
  async stop() { /* 이전 프로세스 정리 */ },
  async build() { return { revision: "new" }; },
  async start(value) { console.log(value.revision); },
  error(error) { console.error(error); },
});
await controller.change();
await controller.close();
```

constructor는 `stop`, `build`, `start`, `error` 훅을 받습니다.
`change()`는 변경 revision을 늘리고 직렬 stop → build → start를 수행합니다.
빌드 중 새 변경이 오면 오래된 결과는 시작하지 않고 최신 변경을 다시 적용합니다.
실패하면 error 훅을 호출합니다. 이후 change 호출은 계속 처리할 수 있습니다.
`close()`는 진행 중 작업을 기다려 정리하며 이후 change는 재시작하지 않습니다.
