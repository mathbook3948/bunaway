`@bunaway/plugin-api`는 AppDefinition, PluginDefinition, CommandContext와 DesktopOptions 등 공통 계약을 소유합니다. Core와 Backend SDK는 이 타입을 다시 export합니다. 플러그인은 Core를 설치하거나 import하지 않고 `@bunaway/plugin`과 공통 프로토콜을 사용합니다.

## 플랫폼 이름

`PLATFORMS`는 플러그인 선언에서 허용하는 `windows`, `macos`, `linux`, `android`, `ios`를 담은 변경 불가능한 목록입니다. `Platform` 타입은 이 목록의 값에서 파생합니다. 플러그인 작성 SDK와 CLI는 각 선언 검증에서 같은 목록을 사용하고, 플러그인 번들러는 플랫폼 파일 필터와 경로 검사에 사용합니다.

```ts
import { PLATFORMS, type Platform } from "@bunaway/plugin-api";

const platform: Platform = "windows";
const allowed = PLATFORMS.some((name) => name === platform);
```

목록에 포함된 이름이 해당 플랫폼의 실행이나 모든 네이티브 기능 지원을 보장하지는 않습니다. 실행 환경별 기능 지원은 등록된 작업의 기능 지원 조회로 확인합니다.

## 앱 정보

`AppInfo`는 `ctx.app`의 타입이며 필드는 [CommandContext](/reference/backend/context/)에 있습니다.
`APP_INFO_MAX_LENGTH`는 `AppInfo` 문자열 하나의 최대 길이인 1024 UTF-16 코드 유닛입니다.
호스트가 넘기는 값은 Core가 시작할 때 이 한도로 검증합니다.

## 호출 컨텍스트

`@bunaway/plugin-api/host`의 currentHost는 실행 중인 명령이나 setup의 Host API를 반환합니다. bindCommandHost와 bindPluginHost는 같은 호출 컨텍스트에 실행을 묶습니다. 명령이 끝나면 후속 호출을 거부하고 setup의 작업은 백엔드 수명을 따릅니다. Backend SDK와 플러그인 작성 SDK가 같은 컨텍스트를 공유합니다.

## Native 창 호스트 계약

`@bunaway/plugin-api/native`는 UI 호스트와 선택 창 제어 플러그인이 공유하는 타입을 제공합니다.
앱에서 호출할 작업 이름, 입력과 출력, 권한 및 비동기 창 교체 로직은 선택 창 제어 플러그인이 소유합니다.

| 타입 | 계약 |
| --- | --- |
| `WindowSpec` | view ID, home URL, 제목, 초기 너비와 높이, 축별 초기 최소 및 최대 크기 제약, 선택적 startup 여부 |
| `WindowSizeConstraints` | 논리 픽셀 단위 최소 및 최대 너비와 높이. 제한이 없는 축은 `null` |
| `WindowBounds` | 화면 물리 픽셀 단위 `x`, `y`, `width`, `height`와 측정 또는 복원 크기 계산에 사용한 `dpi` |
| `WindowState` | 창의 `closed`, `cleaned`, `ready`, `failure`, `deadline` 상태 |
| `WindowReadiness` | 기존 창 ID와 문서 세대, 준비 revision, nativeCreated, document와 sdk의 단계, 공개 error |
| `NativeWindowServices` | 창 사양, 상태 조회와 생성, 종료, 창 객체, 호스트 종료와 취소 확인, 시각과 UI tick |

`WindowSpec`은 `view`, `home`, `title`, `window`, `startup`과 선택적 `visible`, `showWhenReady` 필드를 가집니다. `window`에는 초기 `width`, `height`와 선택적 `minWidth`, `minHeight`, `maxWidth`, `maxHeight`를 둡니다. 크기 값은 96 DPI 기준 논리 픽셀입니다.
`visible`, `showWhenReady`의 기본값과 완료 조건은 [창 준비](/reference/host/windows/#창-준비)를 따릅니다.
`WindowState.ready`는 WebView 설정 완료만 뜻합니다. `NativeWindow.getReadiness()`는 별도 WindowReadiness를 읽습니다.
선택적 `WindowState.replacementCancelled`는 부모 종료로 해당 수명의 진행 중인
재생성을 취소해야 한다는 뜻입니다. 닫힌 뷰에 나중에 요청한 명시적 create는 허용합니다.
호스트가 준비 상태를 소유하며 SDK 확인은 현재 세션과 문서 세대에 연결합니다. HostContext는 공개 준비 payload에 넣지 않습니다.
`NativeWindowServices`는 `specs`, `onLifecycle(listener)`, `read(key)`, `create(spec, replacingLiveWindow?, instanceKey?)`, `close(key, replacing?)`, `window(key)`, `stopping()`, `cancelled(requestId)`, `now()`, `tick()`을 제공합니다.
`close`의 replacing 기본값은 true이며 교체할 창의 자원을 보존합니다.
선택적 `onLifecycle(listener)`는 호스트가 문서에 발행하는 창 수명 phase를 발행 순서대로 관찰하고
종료가 시작된 뒤에는 호출하지 않습니다. 반환한 함수로 리스너를 제거하며, 호스트가 phase를 발행하지 않으면 없습니다.
창 플러그인은 이 서비스로 백엔드의 `windows.waitForLifecycle`을 제공합니다.
선택적 `onAudioChange(listener)`는 같은 방식으로 WebView의 음소거 설정과 재생 상태 변경(`{ windowId, viewId, muted, playing }`)을
관찰하며 `windows.waitForAudioChange`가 사용합니다.
선택적 `onProcessFailure(listener)`는 같은 방식으로 호스트가 처리한 WebView 프로세스 실패(`{ windowId, viewId, kind, recovery }`, `recovery`는 `reload`, `close`, `none`)를
관찰하며 `windows.waitForProcessFailure`가 사용합니다.
`create(spec, replacingLiveWindow)`의 선택적 두 번째 인자는 살아 있던 창의 재생성인지
구분하며 기본값은 false입니다. 호스트는 이 경우에만 닫기 전 포착한 부모 수명을 재사용합니다.
선택적 `lookup`은 `byId(windowId)`, `byView(viewId)`, `focused()`, `lastActive()`로
`WindowIdentity`인 `{ windowId, viewId }` 또는 `null`을 반환합니다. 스냅샷이나 geometry를
새로 관찰하지 않는 조회입니다. `windowId`는 네이티브 수명 ID이고 `viewId`는 정책 ID입니다.
문서 탐색은 ID를 유지하며 네이티브 재생성은 새 ID를 발급합니다. 종료된 ID와 생성 전 뷰,
외부 전경 창은 `null`입니다. Windows는 활성 상태의 `WM_ACTIVATE`로 이력을 갱신하고
마지막 활성 창을 파괴하면 이전 창으로 되돌리지 않고 기록을 지웁니다.
단일 창 모델에서 창 플러그인의 공개 연산은 이 조회를 사용하지 않으며, 이 조회 타입은 호스트 내부 정리 전까지 남아 있습니다.
`NativeWindow`는 `show(visible)`, `focus()`, `close()`, `isFullscreen()`, `getSizeConstraints()`, `setSizeConstraints(constraints)`, `setSize(width, height)`, `setPosition(x, y)`, `setFullscreen(value)`, `setCloseConfirmation(message)`를 제공합니다.
Windows의 선택적 `setFocusable`, `isFocusable`과 `WindowSpec.window.focusable`은 전경 활성화 허용을 제어합니다. 현재 실제 포커스와 별도이며 비활성 표시와 blur 후보 선택에도 적용합니다.

Windows의 선택적 `setMinimizable`, `isMinimizable`, `setMaximizable`, `isMaximizable`, `setClosable`, `isClosable`은 네이티브 버튼과 사용자 동작을 제어합니다. 호스트의 API close와 장애 정리는 허용하며 Close 메뉴 자원과 사용자 닫기 설정은 HWND 수명에 종속됩니다. 선택적 `setOpacity`, `getOpacity`는 HWND 전체의 불투명도(0–1)를 layered window alpha로 설정하고 OS 값에서 조회합니다. 선택적 `setHasShadow`, `hasShadow`는 custom title bar 창의 시스템 그림자를 DWM 비클라이언트 렌더링 정책으로 설정하고 DWM의 렌더링 상태에서 조회하며 네이티브 제목 표시줄 창은 그림자를 끌 수 없습니다. 선택적 `setRoundedCorners`, `hasRoundedCorners`는 `DWMWA_WINDOW_CORNER_PREFERENCE` 힌트를 설정하고 요청한 값을 조회하며 네이티브 제목 표시줄 창은 각지게 할 수 없습니다. 선택적 `setBackgroundMaterial`, `getBackgroundMaterial`은 `DWMWA_SYSTEMBACKDROP_TYPE` 힌트(`auto`, `none`, `mica`, `acrylic`, `tabbed`)를 설정하고 요청한 값을 조회하며 `transparent` 창은 `auto`와 `none` 외에 `UNSUPPORTED`로 거부합니다. 선택적 `setBackgroundColor`, `getBackgroundColor`는 소문자 `#rrggbb` 불투명 색을 HWND별 배경 지우기와 WebView2 컨트롤러의 기본 배경색에 설정하고, 정하지 않았으면 `null`을 조회합니다. `WindowSpec.window.backgroundColor`로 선언하며 `transparent` 창에서는 `UNSUPPORTED`입니다. 선택적 `setIgnoreMouseEvents`, `isIgnoreMouseEvents`는 HWND 전체(WebView 포함)가 마우스 입력을 아래 창으로 통과시키는지 설정하고 OS 스타일에서 조회합니다. 선택적 `setFullscreenable`, `isFullscreenable`은 전체화면 진입 허용만 HWND별로 저장하며 현재 전체화면에서 나가는 것은 항상 허용합니다.

Windows의 선택적 `setTitle(title)`과 `getTitle()`은 현재 HWND의 UTF-16 제목을 변경하고 조회합니다. 선언을 바꾸지 않으며 조회는 1024 코드 단위로 제한합니다. 네이티브 조회 오류와 길이 초과는 예외로 전달합니다.

Windows의 선택적 `setAccessibleTitle(title)`과 `getAccessibleTitle()`은 캡션과 별도로 스크린 리더 이름을 설정하고 조회합니다. 빈 문자열은 설정을 제거하며, 조회는 이 프로세스가 마지막으로 적용한 값 또는 `null`을 반환합니다.

Windows의 선택적 `NativeWindow.showPrintUI(kind)`는 `"browser" | "system"` 인쇄 UI를
요청합니다. 프린터 선택과 제출은 사용자에게 맡기며 메서드 반환을 인쇄 완료로 해석하지 않습니다.
닫힌 WebView는 `INVALID_ARGUMENT`, 생성 중에는 `BUSY`, 인쇄 확장 인터페이스가 없는
WebView2 런타임은 `UNSUPPORTED`입니다. 서비스가 없는 플랫폼도 창 플러그인이
`UNSUPPORTED`로 처리합니다. 호출 권한은 플러그인이 네이티브 진입 전에 검사합니다.

Windows의 선택적 `NativeWindow.capturePage(options)`는 `{ format, region }`을 받아 보이는 페이지를
PNG 또는 JPEG로 렌더링한 `NativePageCapture`(`mime`, base64 `data`, `width`, `height`)로 확정합니다.
`format`은 `PAGE_CAPTURE_FORMATS`(`"png"`, `"jpeg"`) 중 하나이고, `region`은 보이는 페이지의
왼쪽 위에서 잰 CSS 픽셀 사각형이며 각 변은 `MAX_PAGE_CAPTURE_EDGE`(16384) 이하입니다.
`region`이 `null`이면 보이는 영역 전체입니다. 창마다 하나만 실행하며 `BUSY`, 기한 초과 `TIMEOUT`
(`PAGE_CAPTURE_TIMEOUT_MS`, 15초), 영역이 보이는 페이지 밖이거나 이미지가
`MAX_PAGE_CAPTURE_BYTES`(655360)를 넘으면 `INVALID_ARGUMENT`입니다. 창이 닫히면 진행 중인
캡처를 거부합니다.

선택적 `NativeWindow.downloads`는 Windows의 `NativeDownloads` 서비스입니다.
`setRequestsEnabled(enabled)`는 요청 수집만 변경하며 `list()`는 WebViewDownload 배열을 반환합니다.
`approve(id)`, `cancel(id)`, `pause(id)`, `resume(id)`, `forget(id)`는 해당 WebView 수명의
항목을 제어합니다. 창 플러그인은 작업 권한과 backend 출처를 모두 검사한 뒤 서비스를 호출합니다.
다운로드 기본값은 거부이며 `DOWNLOAD_APPROVAL_TIMEOUT_MS`는 30초,
`MAX_WEBVIEW_DOWNLOADS`는 pending, 활성 및 종료된 기록을 합한 32개 상한입니다.
WebViewDownload는 id, url, mimeType, contentDisposition, path, totalBytes, receivedBytes,
state, interruptReason, canResume, paused를 제공합니다. byte 수의 null은 알 수 없거나
안전 정수 범위를 넘는 값입니다. 승인된 항목도 창 종료 시 취소하고 참조를 해제합니다.
호출자는 저장 경로를 바꾸거나 renderer 출처로 이 서비스를 사용할 수 없습니다.
`MAX_DOWNLOAD_METADATA_BYTES`는 JSON UTF-8 metadata 합계 64 KiB,
`MAX_DOWNLOAD_SNAPSHOT_BYTES`는 protocol 한도의 절반인 512 KiB입니다.
`isDownloadSnapshotWithinLimits`는 이스케이프와 UTF-8 크기를 계산하고 UUID, 숫자, 상태와
필드 이름의 최대 크기를 항목별로 예약합니다. 거부와 만료 뒤 retained 항목도 예산에 포함합니다.
실패한 native Cancel은 항목과 operation을 보존하며, cleanup도 실패한 소유 자원을 남겨
재시도하거나 관찰한 browser 종료 뒤 해제합니다.


선택적 `NativeWindow.webview`는 Windows UI 스레드의 `NativeWebView` 서비스입니다.
`getState()`는 URL, 문서 제목, 최상위 loading, history 이동 가능 여부와 controller zoom을
반환합니다. `navigate(url)`, `reload()`, `stop()`, `goBack()`, `goForward()`,
`setZoomFactor(factor)`, `openDevTools()`는 현재 창의 WebView만 제어합니다.
탐색은 기존 origin과 세션 경계를 유지하며 DevTools는 호스트 개발 설정이 필요합니다.
WebView가 닫히면 `INVALID_ARGUMENT`, 아직 생성 중이면 `BUSY`입니다.
서비스가 없는 플랫폼에서는 창 플러그인이 `UNSUPPORTED`를 반환합니다.

Windows의 선택적 `setResizable`, `isResizable`, `setMovable`, `isMovable`은 사용자 조작 허용을 변경하고 조회합니다. 프로그램의 geometry 작업에는 적용하지 않습니다. 전체화면 중의 resizable은 복원할 일반 창의 설정이며 HWND 종료 때 movable 설정을 정리합니다.

Windows의 선택적 `setAspectRatio(ratio)`와 `getAspectRatio()`는 사용자 크기 조절 중 내용 영역의 너비/높이 비율을 고정하거나(`null`이면 해제) 조회합니다. 설정할 때 현재 크기는 바꾸지 않습니다. `MIN_WINDOW_ASPECT_RATIO`(0.1)와 `MAX_WINDOW_ASPECT_RATIO`(10)가 허용 범위이고 `isWindowAspectRatio(value)`가 `null` 또는 이 범위의 유한한 수인지 확인합니다. 구현하지 않은 호스트는 메서드를 생략하고 플러그인이 `UNSUPPORTED`로 응답합니다.

Windows의 선택적 `startDragging()`과 `startResizeDragging(direction)`은 누르고 있는 마우스 기본 버튼을 시스템 이동, 크기 조절 루프로 넘깁니다. `direction`은 `WindowResizeDirection`(`north`, `south`, `east`, `west`, `northEast`, `northWest`, `southEast`, `southWest`)입니다. 버튼이 눌려 있지 않거나 창이 최소화, 최대화, 전체화면이거나 이동, 크기 조절이 막혀 있으면 `INVALID_ARGUMENT`를 던집니다. 구현하지 않은 호스트는 메서드를 생략하고 플러그인이 `UNSUPPORTED`로 응답합니다.

선택적 `NativeWindow.audio`는 Windows의 `NativeWebViewAudio` 서비스입니다.
`getState()`는 `WebViewAudioState`의 `muted`, `playing`을 반환하고 `setMuted(muted)`는
controller의 음소거를 변경합니다. 문서 탐색은 음소거를 유지하고 controller 재생성은
초기화합니다. 재생과 음소거는 독립 상태이며 물리 장치 출력을 의미하지 않습니다.
서비스가 없으면 windows 플러그인이 `UNSUPPORTED`로 거부하고 호출 권한은 네이티브
진입 전에 검사합니다. 생성 중에는 `BUSY`, 닫힌 WebView는 `INVALID_ARGUMENT`입니다.
`showInactive()`는 현재 일반, 최소화나 최대화 상태와 다른 창의 입력 포커스를 유지하며
숨김을 해제합니다. `activate()`는 표시된 비최소화 창의 전경 전환을 요청하고 실제
전경 여부를 boolean으로 반환합니다. 숨김이나 최소화 상태에서는 변경 없이 `false`입니다.
`focus()`는 먼저 표시하거나 최소화를 복원한 뒤 같은 전경 관찰로 결과를 반환합니다.
Windows 호스트는 활성화 뒤 양쪽 창의 실제 상태를 관찰해 이벤트와 snapshot에 반영합니다.
`blur`의 후보 선택은 windows 플러그인이 호출 컨텍스트의 제어 권한과 창 수명을 검사한
뒤 `activate()`로 실행합니다. macOS의 `showInactive()`는 `orderFront:`로 표시하며 key window 전환이나
앱 활성화를 요청하지 않고, 최소화한 창은 최소화 상태로 둡니다. macOS의 `activate()`는 `UNSUPPORTED`입니다.
상태 제어는 `minimize()`, `maximize()`, `unmaximize()`, `restore()`, `toggleMaximize()`입니다. 모두 동기 실행하며 숨긴 창도 표시합니다. `restore()`는 최소화 전 최대화 상태를 복원하고 `unmaximize()`는 일반 크기를 적용합니다. 전체화면 중에는 창 플러그인이 이 다섯 제어를 거부합니다. 크기 제약과 전체화면 복원 정보의 소유자는 계속 호스트입니다.
상태 조회는 `isMinimized()`, `isMaximized()`, `isFullscreen()`, `isVisible()`, `isFocused()`이며 `boolean`을 반환합니다. 최소화, 최대화, 표시 상태는 실제 HWND에서 읽고 `isFocused()`는 해당 HWND가 OS 전경 창인지 확인합니다. 전체화면은 해당 네이티브 창에 적용한 호스트 모드입니다. 조회는 표시나 포커스를 바꾸지 않습니다. 네이티브 상태 변경 또는 조회 실패는 예외를 던지며 UI 호스트가 공개 `INTERNAL` 오류로 변환합니다.
두 `close()` 메서드는 동기 또는 비동기로 닫기 수락 여부를 반환합니다.
Windows와 macOS의 선택적 `NativeWindow.respondClose(requestId, allow)`는 `windows.closeRequested`로 대기 중인
사용자 닫기에 답합니다. `allow: true`는 그 창 자신의 닫기 확인만 건너뛰고 닫기를 계속하며
`false`는 창을 유지합니다. macOS에는 닫기 확인이 없어 `true`는 닫기 순서만 계속합니다. 대기 중인 요청이 아니면 `INVALID_ARGUMENT`를 던집니다.
플러그인은 `windows.respondClose` 작업 권한을 검사한 뒤 호출합니다.

Windows의 선택적 `NativeWindow.destroy()`는 확인, 트레이 숨김과 종료 취소를 우회합니다.
플러그인은 백엔드 출처와 `windows.destroy` 작업 권한을 검사한 뒤 호출합니다.
`setParent(windowId, modal)`, `getParent()`, `getChildren()`는 현재 네이티브 수명으로
최상위 owner 관계를 설정하거나 조회합니다. `setEnabled(enabled)`와 `isEnabled()`는
입력 가능 상태를 제어하고 조회합니다. 이 바인딩이 없는 플랫폼은 `UNSUPPORTED`입니다.
선택적 `NativeWindowServices.destroy(view)`는 생성 취소와 오류 때 부분 자원을
무조건 정리하는 호스트 내부 경로이며 공개 API의 호출자 권한을 부여하지 않습니다.
호스트는 자식 세션을 먼저 철회하고 자식 HWND와 WebView 정리 뒤 부모를 파괴합니다.
마지막 모달의 정리가 끝날 때 부모의 이전 enabled 상태를 복원합니다.

`NativeWindow.getSnapshot()`은 `WindowSnapshot`을 반환합니다. `windowId`, `viewId`,
`revision`, `state`, `bounds`를 한 번에 관찰합니다. `WindowDisplayState`의
`visible`, `focused`, `minimized`, `maximized`, `fullscreen`, `alwaysOnTop`은 기존 상태 조회와
같은 의미이고 `WindowBounds`는 기존 물리 outer bounds와 같습니다.
`WindowChange`는 표시, 포커스, 창 상태, 전체화면, 항상 위 및 geometry 변경 이름의 합집합입니다.
`moved`, `resized`는 Windows 네이티브 이동/크기 조절 루프 종료의 최종 geometry 알림입니다. 시작과 최종 값이 같으면 발행하지 않으며 중간 관찰 뒤 새 revision을 사용합니다.
호스트가 창별 관찰을 소유하고 HWND 파괴 전에 해제합니다.

선택적 `NativeWindow.setTaskbarProgress(progress)`는 Windows 작업 표시줄 진행률을 설정합니다.
`{ state: "none" | "indeterminate" }` 또는
`{ state: "normal" | "paused" | "error", value: number }`를 받으며 value는 0~1입니다.
플러그인이 작업 권한, 입력과 창 수명을 검사합니다. 바인딩이 없으면 `UNSUPPORTED`,
작업 표시줄 버튼 생성 전에는 `BUSY`입니다. 호스트는 UI STA에서 동기 COM 호출을 완료한 뒤
반환하며 네이티브 실패는 UI 경계에서 `INTERNAL`로 변환합니다. 표시와 포커스를 변경하지 않습니다.
호스트는 버튼 재생성 때 마지막 성공 값을 다시 적용하고 HWND 파괴 때 폐기합니다.
선택적 `NativeWindow.setThumbnailClip(region)`은 작업 표시줄 썸네일에 내용 영역의 `{ x, y, width, height }`만 표시하고
`null`이면 해제합니다. 단위는 96 DPI 논리 픽셀이며 내용 영역을 넘는 부분은 잘라내고, 잘라낸 결과가 비면 `INVALID_ARGUMENT`입니다. 최소화 중에는 내용 영역 크기를 알 수 없어 자르지 않습니다.
선택적 `NativeWindow.setThumbnailToolTip(toolTip)`은 썸네일 툴팁을 설정하고 `null` 또는 빈 문자열이면 기본값으로 되돌립니다.
둘 다 `setTaskbarProgress`처럼 바인딩이 없으면 `UNSUPPORTED`, 버튼 생성 전에는 `BUSY`이며 버튼 재생성 때 마지막 성공 값을 다시 적용합니다.
선택적 `NativeWindow.setIcon(icon)`은 제목 표시줄, Alt+Tab, 작업 표시줄의 창 아이콘을 아이콘 공급자 `(sizePx) => HICON`으로 설정하고 `null`이면 앱 기본 아이콘으로 되돌립니다. 호스트는 작은 아이콘과 큰 아이콘 크기로 공급자를 한 번씩 호출하고 반환된 HICON을 소유해 교체, 되돌리기, HWND 파괴, 호스트 종료 때 해제하며, 공급자가 던진 오류는 그대로 전달하고 기존 아이콘을 유지합니다. 선택적 `NativeWindow.hasCustomIcon()`은 `setIcon`으로 지정한 아이콘이 적용 중인지 돌려줍니다.
선택적 `NativeWindow.setOverlayIcon(icon, description)`은 아이콘 공급자 `(sizePx) => HICON`과 접근성 설명으로 작업 표시줄 오버레이 아이콘을 설정하고, `icon`이 `null`이면 제거하며 `description`을 무시합니다.
호스트는 설정할 때와 버튼 재생성으로 다시 적용할 때 그 시점 창 DPI의 작은 아이콘 크기로 공급자를 호출하고, 반환된 HICON의 소유권을 받아 다음 설정, 제거, HWND 파괴, 셸 거부 때 해제합니다.
공급자가 던진 오류(예: `INVALID_ARGUMENT`)는 그대로 전달하며 기존 오버레이를 유지합니다. 나머지 오류와 재적용, 폐기는 위 설정과 같습니다.
선택적 `NativeWindow.setThumbnailToolbar(buttons)`는 작업 표시줄 썸네일 아래 툴바를 `buttons` 순서대로 바꾸며(최대 `NATIVE_THUMBNAIL_BUTTON_LIMIT`개, 빈 목록이면 모든 버튼을 숨김) 각 버튼은 `{ id, icon, tooltip, flags }`입니다.
`icon`은 오버레이와 같은 아이콘 공급자이고, 호스트는 버튼마다 한 번씩 호출해 반환된 HICON을 소유하며 툴바가 성공적으로 바뀐 뒤, 또는 HWND 파괴 때 해제합니다. 공급자가 던진 오류는 그대로 전달하고 기존 툴바를 유지합니다.
버튼을 누르면 호스트가 `windows.thumbnailToolbarClicked`로 그 버튼의 `id`만 알리므로 어댑터에 클릭 콜백은 없습니다. 버튼 생성 전 `BUSY`, 버튼 재생성 때의 재적용은 `setTaskbarProgress`와 같습니다.
`windows` 플러그인이 base64 ICO를 공용 ICO 검증으로 네이티브 호출 전에 검사하고 공급자를 만듭니다.
`NativeWindow.getBounds(area)`는 `"content"`, `"outer"`, `"normal"` 영역의 `WindowBounds`를 반환합니다. normal은 일반 상태 복원용 바깥 영역이며 작업 영역 좌표를 화면 좌표로 보정합니다. 전체화면 중에는 저장된 복원 크기를 현재 DPI와 제약으로 계산합니다.
Windows의 `WindowSpec.window.maximized`와 `fullscreen`은 초기 일반 영역에 최대화, 전체화면을 순서대로 적용합니다. 숨김 생성을 유지하며 초기 전체화면의 해제는 현재 표시 상태를 유지합니다.
선택적 `NativeWindow.center(monitorId?)`는 `monitorId`가 없으면 현재 모니터, 있으면 호출 시점에 해석한 공개 모니터 ID의 작업 영역에 outer 또는 normal 복원 영역을 중앙 배치합니다. 알 수 없는 ID는 `INVALID_ARGUMENT`이며 주 모니터로 대체하지 않습니다. 모니터 ID를 지원하지 않는 구현은 ID가 주어지면 `UNSUPPORTED`를 던집니다. Windows 구현은 표시, 활성화와 크기를 유지하며 전체화면을 거부합니다.
`getDpi()`는 가장 최근 처리한 DPI 변경을 반영합니다. 조회는 표시 상태를 바꾸지 않으며 네이티브 조회 실패는 호출 경계에서 `INTERNAL`로 처리합니다. 호스트는 플러그인에 자원을 넘기기 전에 대상 권한과 창 수명을 확인합니다.

`NativeWindow.setGeometry(area, geometry)`는 `"content" | "outer"` 영역에 물리 픽셀의
`{ x, y }`, `{ width, height }` 또는 `{ x, y, width, height }`를 적용합니다.
플러그인이 입력 schema와 단위를 검증하고 논리 입력을 현재 DPI로 변환합니다.
호스트는 content 크기가 200~8192 논리 픽셀인지 검사한 뒤 기존 크기 제약을 적용하고
변환된 rectangle 경계도 검사합니다. 일반 상태에서는 현재 영역, 최소화와 최대화 중에는
일반 복원 영역을 바꾸며 숨김, 활성화와 최소화 전 최대화 복원 이력을 유지합니다.
전체화면과 잘못된 크기, 경계는 `INVALID_ARGUMENT` 예외입니다. 검증 오류는 변경 전에
발생하며 네이티브 적용 실패는 UI 경계에서 `INTERNAL`로 변환합니다. 동기 적용 중에는
이벤트의 중간 관찰을 보류하고 완료 후 실제 현재 bounds를 관찰합니다.

`MIN_WINDOW_DIMENSION`과 `MAX_WINDOW_DIMENSION`은 설정과 창 API에 입력할 수 있는 정수 범위인 200과 8192입니다. 사용자가 제한 없이 조절하는 창의 크기 범위와는 별개입니다.
`isWindowSizeDimension(value)`는 `null` 또는 이 범위의 정수인지 확인합니다. `hasValidWindowSizeConstraints(constraints)`는 네 제약 값과 축별 최소값, 최대값의 순서를 검사합니다.
`WINDOW_BACKGROUND_COLOR_PATTERN`은 창 배경색으로 받는 `#RGB`와 `#RRGGBB` 형식이고, `normalizeWindowBackgroundColor(value)`는 유효한 값을 소문자 `#rrggbb`로 펼치며 그 밖의 값에는 `undefined`를 반환합니다. 알파가 있는 형식은 받지 않습니다.
`transparentWindowError(window)`는 `transparent: true`인 창 선언이 `titlebar: "custom"`이 아니거나 `backgroundColor`를 함께 선언했을 때 그 이유를 문장으로 반환하고, 투명하게 만들 수 있으면 `undefined`를 반환합니다.
`clampWindowSize(width, height, constraints)`는 논리 픽셀 크기를 지정한 제약 안으로 보정해 `{ width, height }`를 반환합니다. `null`인 제약은 보정에 사용하지 않습니다.

`NativeWindowServices.supportsCreationOptions`는 호출별 표시 옵션의 네이티브 지원 여부입니다.
선택적 `validateCreation(spec)`는 작업 영역과 DPI에 의존하는 입력을 슬롯 예약과
기존 창 종료 전에 검증합니다. HWND나 프로필을 생성하지 않으며 실패는 생성 요청에 전달됩니다.
`WindowSpec.window`는 `WindowPlacement`의 x/y, center, useContentSize와 preventOverflow를 포함합니다.
`INT32_MIN`과 `INT32_MAX`는 네이티브 코드가 좌표, 크기와 식별자를 저장하는 signed 32-bit 정수 범위이며
`MIN_WINDOW_COORDINATE`, `MAX_WINDOW_COORDINATE`는 같은 값을 화면 좌표 범위로 사용합니다.
`hasValidWindowPlacement(value)`는 좌표 쌍, boolean 타입과 center 충돌을 검사하고 타입을 좁힙니다.
크기 기준과 플랫폼 지원은 [초기 창 설정](/reference/configuration/#app)을 따릅니다.
Windows와 macOS는 true를 제공합니다. 공통 어댑터는 비어 있지 않은 options를
지원하지 않는 호스트에서 기존 창을 닫기 전에 `UNSUPPORTED`로 거부합니다. macOS는 title, 크기와
크기 제약, `visible`, `showWhenReady`만 받고 `validateCreation`에서 나머지 창 옵션을 같은 시점에 거부합니다.

`MAX_WINDOWS`는 창 정의 개수의 내부 상한인 128입니다. 설정 검증은 정확히 하나의 창 정의를 요구하며
실행 중인 창 개수와는 별개입니다.
`lookup.byRequest(requestId)`는 UI 호스트가 관리하는 요청의 인증된 컨텍스트에서 정확한
호출자 창을 찾습니다.
`creationSettled(key)`는 생성 성공, 실패와 취소 모두에서 재생성 메타데이터를 해제합니다.

선택적 `NativeWindowServices.systemEvents`는 UI 플러그인에 OS 변경 알림을 제공합니다.
`NativeSystemEvents.subscribe(receive, { sessionNotifications? })`는 첫 구독 때 숨김 HWND를
생성하고 마지막 구독 해제 때 정리합니다. 반환된 해제 함수는 반복 호출할 수 있습니다.
`NativeSystemSignal`은 설정, 테마, 시스템 색, accent와 전원 상태의 무효화 알림 및
suspend, resume, 현재 Windows 세션의 잠금과 잠금 해제 신호입니다.
설정과 색 등의 반복 알림은 한 메시지 pump에서 합치며 lifecycle 전환은 순서를 유지합니다.
resume은 시스템 복귀 알림인 PBT_APMRESUMEAUTOMATIC에만 대응합니다. 이후 사용자 활동을
알리는 PBT_APMRESUMESUSPEND는 추가 resume을 전달하지 않습니다.
콜백은 native WndProc 밖에서 실행합니다. 초기 상태 재생이나 이벤트 이력은 제공하지 않습니다.
세션 알림은 명시적으로 선택하며 WTS 등록 실패는 구독 호출에 전달합니다.
`publish(event, payload, requiredOperation)`는 수신자의 조회 작업 권한과 현재 이벤트 구독을
모두 검사하고 기존 native event 채널로 전달합니다. 지원하지 않는 호스트는 이 서비스를
생략합니다. 이 계약은 물리 절전이나 사용자의 실제 세션 전환 검증 결과가 아닙니다.
실패 때 보존했던 임시 프로필은 최종 종료 정리로 돌려 보냅니다.


## 모니터 서비스

Windows UI 호스트는 `NativeWindowServices.monitors`로 `NativeMonitorServices`의
list, primary, nearestPoint, nearestRect와 cursor 조회를 제공합니다.
선택적인 snapshot은 `NativeMonitorSnapshot`을 반환하며 오래된 호스트에서는 생략할 수 있습니다.
`NativeWindow.getMonitor()`는 HWND의 최대 겹침 모니터를 조회합니다.
두 서비스는 다른 플랫폼에서 생략할 수 있습니다.
결과인 `NativeMonitor`는 물리 bounds와 workArea, 현재 장치명 id, name, primary,
dpi와 scaleFactor 및 드라이버가 제공하는 rotation과 refreshRate를 포함합니다.
Win32 HMONITOR는 공개하지 않고 매 조회에서 다시 해석합니다.

`NativeMonitorSnapshot`의 sourceId는 관찰 수명의 UUID이고 revision은 0부터 시작합니다.
monitors는 마지막 유효 목록이며 error는 WireError 또는 null입니다.
`NativeMonitorChange`는 같은 sourceId와 증가한 revision, id 배열인 added, removed, changed 및
error를 이벤트로 전달합니다. 오류 진입과 복구도 revision을 증가시키고 오류 중에는 마지막
유효 목록을 유지합니다. 초기 상태는 이벤트로 재전송하지 않습니다.
UI 호스트는 디스플레이 알림을 메시지 처리 뒤 합쳐서 관찰하며 주기적으로 조회하지 않습니다.
전달에는 뷰의 `windows.monitorsChanged` 이벤트 허용과 `windows.getMonitorSnapshot` 조회 권한이
모두 필요합니다.


선택적 `NativeWindowServices.appearance`는 Windows UI 스레드의 창 프레임 수명 서비스를
제공합니다. `NativeAppearanceWindows.subscribe(receive)`는 기존 창과 이후 생성하는 창마다
`NativeAppearanceWindow`의 `windowId`, `setDark(dark)`, `setContentColorScheme(scheme)`를 전달합니다. receive가 반환한
정리 함수는 해당 창 수명 종료 때 실행합니다. subscribe가 반환한 정리 함수는 모든 창의
DWM dark mode를 해제하고 DLL을 닫습니다. 한 번에 하나의 플러그인 소유자만 구독합니다.
이미 종료한 창이나 해제한 구독의 setDark와 setContentColorScheme은 CANCELLED이며 HWND는
플러그인에 노출하지 않습니다. `setContentColorScheme`은 `auto`, `light`, `dark`로 웹 콘텐츠의
`prefers-color-scheme`을 지정합니다. WebView2 프로필 단위 설정이라 같은 프로필의 창은 마지막
값을 공유하며, 콘텐츠가 아직 없으면 마지막 값을 기억했다가 생성 직후 적용합니다.

Windows의 선택적 `getTitlebar`, `setAlwaysOnTop`, `isAlwaysOnTop`, `moveTop`, `moveToBottom`,
`setSkipTaskbar`, `isSkipTaskbar`는 창 caption 모드와 표시 옵션을 제공합니다. `WindowSpec.window`는
`titlebar`, `alwaysOnTop`, `skipTaskbar`를 선언합니다. 설정의 기본값은 system, false, false입니다.
custom은 caption만 제거하며 resize frame과 시스템 메뉴는 유지합니다. WebView2가 CSS
app-region의 drag/no-drag를 처리하고 없는 런타임은 UNSUPPORTED를 반환합니다.
setSkipTaskbar는 변경할 때 숨겨진 일반 창을 요구하며 그 외 상태는 BUSY입니다.
선택적 `setContentProtection(contentProtection)`과 `isContentProtected()`는 스크린샷과 화면 공유에서
창을 제외하는 상태를 변경하고 조회합니다. `WindowSpec.window.contentProtection`으로 선언하며 기본값은 false입니다.
창 상태와 관계없이 변경할 수 있고 적용할 수 없으면 실패합니다.
선택적 `requestAttention(mode)`와 `cancelAttention()`은 포커스나 표시 상태를 바꾸지 않고 작업 표시줄
버튼의 점멸을 시작하고 멈춥니다. mode는 `WindowAttentionMode`(`untilFocused` 또는 `continuous`)입니다.
네이티브 HWND와 WebView가 자원을 소유하며 새 창은 선언의 기본값에서 시작합니다.

## NativeDialogServices

Windows UI STA의 선택적 파일 선택 서비스입니다. `origin(requestId)`은 호스트가 인증한
창 ID를 반환하고 `owner(windowId)`은 정확한 창 수명의 HWND와 `alive()` 검사를 캡처합니다.
`createWindow(receive)`와 `destroyWindow(hwnd)`은 모달 취소 확인에 필요한 임시 비표시 창을
소유합니다. `poll()`은 제어 채널을 읽고 `stopping()`은 확정된 앱 종료 상태를 반환합니다.
`watchCancellation(requestId?)`은 검증한 제어 패킷의 취소 의도를 관측하는 수명입니다.
반환한 `cancelled()`로 확인하고 `dispose()`로 해제합니다. 관측 중에는 일반 작업, abort
리스너나 네이티브 정리를 실행하지 않습니다. 모달 스택이 반환한 뒤 정상 dispatch를 재개합니다.
