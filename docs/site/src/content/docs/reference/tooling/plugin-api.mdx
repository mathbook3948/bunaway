---

`@bunaway/plugin-api`는 AppDefinition, PluginDefinition, CommandContext와 DesktopOptions 등 공통 계약을 소유합니다. Core와 Backend SDK는 이 타입을 다시 export합니다. 플러그인은 Core를 설치하거나 import하지 않고 `@bunaway/plugin`과 공통 프로토콜을 사용합니다.

`@bunaway/plugin-api/host`의 currentHost는 실행 중인 명령이나 setup의 Host API를 반환합니다. bindCommandHost와 bindPluginHost는 같은 호출 컨텍스트에 실행을 묶습니다. 명령이 끝나면 후속 호출을 거부하고 setup의 작업은 백엔드 수명을 따릅니다. Backend SDK와 플러그인 작성 SDK가 같은 컨텍스트를 공유합니다.

## Native 창 호스트 계약

`@bunaway/plugin-api/native`는 UI 호스트와 선택 창 제어 플러그인이 공유하는 타입을 제공합니다.
앱에서 호출할 작업 이름, 입력과 출력, 권한 및 비동기 창 교체 로직은 선택 창 제어 플러그인이 소유합니다.

| 타입 | 계약 |
| --- | --- |
| `WindowSpec` | view ID, home URL, 제목, 초기 너비와 높이, 축별 초기 최소 및 최대 크기 제약, 선택적 startup 여부 |
| `WindowSizeConstraints` | 논리 픽셀 단위 최소 및 최대 너비와 높이. 제한이 없는 축은 `null` |
| `WindowBounds` | 화면 물리 픽셀 단위 `x`, `y`, `width`, `height`와 측정 또는 복원 크기 계산에 사용한 `dpi` |
| `WindowState` | 창의 `closed`, `cleaned`, `ready`, `failure`, `deadline` 상태 |
| `NativeWindowServices` | 창 사양, 상태 조회와 생성, 종료, 창 객체, 호스트 종료와 취소 확인, 시각과 UI tick |

`WindowSpec`은 `view`, `home`, `title`, `window`, `startup` 필드를 가집니다. `window`에는 초기 `width`, `height`와 선택적 `minWidth`, `minHeight`, `maxWidth`, `maxHeight`를 둡니다. 크기 값은 96 DPI 기준 논리 픽셀입니다.
`NativeWindowServices`는 `specs`, `read(view)`, `create(spec)`, `close(view)`, `window(view)`, `stopping()`, `cancelled(requestId)`, `now()`, `tick()`을 제공합니다.
선택적 `lookup`은 `byId(windowId)`, `byView(viewId)`, `focused()`, `lastActive()`로
`WindowIdentity`인 `{ windowId, viewId }` 또는 `null`을 반환합니다. 스냅샷이나 geometry를
새로 관찰하지 않는 조회입니다. `windowId`는 네이티브 수명 ID이고 `viewId`는 정책 ID입니다.
문서 탐색은 ID를 유지하며 네이티브 재생성은 새 ID를 발급합니다. 종료된 ID와 생성 전 뷰,
외부 전경 창은 `null`입니다. Windows는 활성 상태의 `WM_ACTIVATE`로 이력을 갱신하고
마지막 활성 창을 파괴하면 이전 창으로 되돌리지 않고 기록을 지웁니다.
플러그인은 인증된 출처와 대상 권한을 검증하고 닫혔거나 재생성 중인 창을 결과에서 제외합니다.
`lookup`이 없으면 식별자 탐색 API는 `UNSUPPORTED`를 반환합니다.
`NativeWindow`는 `show(visible)`, `focus()`, `close()`, `isFullscreen()`, `getSizeConstraints()`, `setSizeConstraints(constraints)`, `setSize(width, height)`, `setPosition(x, y)`, `setFullscreen(value)`, `setCloseConfirmation(message)`를 제공합니다.
`showInactive()`는 현재 일반, 최소화나 최대화 상태와 다른 창의 입력 포커스를 유지하며
숨김을 해제합니다. `activate()`는 표시된 비최소화 창의 전경 전환을 요청하고 실제
전경 여부를 boolean으로 반환합니다. 숨김이나 최소화 상태에서는 변경 없이 `false`입니다.
`focus()`는 먼저 표시하거나 최소화를 복원한 뒤 같은 전경 관찰로 결과를 반환합니다.
Windows 호스트는 활성화 뒤 양쪽 창의 실제 상태를 관찰해 이벤트와 snapshot에 반영합니다.
`blur`의 후보 선택은 windows 플러그인이 호출 컨텍스트의 제어 권한과 창 수명을 검사한
뒤 `activate()`로 실행합니다. macOS의 `showInactive()`와 `activate()`는 `UNSUPPORTED`입니다.
상태 제어는 `minimize()`, `maximize()`, `unmaximize()`, `restore()`, `toggleMaximize()`입니다. 모두 동기 실행하며 숨긴 창도 표시합니다. `restore()`는 최소화 전 최대화 상태를 복원하고 `unmaximize()`는 일반 크기를 적용합니다. 전체화면 중에는 창 플러그인이 이 다섯 제어를 거부합니다. 크기 제약과 전체화면 복원 정보의 소유자는 계속 호스트입니다.
상태 조회는 `isMinimized()`, `isMaximized()`, `isFullscreen()`, `isVisible()`, `isFocused()`이며 `boolean`을 반환합니다. 최소화, 최대화, 표시 상태는 실제 HWND에서 읽고 `isFocused()`는 해당 HWND가 OS 전경 창인지 확인합니다. 전체화면은 해당 네이티브 창에 적용한 호스트 모드입니다. 조회는 표시나 포커스를 바꾸지 않습니다. 네이티브 상태 변경 또는 조회 실패는 예외를 던지며 UI 호스트가 공개 `INTERNAL` 오류로 변환합니다.
두 `close()` 메서드는 동기 또는 비동기로 닫기 수락 여부를 반환합니다.

`NativeWindow.getSnapshot()`은 `WindowSnapshot`을 반환합니다. `windowId`, `viewId`,
`revision`, `state`, `bounds`를 한 번에 관찰합니다. `WindowDisplayState`의
`visible`, `focused`, `minimized`, `maximized`, `fullscreen`은 기존 상태 조회와
같은 의미이고 `WindowBounds`는 기존 물리 outer bounds와 같습니다.
`WindowChange`는 표시, 포커스, 창 상태, 전체화면 및 geometry 변경 이름의 합집합입니다.
호스트가 창별 관찰을 소유하고 HWND 파괴 전에 해제합니다.
`NativeWindow.getBounds(area)`는 `"content"`, `"outer"`, `"normal"` 영역의 `WindowBounds`를 반환합니다. normal은 일반 상태 복원용 바깥 영역이며 작업 영역 좌표를 화면 좌표로 보정합니다. 전체화면 중에는 저장된 복원 크기를 현재 DPI와 제약으로 계산합니다.
`getDpi()`는 가장 최근 처리한 DPI 변경을 반영합니다. 조회는 표시 상태를 바꾸지 않으며 네이티브 조회 실패는 호출 경계에서 `INTERNAL`로 처리합니다. 호스트는 플러그인에 자원을 넘기기 전에 대상 권한과 창 수명을 확인합니다.

`NativeWindow.setGeometry(area, geometry)`는 `"content" | "outer"` 영역에 물리 픽셀의
`{ x, y }`, `{ width, height }` 또는 `{ x, y, width, height }`를 적용합니다.
플러그인이 입력 schema와 단위를 검증하고 논리 입력을 현재 DPI로 변환합니다.
호스트는 content 크기가 200~4096 논리 픽셀인지 검사한 뒤 기존 크기 제약을 적용하고
변환된 rectangle 경계도 검사합니다. 일반 상태에서는 현재 영역, 최소화와 최대화 중에는
일반 복원 영역을 바꾸며 숨김, 활성화와 최소화 전 최대화 복원 이력을 유지합니다.
전체화면과 잘못된 크기, 경계는 `INVALID_ARGUMENT` 예외입니다. 검증 오류는 변경 전에
발생하며 네이티브 적용 실패는 UI 경계에서 `INTERNAL`로 변환합니다. 동기 적용 중에는
이벤트의 중간 관찰을 보류하고 완료 후 실제 현재 bounds를 관찰합니다.

`MIN_WINDOW_DIMENSION`과 `MAX_WINDOW_DIMENSION`은 설정과 창 API에 입력할 수 있는 정수 범위인 200과 4096입니다. 사용자가 제한 없이 조절하는 창의 크기 범위와는 별개입니다.
`isWindowSizeDimension(value)`는 `null` 또는 이 범위의 정수인지 확인합니다. `hasValidWindowSizeConstraints(constraints)`는 네 제약 값과 축별 최소값, 최대값의 순서를 검사합니다.
`clampWindowSize(width, height, constraints)`는 논리 픽셀 크기를 지정한 제약 안으로 보정해 `{ width, height }`를 반환합니다. `null`인 제약은 보정에 사용하지 않습니다.
