```sh
bunaway upgrade [directory] [--write]
```

directory의 package.json에 선언한 `@bunaway/*` 패키지와 `packageManager`가 지금 실행 중인 CLI의 릴리스와 같은지 확인합니다.
directory를 생략하면 현재 폴더를 검사합니다. `--write`가 없으면 아무 파일도 쓰지 않습니다.

## 출력과 종료 코드

항목마다 `OK`, `CHANGE`, `SKIP`, `FAIL` 중 하나를 출력합니다.

| 상태 | 의미 |
| --- | --- |
| OK | 이미 맞습니다. |
| CHANGE | 맞추어 고칠 값입니다. `--write`가 있으면 package.json에 씁니다. |
| SKIP | `workspace:`, `link:`, `file:`, `.tgz`, 상대 경로, `owner/repo` git 단축형 같이 레지스트리 버전이 아닌 지정은 그대로 두고 설치 버전도 비교하지 않습니다. 로컬 묶음으로 설치한 앱은 새 묶음의 파일로 직접 바꿔야 합니다. |
| FAIL | 직접 고쳐야 합니다. |

검사 모드는 CHANGE나 FAIL이 있으면 종료 코드 1을 반환해 CI에서 맞지 않는 상태를 잡을 수 있습니다.
`--write`는 package.json을 고칠 수 없는 FAIL(이 릴리스에 없는 `@bunaway/*` 패키지, overrides와 resolutions 안의 `@bunaway/` 규칙)이 없을 때만 쓰고 0을 반환합니다.

## 검사와 변경 대상

- `dependencies`, `devDependencies`, `optionalDependencies`, `peerDependencies`의 `@bunaway/*`: 이 CLI의 정확한 버전으로 맞춥니다. `^`, `~` 같은 범위는 [validate](/reference/cli/validate/)가 거부하므로 보존하지 않습니다.
- `packageManager`: `bun@<이 릴리스의 Bun 버전>`으로 맞춥니다.
- `engines.bun`: 있을 때만 이 릴리스의 Bun 버전으로 맞춥니다.
- 설치 상태: `node_modules`에 설치된 버전이 이 릴리스와 다르면 FAIL로 알립니다. 설치하지 않은 선택 의존성은 통과합니다.

## 쓰기 방식

- 쓰는 파일은 directory의 package.json 하나입니다. 심볼릭 링크이거나 일반 파일이 아니면 거부하고, UTF-8이 아닌 바이트가 있으면 읽지 않고 거부합니다.
- 들여쓰기, 줄바꿈(LF/CRLF), BOM, 끝 줄바꿈 여부와 키 순서를 유지합니다. 다시 쓴 결과가 원문의 서식과 달라질 수 있으면 쓰지 않고 FAIL로 알립니다.
- 같은 폴더의 임시 파일에 쓴 뒤 교체합니다. 계획한 뒤 파일이 바뀌었으면 아무것도 쓰지 않습니다.
- 잠금 파일과 `node_modules`는 바꾸지 않습니다. 쓴 뒤 `bun install`과 `bunaway validate`를 실행하세요.

설정 파일의 형식을 바꾸는 migration 단계는 아직 없습니다. 첫 형식 변경이 생길 때 그 변환과 함께 추가합니다.
