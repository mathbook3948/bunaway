```sh
bunaway dev [directory] [--inspect[=<port>]]
```

설정과 정책, 설치된 SDK를 확인하고 네이티브 도구를 준비한 뒤 변경 감시를 시작합니다.
소스 컴파일은 감시 시작 후 수행합니다. 시작할 때 소스에 문법 오류나 import 오류가 있어도 CLI는 종료하지 않고 다음 저장을 기다립니다. 설정, 소스 경로, 정책이나 도구 준비가 잘못되면 시작에 실패합니다.
`dev` 설정이 있으면 외부 UI 서버를 시작하고 HTTP 준비를 기다립니다.
모든 생성 앱의 실행 스크립트는 `bun run dev`입니다. Vite 기반 템플릿의 `dev.command`는 웹 전용 `dev:web`을 실행합니다.
개발 실행은 프로덕션 `build.command`를 실행하지 않습니다.

## 디버깅

Windows x64 개발 앱은 UI DevTools와 F12, Ctrl+Shift+I 단축키를 활성화합니다.
`--inspect`는 백엔드 Bun inspector를 `ws://127.0.0.1:6499/bunaway`에 연결합니다.
`--inspect=<port>`로 1부터 65535까지 다른 포트를 지정할 수 있습니다. 생략하면 inspector를 시작하지 않습니다.
이 옵션은 Windows x64에서만 지원하며 다른 플랫폼에서는 시작 전에 오류를 반환합니다.
Windows의 호환되는 명령 구현 변경은 창과 상태, 세션, 구독, 디버거 연결을 유지합니다.
계약과 설정 변경으로 전체 재시작한 뒤에는 같은 주소로 디버거를 다시 연결합니다.

개발 번들에는 원본 소스를 포함한 inline 소스맵을 생성합니다. 외부 서버를 사용하는 UI의 소스맵은 해당 서버가 제공합니다.
[개발 모드 디버깅](/guides/debugging/)에서 연결 설정과 원본 오류 위치를 확인하는 절차를 설명합니다.

## 파일 감시

감시 중인 파일을 저장하면 앱 코드 교체나 전체 재시작을 수행합니다.
node_modules, vendor, dist, .bunaway, .git, .next, .turbo는 호스트 재시작 감시에서 제외합니다.

외부 서버가 없으면 UI 변경도 전체 앱을 재시작합니다.
UI와 백엔드가 공유하는 파일의 변경도 전체 재시작하며 두 번들을 함께 갱신합니다.
외부 서버가 있으면 UI는 서버의 HMR로 갱신하고 다음 파일과 디렉터리를 감시합니다.

- `src-bunaway/`.
- `build.app`이 있는 디렉터리.
- 루트의 package.json, bun.lock, tsconfig.json.

앱 정의가 프로젝트 루트에 있으면 루트 파일만 감시하고 UI 하위 디렉터리는 제외합니다.
앱 정의에서 import한 프로젝트 내부 파일도 감시합니다. `shared/`, `services/`처럼 다른 디렉터리에 있는 전이 의존성과 JSON 파일도 앱 변경 처리 대상입니다. 성공한 검증마다 import 목록을 갱신하며, 실패하면 이전 목록을 유지합니다. 프로젝트 밖의 파일과 node_modules의 변경은 감시하지 않습니다.

## 재시작

Windows의 호환되는 명령 구현 변경은 앱 코드만 다시 번들해 교체합니다.
진행 중인 호출은 기존 코드로 완료하고 이후 호출부터 새 코드를 사용합니다.
StateStore 데이터는 유지하며 모듈 내부 변수는 초기화합니다.
계약, 상태 초기값, 플러그인 객체나 실행 설정 변경은 전체 재시작합니다.

이전 호스트가 종료된 뒤 빌드하고 새 호스트를 시작합니다.
Windows의 CLI 중단은 `desktop.beforeQuit`와 트레이 숨김을 우회하고 플러그인 StopHook과 자원을 정리합니다. 앱에서 시작한 종료 검사가 대기 중이어도 CLI 중단은 진행합니다.
빌드 중 파일이 다시 바뀌면 최신 변경을 빌드할 때까지 앱 실행을 미룹니다.
빌드에 실패하면 오류를 표시하고 다음 저장을 기다립니다. 빌드 실패 중에는 제외 디렉터리 밖의 프로젝트 파일 변경으로 재시도할 수 있으며, 성공하면 일반 감시 범위로 돌아갑니다. Windows 앱 코드 교체의 빌드 실패는 기존 앱을 유지합니다. 전체 재시작 경로에서는 이전 앱이 종료된 상태로 남습니다.
백엔드만 바뀌면 외부 서버를 유지하고, 서버 설정이 바뀌면 서버도 다시 시작합니다.

앱이 다시 시작되면 새 클라이언트 연결을 사용하고 메모리 상태도 초기화됩니다.
진행 중이던 요청과 구독은 정리되며 자동으로 다시 전송되지 않습니다. 이미 저장한 파일은 그대로 남습니다.

## 종료

Ctrl+C를 누르면 앱과 개발 서버의 자식 프로세스를 정리합니다. 창 닫기는 앱의 종료 취소와 숨김 설정을 따르며 앱이 종료되면 서버도 정리합니다. 서버가 종료되거나 준비 시간을 초과해도 같은 정리 과정을 거칩니다.
Windows에서 이전 앱이 40초 안에 종료되지 않으면 재시작을 중단합니다.
개발 서버는 CLI가 직접 실행합니다. 다른 서버가 같은 포트를 사용 중이면 오류가 발생합니다.

개발 산출물은 `.bunaway/<target>/`에 생성합니다. 개발 중에는 이 파일을 직접 실행하는 대신 dev 명령을 사용하세요.
배포할 앱은 build/package 명령으로 만듭니다.
