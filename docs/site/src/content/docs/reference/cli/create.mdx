```sh
bunaway create <new-directory> [--template vanilla|vite|react|vue|svelte] [--package-dir <tarball-directory>]
```

## 옵션

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| new-directory | 필수 | 아직 없는 앱 디렉터리. 부모 디렉터리는 존재해야 함 |
| --template | vanilla | vanilla, vite, react, vue, svelte |
| --package-dir | 없음 | 생성 앱의 @bunaway 의존성에 연결할 로컬 tarball 묶음 |

현재 공개 registry에 패키지가 배포되지 않았으므로 로컬 tarball 묶음으로 설치합니다.
옵션의 중복, 알 수 없는 옵션, 누락된 값, 지원하지 않는 템플릿은 거부합니다.

## 생성 동작

지정한 새 폴더에 앱을 생성합니다. 기존 폴더는 덮어쓰지 않습니다.
앱 ID는 디렉터리 이름을 정규화한 `app.<slug>`, 창 제목은 디렉터리 이름입니다.
`bunaway.json`, `policy.json`, 공통 `app.ts`와 UI가 생성됩니다.

vanilla 템플릿에는 정적 UI와 네이티브 dev/build 스크립트가 있습니다.
모든 템플릿은 dev/build/package/validate/doctor 스크립트로 앱 CLI를 실행합니다.
vite, react, vue, svelte 템플릿에는 웹 전용 dev:web/build:web/preview 스크립트와 `bunaway` CLI 스크립트도 있습니다.
`build.command`가 build:web을 연결하므로 별도 웹 빌드 없이 build와 package --build를 실행할 수 있습니다.
Vite 기반 템플릿은 공식 create-vite@9.2.1의 vanilla-ts, react-ts, vue-ts, svelte-ts 화면을 사용합니다.
화면과 UI 소스, 자산은 원본 그대로이며 네이티브 SDK 호출은 앱에서 추가합니다.
`bun run typecheck`로 UI 컴포넌트, 백엔드와 Vite 설정을 검사합니다.
`--package-dir`에는 같은 릴리스 버전의 tarball 묶음이 있는 경로를 지정합니다.
생략하면 의존성에 정확한 registry 버전을 기록합니다. 해당 버전은 현재 공개 registry에서 설치할 수 없습니다.

생성이 끝나면 출력된 안내에 따라 `bun install`로 의존성을 설치하고 앱을 검증한 뒤 실행하세요.
[첫 앱](/start/quickstart/)과 [Vite 개발](/guides/development/)을 참고하세요.
