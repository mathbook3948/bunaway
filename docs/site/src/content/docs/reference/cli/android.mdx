```sh
bunaway android sync [directory]
bunaway android build [directory]
bunaway android run [directory] --serial <device>
```

디렉터리를 생략하면 현재 프로젝트를 사용합니다. `sync`는 웹 빌드와 Bun 백엔드 번들을
실행한 뒤 앱의 `android/` 프로젝트를 생성하거나 갱신합니다. APK는 빌드하지 않습니다.
`build`와 `run`은 먼저 같은 동기화를 실행합니다. `run`에는 `adb devices`에 표시되는
기기 식별자를 반드시 전달해야 합니다. 선택한 기기에 APK를 설치한 뒤 기존 앱을 종료하고
새 Activity를 시작합니다. 빌드와 시작에 성공하면 명령이 끝나며 파일 변경은 감시하지 않습니다.
`run`은 앱 Manifest의 MAIN/LAUNCHER Activity를 찾아 시작합니다. 실행할 Activity가 없거나
ADB가 시작 오류를 반환하면 명령이 실패합니다.
설치와 시작에는 Gradle이 빌드 결과에 기록한 최종 application ID를 사용합니다.
앱 Gradle 설정에서 `applicationId`를 바꾸거나 debug `applicationIdSuffix`를 지정해도
그 ID에 해당하는 앱을 종료하고 실행합니다.

## 준비

`sync`는 Windows와 Bun 1.4.2가 필요합니다. 최초 동기화에서 고정된 Android Bun을 내려받습니다.
`build`와 `run`은 JDK 17 이상과 Android SDK도 필요합니다.
`JAVA_HOME`과 `ANDROID_HOME`에 설치 경로를 지정하세요. SDK에는 API 36 플랫폼과
Build Tools 36.1.0이 있어야 합니다. 필요한 Gradle과 Android 빌드 의존성은 최초 빌드에서
내려받으므로 네트워크 연결이 필요합니다.

앱이 사용하는 Android System WebView는 origin-matched message listener와
document-start script를 지원해야 합니다. 사용할 수 없으면 앱 초기화 오류를 표시합니다.

## Android Studio와 Java 코드

`sync` 후 Android Studio에서 앱의 `android/` 디렉터리를 엽니다.
웹 UI나 Bun 백엔드를 변경하면 `bunaway android sync`를 다시 실행한 뒤 IDE에서 빌드합니다.
Java 코드만 바꾸면 IDE에서 바로 빌드할 수 있습니다.

```text
android/
  app/src/main/java/dev/bunaway/app/MainActivity.java
  app/src/main/AndroidManifest.xml
  app/build.gradle
  settings.gradle
  build.gradle
  gradle/
  bunaway-project.json
  .bunaway/host/
  .bunaway/inputs/
  .bunaway/app.gradle
  .bunaway/settings.gradle
```

`app/`과 루트 Gradle 파일, Wrapper는 처음에만 생성합니다. 이후 동기화는 이 파일들과
`local.properties`를 덮어쓰지 않습니다. Java 코드와 리소스, Manifest 및 의존성을 앱 모듈에
추가하세요. 생성된 `MainActivity`는 Java의 `BunawayActivity`를 상속합니다.
수명주기를 재정의하면 `super` 호출을 유지해야 Bun과 WebView의 시작 및 종료가 연결됩니다.

앱의 `app/build.gradle`은 다음 연결로 시작합니다. 앱에 필요한 의존성과 설정은 그 아래에 추가합니다.

```groovy
apply from: rootProject.file('.bunaway/app.gradle')
```

`settings.gradle`은 앱 모듈을 선언하고 프레임워크 설정 스크립트를 연결합니다.
프레임워크의 내부 모듈 경로와 APK 입력 구조는 이 스크립트가 관리합니다.

```groovy
include ':app'
apply from: file('.bunaway/settings.gradle')
```

`.bunaway/`는 프레임워크 호스트, 웹 UI와 Bun 번들, 정책과 런타임을 담는 생성 영역입니다.
동기화할 때 전체를 교체하므로 직접 수정하지 마세요. 생성된 `.gitignore`는 이 영역과
빌드 캐시, 로컬 SDK 경로를 제외합니다. 나머지 네이티브 프로젝트는 버전 관리에 포함하세요.
프레임워크를 갱신하면 호스트와 입력은 다시 동기화되지만 앱이 소유하는 AGP 및 Wrapper 버전은
자동 변경하지 않습니다. 빌드 도구 버전 변경은 앱의 Gradle 설정에 직접 반영하세요.

기존 `android/`에 bunaway 프로젝트 표식이 없으면 동기화를 거부합니다.
생성 영역으로 이어지는 심볼릭 링크나 junction도 거부합니다.
현재 Java에서 Android 기능을 직접 추가할 수 있지만, TypeScript에서 새 네이티브 기능을
호출하는 플러그인 등록과 어댑터 자동 연결은 아직 제공하지 않습니다.

## 앱 설정과 지원 범위

기존 `src-bunaway/app.ts`, `bunaway.json`과 `policy.json`을 사용합니다.
`build.command`로 웹 빌드를 먼저 실행하고 `build.app`의 공통 앱 정의와
`build.frontend`의 웹 자산을 Android 프로젝트에 넣습니다. Android 전용 Bun 진입점은 작성하지 않습니다.

- `app.view`와 `app.home`으로 단일 뷰를 지정합니다. `app.windows`는 거부합니다.
- `app.home`은 패키지 자산을 제공하는 HTTPS URL이며 인증 정보와 포트는 허용하지 않습니다.
- `app.appId`는 점으로 구분된 Java 패키지 이름이어야 합니다.
- 정책의 뷰와 backend `permissions`는 빈 배열이어야 합니다. Android 네이티브 플러그인 어댑터는 아직 없습니다.
- 기본 생성 템플릿은 저장 플러그인을 사용합니다. 현재 Android에서는 해당 플러그인을 사용하는 기능과 권한을 제거한 앱 정의가 필요합니다.

공통 명령, 이벤트, 취소, 오류와 Core 상태는 기존 SDK를 사용합니다.
UI 초기화에서 앱 정의의 `CommandsOf`, `EventsOf`로 타입을 지정한 클라이언트를 만들고
실패를 처리하는 방법은 [createClient](/reference/client/create-client/)를 따릅니다.

현재는 패키지 웹 자산만 제공합니다. 외부 탐색과 웹 네트워크 요청은 차단하며,
웹 UI에는 백엔드 번들이나 호스트 설정을 제공하지 않습니다.
화면 회전은 WebView 문서와 세션을 재생성하며 Bun과 Core 메모리 상태를 유지합니다.
Activity를 종료하면 Core와 Bun을 종료합니다. 앱 프로세스 재시작 뒤 메모리 상태 복원은 제공하지 않습니다.

## 출력과 실패

성공한 APK는 `dist/android/app-debug.apk`이며 앱 ID와 APK SHA-256은 같은 디렉터리의
`manifest.json`에 기록합니다. 앱 ID는 Gradle 빌드 결과의 최종 application ID입니다.
x86_64와 arm64-v8a 런타임을 포함합니다.
현재 실제 실행 검증은 Android 16 API 36 x86_64 에뮬레이터에서 수행합니다.
ARM64 실기기와 API 29 실제 실행은 별도 검증이 필요합니다.

지원하지 않는 설정, 네이티브 권한, 잘못된 SDK 경로나 버전, 웹 또는 Gradle 빌드 실패는
명령 실패로 끝납니다. 동기화 실패는 이전 생성 영역을 유지하고, APK 빌드 실패는 이전 APK를
유지합니다. Gradle 빌드가 실패해도 그 전에 성공한 동기화는 유지됩니다.
게시 후 백업 제거 실패는 새 출력이 이미 게시됐다는 별도 오류로 보고합니다.
동일 Android 대상의 sync와 빌드, 실행은 같은 잠금으로 중복 작업을 거부합니다.
`run`은 APK 설치와 Activity 시작이 끝날 때까지 잠금을 유지합니다. SIGINT나 SIGTERM으로
중단하면 진행 중인 ADB 클라이언트의 종료를 확인한 뒤 잠금을 해제합니다.
설치나 시작이 실패하거나 중단돼도 이미 게시한 APK와 완료된 기기 작업은 유지됩니다.
Android Studio 빌드와 CLI 동기화는 동시에 실행하지 마세요. IDE 빌드는 이 잠금을 사용하지 않습니다.
debug APK와 개발용 서명은 출시 파일이 아닙니다. release APK, AAB와 Store 채널은 아직 제공하지 않습니다.
