```sh
bunaway validate [directory]
```

directory를 생략하면 현재 폴더를 검사합니다. 성공하면 `Configuration and policy are valid.`를 출력하고 종료 코드 0을 반환합니다.
실패하면 오류와 0이 아닌 종료 코드를 반환합니다. 이 명령은 파일을 검사하며 앱 실행이나 자동 수정은 하지 않습니다.

## 검사 범위

- `src-bunaway/bunaway.json` v1 및 허용 필드.
- 앱 정의 파일, 프런트엔드 디렉터리, 홈 자산과 프로젝트 내부 경로.
- AppDefinition의 default export 계약과 설치된 프레임워크/SDK 참조.
- 정확한 SDK 릴리스 버전, 설치 artifact inventory, alias/override 제한.
- 앱 ID, 창 크기, 로컬 home origin.
- 정책 스키마, 중복 뷰, HTTP origin 금지, 정확히 한 뷰와 app.view 일치.
- 선언한 bundle의 형식. bundle 생략 자체는 허용.

검사 대상은 프로젝트 파일과 의존성입니다. 명령의 실행 결과와 Host API 권한, OS 권한, GUI 동작은 앱을 실행해 확인하세요.
정책에 필요한 권한은 앱 개발자가 직접 선언합니다.

## Vite 앱

validate는 프로덕션 `build.frontend`의 실제 자산을 요구합니다.

```sh
bun run build
bun run bunaway validate
```

doctor와 dev의 개발 검증은 외부 서버가 있을 때 아직 없는 웹 출력 디렉터리를 허용합니다.
배포 전 검증에는 웹 빌드 결과가 필요합니다.

## 프로그램 API

`validateProject(directory, { development?: boolean }): Promise<Project>`.
`development`의 기본값은 false입니다. 반환 객체에는 root, frameworkRoot, appEntry, frontend, app, policy가 있습니다.
bundle과 dev를 선언했다면 함께 반환합니다.
지원 필드는 [설정](/reference/configuration/)과 [정책](/reference/policy/)을 따릅니다.
