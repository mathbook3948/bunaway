```sh
bunaway build [directory]
```

현재 머신의 Windows x64 또는 macOS arm64 대상 앱 산출물을 만듭니다.
현재 머신과 다른 플랫폼으로 교차 빌드할 수는 없습니다. Bun 1.4.2가 필요합니다.

## 준비와 자산

프로덕션 설정을 검증한 뒤 플랫폼의 네이티브 도구와 Bun, 라이선스, Loader를 준비하고 확인합니다.
앱 백엔드와 UI를 별도로 번들하고 정적 자산, 설정, 정책, 라이선스, manifest를 포함합니다.
Vite 같은 외부 UI 도구를 쓰면 웹 build 스크립트를 먼저 실행하세요.
`bunaway build`는 `dev.command`나 웹 프로덕션 빌드를 실행하지 않습니다.

자산에 심볼릭 링크가 있거나 대소문자만 다른 파일이 출력 경로에서 충돌하면 빌드에 실패합니다.
프런트엔드 `.d.ts`는 배포하지 않으며 입력과 출력 무결성은 manifest의 해시로 기록합니다.

## 출력과 실행

| 대상 | 출력 |
| --- | --- |
| Windows | `dist/windows-x64/` |
| macOS | `dist/macos-arm64/<appId>.app/` |

Windows 산출물은 `bunaway.cmd`, `launch.ps1`, assets, licenses, runtime/bun.exe를 포함합니다.
앱 폴더 전체를 배포하고 런처로 실행하세요.
런처는 고정된 Bun과 앱 자산을 확인하고 실행 환경을 준비합니다.
macOS에서는 `.app`을 만들고 로컬 실행용 ad-hoc 서명을 적용합니다. 배포에 필요한 Developer ID 서명과 공증은 별도로 진행합니다.

## 실패와 동시 작업

임시 작업 디렉터리에서 빌드하고 검증에 성공하면 최종 산출물을 교체합니다. 실패하면 이전 프로덕션 산출물을 유지합니다.
같은 target의 빌드와 패키징이 동시에 출력을 바꾸지 않도록 잠금을 사용합니다.
Windows에서 다시 빌드해도 기존 `packaged/`에서 인식한 채널의 산출물과 보고서는 유지합니다.

## 프로그램 API

`buildProject(directory, { development?, native? }): Promise<BuiltPackage>`.
`development`의 기본값은 false입니다. 도구에서 이미 준비한 NativeInputs를 재사용하려면 `native`를 전달합니다.
결과는 `output`, `package`, `executable`, `arguments`입니다.
프로그램 실행은 반환한 executable과 arguments를 함께 사용합니다.
