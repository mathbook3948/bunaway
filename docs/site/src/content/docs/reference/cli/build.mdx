```sh
bunaway build [directory]
```

현재 머신의 Windows x64 또는 macOS arm64 대상 앱 산출물을 만듭니다.
현재 머신과 다른 플랫폼으로 교차 빌드할 수는 없습니다. Bun 1.4.2가 필요합니다.

## 준비와 자산

앱 정의와 UI 자산을 빌드하고 정책 및 런타임을 포함한 앱 패키지를 만듭니다.
`build.command`가 있으면 프로젝트 루트에서 웹 프로덕션 빌드를 먼저 실행합니다.
기존 출력이 있어도 매번 실행하며, 종료 코드 0을 확인한 뒤 웹 출력 디렉터리와 시작 페이지, 앱 소스를 검증합니다.
웹 빌드 명령이 연결된 앱도 `bun run build` 한 번으로 앱을 만듭니다.
`build.command`를 생략하면 지정한 정적 UI를 CLI가 번들합니다.
개발 서버 명령 `dev.command`는 실행하지 않습니다. [빌드 설정](/reference/configuration/#build)에서 기존 앱의 연결 방법을 확인하세요.

자산에 심볼릭 링크가 있거나 대소문자만 다른 파일이 출력 경로에서 충돌하면 빌드에 실패합니다.
프런트엔드의 `.d.ts` 파일은 앱에 포함되지 않습니다.

## 출력과 실행

| 대상 | 출력 |
| --- | --- |
| Windows | `dist/windows-x64/` |
| macOS | `dist/macos-arm64/<appId>.app/` |

Windows 산출물은 `bunaway.cmd`, `launch.ps1`, assets, licenses, runtime/bun.exe를 포함합니다.
앱 폴더 전체를 배포하고 런처로 실행하세요.
macOS에서는 `.app`을 만들고 로컬 실행용 ad-hoc 서명을 적용합니다. 배포에 필요한 Developer ID 서명과 공증은 별도로 진행합니다.

## 실패와 동시 작업

웹 빌드가 실패하거나 성공 후 출력 디렉터리나 시작 페이지가 없으면 앱 빌드를 중단합니다.
빌드에 실패하면 이전 프로덕션 앱 산출물을 유지합니다. 외부 빌드 도구가 수정한 웹 출력은 해당 도구가 관리합니다.
같은 target의 빌드와 패키징은 동시에 실행하지 마세요. 충돌하면 잠금 오류로 실패합니다.
잠금은 웹 빌드부터 앱 산출물 게시까지 유지합니다.
Windows에서 다시 빌드해도 기존 `packaged/`에서 인식한 채널의 산출물과 보고서는 유지합니다.
