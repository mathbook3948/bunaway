```ts
context.host.call("log.write", { level, message, details? }): Promise<null>
```

호스트의 앱 로그에 기록합니다. UI의 `console.log`나 백엔드 stdout과는 다른 API입니다.

```ts
await context.host.call("log.write", {
  level: "info", message: "메시지를 저장했습니다", details: { length: text.length },
});
```

## 입력

| 필드 | 필수 | 제약 |
| --- | --- | --- |
| `level` | 예 | debug·info·warn·error |
| `message` | 예 | 문자열, 최대 1,024자 |
| `details` | 아니요 | JSON 데이터. 전체 메시지 제한 적용 |

## 정책과 결과

뷰 명령은 그 뷰의 `host.log: true`, 백엔드 setup은 `backend.log: true`가 필요합니다.
기본 템플릿은 둘 다 false라서 예시를 그대로 추가하면 거부됩니다.
플러그인의 `requiredHost.log`를 true로 선언하는 것만으로 권한이 생기지 않습니다.
성공 결과는 `null`입니다.

Windows 구현은 앱 데이터의 `logs/app.log`에 JSON 줄을 추가하고,
기록에 시간과 원래 `source`를 포함합니다. 1 MiB를 넘은 기존 로그는 다음 기록 시 한 번 회전합니다.
정확한 저장 위치·회전 방식은 플랫폼 구현의 동작이므로 공통 출력 형식으로 모든 플랫폼에 강제하지 않습니다.

권한 부족은 `PERMISSION_DENIED`, 입력 위반은 `INVALID_ARGUMENT`, 일반 기록 실패는 `INTERNAL`입니다.
민감한 데이터는 앱에서 기록 내용을 정해 제외해야 합니다. 전달한 임의 details를 자동으로 모두 비밀값 제거한다고 가정하지 않습니다.
현재 기본 로그 플러그인은 빈 모듈이지만 이 Host operation은 구현돼 있습니다.
