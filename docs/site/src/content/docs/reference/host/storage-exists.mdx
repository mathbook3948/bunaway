```ts
storage.exists({ path }): Promise<boolean>
```

`@bunaway/plugin-storage`의 `storage.exists`는 지정한 파일이나 디렉터리가 있는지 반환합니다. 네이티브 구현은 Windows와 macOS에서 지원합니다.

```ts
import storage from "@bunaway/plugin-storage";

const exists = await storage.exists({
  path: "C:/Users/me/Documents/messages/한글 memo.txt",
});
```

## 입력과 권한

`path`는 [storage.readText](/reference/host/storage-read-text/)와 같은 경로 계약을 따릅니다. 현재 Windows 구현은 드라이브 또는 UNC 공유에서 시작하는 절대 경로를 받습니다.

호출 출처의 permissions에 `storage.exists`를 허용합니다. UI에서 직접 호출하려면 해당 뷰의 `commands`에도 `plugin.storage.exists`를 허용합니다. 이 권한은 호출자가 지정한 유효한 경로에 적용합니다. 파일별 접근 제한은 앱 명령에서 검사하고 화면에는 그 앱 명령만 허용합니다.

```json
{
  "commands": ["plugin.storage.exists"],
  "host": {
    "permissions": [
      "storage.exists"
    ]
  }
}
```

앱에서 `storage`를 등록해야 합니다. 뷰에서 시작한 백엔드 명령은 해당 뷰의 `host.permissions`를 사용합니다. 플러그인 setup과 setup에서 시작한 작업은 `backend.permissions`를 사용합니다. 권한 정책과 호출 출처는 [백엔드 Host API](/reference/backend/host-api/)를 확인하세요.

화면용 함수는 두 번째 인자로 `InvokeOptions`를 받습니다. `signal`과 `deadline`은 [호출 취소와 기한](/reference/client/invoke/)의 의미를 따릅니다.

## 결과와 오류

파일이나 디렉터리가 있으면 `true`, 실제로 없는 경로이면 `false`입니다. 부모 경로나 마지막 경로가 없을 때만 `false`를 반환하고 접근 거부를 파일 없음으로 바꾸지 않습니다. 링크는 따라가므로 대상이 없는 링크는 `false`입니다.

잘못된 경로는 `INVALID_ARGUMENT`입니다. 작업 권한이 없거나 운영체제가 접근을 거부하면 `PERMISSION_DENIED`이며, 그 밖의 파일 시스템 오류는 `INTERNAL`입니다. 일반 파일과 디렉터리가 아닌 대상(FIFO 등)은 `INVALID_ARGUMENT`입니다.

결과는 조회 시점의 관찰이며 이후 경로가 계속 존재한다는 보장은 아닙니다.

취소되거나 기한이 지난 호출은 각각 `CANCELLED` 또는 `TIMEOUT`으로 실패할 수 있습니다. 이미 시작된 운영체제 작업이 되돌려지거나 중단된다고 보장하지 않습니다. 플러그인 미등록 또는 현재 호스트에서 사용할 수 없는 네이티브 구현은 `UNSUPPORTED`입니다.

## macOS 경로

macOS는 POSIX 정규 절대 경로를 받습니다. `/tmp`와 `/var`의 symlink 별칭 대신
`/private/tmp`와 `/private/var` 같은 실제 경로를 사용하세요. 상대 경로, `.`과 `..`,
빈 경로 요소와 끝의 `/`를 거부합니다. 경로는 NUL을 포함해 1024 bytes 이하,
각 이름은 UTF-8 기준 255 bytes 이하여야 합니다. symlink와 여러 hardlink가 있는 파일을
거부하며 OS 접근 거부를 없는 대상으로 숨기지 않습니다. 작업별 권한과 취소 규칙은
Windows와 같으며 macOS에서도 I/O Worker에서 실행합니다.
