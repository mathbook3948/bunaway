```ts
storage.copyFile({ from, to }): Promise<null>
storage.move({ from, to }): Promise<null>
```

`copyFile`과 `move`는 Windows와 macOS에서 지원합니다. `storage`를 등록하고
`storage.copyFile` 또는 `storage.move` 권한을 각각 허용합니다.
직접 화면 호출에는 해당 이름 앞에 `plugin.`을 붙인 명령 권한도 필요합니다.
이 권한은 다른 전송 작업이나 일반 읽기와 쓰기를 허용하지 않습니다.

`from`과 `to`는 [텍스트 읽기](/reference/host/storage-read-text/)와 같은 앱 지정 절대 경로입니다.
앱 명령에서 두 위치의 접근 규칙을 모두 검사하세요. 추가 필드, overwrite와 recursive 옵션은 받지 않습니다.
`to`의 상위 디렉터리는 존재해야 합니다. 원본이 링크이면 링크가 가리키는 파일을 복사합니다.

## 파일 복사

`copyFile`은 일반 파일의 내용만 복사하며 크기 상한이 없습니다.
대상 파일을 배타적으로 만들고(`O_EXCL`, Windows는 `CREATE_NEW`) 최대 1 MiB 단위로 바이트를 옮기므로 큰 파일도 메모리에 모두 올리지 않습니다.
복사하는 동안 원본이 커지면 시작할 때 확인한 크기까지만 복사하고, 줄어들면 `INTERNAL`로 실패하며 일부만 쓴 대상이 남을 수 있습니다.
기존 파일, 디렉터리와 대상이 있는 링크는 덮어쓰지 않고 `INVALID_ARGUMENT`로 실패하며 그 뒤에 있는 파일도 바뀌지 않습니다.
대상이 없는 링크는 POSIX에서는 `INVALID_ARGUMENT`로 거부하지만, Windows의 `CREATE_NEW`는 링크를 따라가 링크가 가리키는 위치에 새 파일을 만듭니다(기존 데이터는 덮어쓰지 않습니다).
임의 바이트와 빈 파일을 보존합니다.

복사는 하나의 동기 작업이라 시작한 뒤에는 취소할 수 없습니다. 큰 파일은 그만큼 같은 I/O Worker의 다른 호출을 지연시킵니다.
복사 중 다른 프로세스가 원본을 바꾸면 복사본이 일관되지 않을 수 있고, 앱 전체나 파일 시스템 전체의 원자적 스냅샷을 보장하지 않습니다.
복사본은 OS의 상속 ACL과 새 생성 및 쓰기 시각을 사용하며 원본의 ACL, 속성과 시각을 복제하지 않습니다.

```ts
import storage from "@bunaway/plugin-storage";

await storage.copyFile({
  from: "C:/notes/한글.txt",
  to: "C:/archive/한글.txt",
});
```

이 복사는 원자적 저장이나 crash recovery를 제공하지 않습니다.
읽기나 쓰기가 중간에 실패하면 일부만 복사된 대상이 남을 수 있습니다.
대상 이름이 다른 파일로 바뀌었을 수 있으므로 이름으로 찾아 삭제하지 않으며 원본은 유지합니다.
큰 파일과 stream 복사, 디렉터리 재귀 복사는 후속 작업입니다.

## 파일과 디렉터리 이동

`move`는 파일 또는 디렉터리를 새 이름으로 옮깁니다. Windows는 `MoveFileExW`를 덮어쓰기 플래그 없이, macOS는 `renamex_np`를
`RENAME_EXCL`로 호출하므로 검사와 이름 변경 사이에 생긴 대상도 덮어쓰지 않습니다.
대상 이름이 이미 있으면 `INVALID_ARGUMENT`로 실패하고 아무것도 바꾸지 않습니다. 같은 디렉터리 안의 이름 변경과
같은 볼륨의 다른 디렉터리로의 이동을 지원합니다. 디렉터리는 내용을 읽거나 링크를 따라가지 않고 디렉터리 자체를 옮기며,
원본이 링크이면 링크 자체를 옮깁니다.

source와 destination이 같거나 source의 하위 경로로 이동하면 `INVALID_ARGUMENT`입니다.
다른 볼륨으로의 이동은 복사하지 않고 `UNSUPPORTED`이며 source를 그대로 둡니다.
대상 상위 디렉터리가 없거나 source가 없으면 `INVALID_ARGUMENT`입니다.
파일 시스템이나 다른 프로세스의 열린 핸들 때문에 실패할 수 있습니다.

## 실패와 취소

입력, 없는 대상 또는 parent, 기존 destination과 복사 상한 위반은 `INVALID_ARGUMENT`,
작업 권한과 OS 접근 거부는 `PERMISSION_DENIED`입니다.
공유 위반과 일반 I/O 실패는 `INTERNAL`일 수 있습니다.
전송에 필요한 source 읽기 및 삭제 권한, destination 생성 권한과 OS 상속 ACL은 작업별로 적용합니다.

모든 작업은 I/O Worker에서 실행하며 Promise를 반환합니다.
두 번째 인자의 signal과 deadline은 [호출 취소와 기한](/reference/client/invoke/)을 따릅니다.
처리 전 취소는 작업을 막지만 시작한 동기 OS 작업을 중간에 끊거나 되돌리지 않습니다.
timeout이나 연결 종료 후에도 전송이 완료됐을 수 있습니다. 재시도 전에 두 위치의 실제 상태를 확인하세요.
덮어쓰기, 다른 볼륨의 move 및 원자적 저장의 충돌 및 복구 계약은 후속 작업입니다.

## macOS copyFile

POSIX 절대 경로를 사용하며 symlink는 따라갑니다. 크기 상한은 없고 기존 대상은 파일, 디렉터리와
대상이 없는 링크를 포함해 덮어쓰지 않습니다.
대상을 `O_EXCL`로 만든 뒤 원본을 1 MiB씩 옮기며 동시 쓰기의 일관된 스냅샷을 보장하지 않습니다.
쓰기 실패 때 일부 대상이 남을 수 있습니다. 교체된 이름을 찾아 삭제하지 않으며
원본은 유지합니다.
