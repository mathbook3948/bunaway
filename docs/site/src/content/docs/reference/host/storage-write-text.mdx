```ts
storage.writeText({ scope, path, text }): Promise<null>
```

`@bunaway/plugin-storage`의 화면용 함수는 두 번째 인자로 `InvokeOptions`를 받습니다.
signal과 deadline의 의미는 [호출 취소와 기한](/reference/client/invoke/)을 따릅니다.

저장 범위 안의 파일에 텍스트를 씁니다. 기존 파일 내용은 새 텍스트로 대체합니다.

```ts
import { storage } from "@bunaway/plugin-storage";

await storage.writeText({
  scope: "appData",
  path: "messages/current.txt",
  text: "저장할 문자열",
});
```

## 입력과 정책

`storage`는 명령이나 `defineApp()`으로 연결한 플러그인 setup에서 호출합니다.
플러그인 등록과 실행 범위는
[백엔드 Host API](/reference/backend/host-api/)에서 확인하세요.

`scope`, `path`는 [storage.readText](/reference/host/storage-read-text/)와 같은 필수 경로 계약입니다.
`text`는 필수 JSON 문자열이며 추가 필드는 허용하지 않습니다.
text에는 별도 글자 수 제한이 없지만 전체 요청은 UTF-8 기준 1 MiB 이하여야 합니다.
앱 명령의 입력 스키마에 더 작은 상한을 정할 수 있으며 템플릿은 10,000자로 제한합니다.

storagePlugin을 등록하고 permissions에 `storage:write-text`와 파일 범위를 allow에 지정합니다.
UI에서 storage.writeText를 직접 호출하면 commands에 `plugin.storage.writeText`도 허용합니다. 읽기 권한만 있는 범위에서는 쓰기를 거부합니다.
허용한 디렉터리와 파일 범위 안에서만 저장할 수 있습니다.
Windows에서는 상위 디렉터리를 고정하기 위해 디렉터리 목록 접근 권한도 필요합니다. 이 운영체제 접근이 거부되면 `PERMISSION_DENIED`로 실패합니다.

## 반환과 이벤트

성공은 `null`입니다. 템플릿은 저장 성공 뒤 `message.saved`를 발행합니다.
파일 저장이 끝난 뒤 이벤트 전달에 실패해도 파일은 저장된 상태입니다.
여러 파일의 트랜잭션이나 버전 이력이 필요하면 앱에서 관리합니다.

## 취소와 재시도

진행 전 취소는 작업을 막습니다. 이미 시작하거나 끝난 쓰기는 자동 롤백하지 않습니다.
클라이언트가 `TIMEOUT`을 받거나 연결이 끊겼을 때도 파일은 이미 저장됐을 수 있습니다.
파일을 다시 읽어 완료 여부를 확인한 뒤 필요하면 재시도를 안내합니다.

잘못된 입력은 `INVALID_ARGUMENT`, 권한, 운영체제 접근과 경로 거부는 `PERMISSION_DENIED`,
취소는 `CANCELLED`, 일반 작업, 응답 실패는 `INTERNAL`일 수 있습니다.
삭제, append, 바이너리 쓰기는 현재 별도의 Host operation으로 제공하지 않습니다.
