```ts
storage.writeText({ path, text, atomic? }): Promise<null>
```

`@bunaway/plugin-storage`의 화면용 함수는 두 번째 인자로 `InvokeOptions`를 받습니다.
signal과 deadline의 의미는 [호출 취소와 기한](/reference/client/invoke/)을 따릅니다.

앱이 지정한 경로의 파일에 텍스트를 씁니다. 기존 파일 내용은 새 텍스트로 대체하며 없는 상위 디렉터리는 만듭니다.

```ts
import storage from "@bunaway/plugin-storage";

await storage.writeText({
  path: "C:/Users/me/Documents/messages/current.txt",
  text: "저장할 문자열",
});
```

## 입력과 정책

`storage`는 명령이나 `defineApp()`으로 연결한 플러그인 setup에서 호출합니다.
플러그인 등록과 실행 범위는
[백엔드 Host API](/reference/backend/host-api/)에서 확인하세요.

`path`는 [storage.readText](/reference/host/storage-read-text/)와 같은 필수 경로 계약입니다.
`text`는 필수 JSON 문자열이며 `atomic`을 뺀 추가 필드는 허용하지 않습니다.
text에는 별도 글자 수 제한이 없지만 전체 요청은 UTF-8 기준 1 MiB 이하여야 합니다.
앱 명령의 입력 스키마에 더 작은 상한을 정할 수 있으며 템플릿은 10,000자로 제한합니다.

`storage`를 등록하고 permissions에 `storage.writeText`를 지정합니다.
UI에서 직접 호출하려면 commands에 `plugin.storage.writeText`도 허용합니다. 읽기 권한만 있으면 쓰기를 거부합니다.
저장 위치와 파일별 접근 제한은 앱 명령에서 정하고 화면에는 그 명령만 허용합니다.
대상이 링크이면 링크가 가리키는 파일에 씁니다. 디렉터리나 FIFO처럼 일반 파일이 아닌 대상은 `INVALID_ARGUMENT`입니다.

## 원자적 저장

`atomic: true`를 주면 같은 폴더의 임시 파일에 전체 내용을 쓰고 디스크에 반영한 뒤 대상 위에 교체합니다.
쓰는 도중 실패하거나 프로세스가 끝나도 대상은 이전 내용이거나 새 내용이며, 반쯤 쓰인 파일이 되지 않습니다.
실패하면 임시 파일을 지우고 기존 대상은 바뀌지 않습니다. 생략하거나 `false`이면 지금처럼 같은 파일에 덮어씁니다.
`atomic`은 `storage.writeText`와 `storage.writeBytes`에만 있고 append 작업은 이 필드를 거부합니다.

- 교체는 같은 폴더 안의 이동이므로 대상 파일은 새 파일로 바뀝니다. 기존 파일의 ACL, 대체 데이터 스트림과
  하드 링크는 이어지지 않습니다. POSIX 권한 비트는 유지합니다.
- 대상이 링크이면 링크는 그대로 두고 가리키는 파일을 교체합니다. 가리키는 파일이 없는 링크는 `INVALID_ARGUMENT`입니다.
- 읽기 전용 파일은 덮어쓰기와 같이 `PERMISSION_DENIED`입니다. Windows에서는 다른 프로세스가 대상을 열고 있으면
  삭제 공유 여부와 관계없이 교체할 수 없어, 짧게 다시 시도한 뒤 `PERMISSION_DENIED`로 실패하고 기존 파일은 그대로입니다.
- Windows는 `MoveFileExW`의 교체와 write-through로 이동을 디스크에 반영합니다. macOS는 이름 바꾸기 뒤 폴더를 동기화합니다.
- 보장은 같은 볼륨 안의 교체입니다. 네트워크 파일 시스템에서는 서버의 동작에 따릅니다.
  전원 차단에서의 내구성은 운영체제와 저장 장치가 쓰기를 실제로 반영하는지에 달려 있어 보장하지 않습니다.
- 임시 파일은 `.bunaway-`로 시작하고 `.tmp`로 끝나는 예측할 수 없는 이름으로 배타적으로 만듭니다.
  프로세스가 교체 전에 끝나면 이 파일이 남을 수 있습니다.
- 다른 프로세스가 읽은 뒤 바꾼 파일을 감지하지 않습니다. 감지가 필요한 앱은 파일을 읽기 전에 [storage.stat](/reference/host/storage-stat/)의
  `modifiedAtMs`와 `sizeBytes`를 기억해 두었다가 쓰기 직전의 값과 비교하세요. 이 앱이 쓴 뒤에는 `stat`으로 기준값을 다시 잡습니다. 비교와 쓰기 사이의 변경, 기준값을 다시 잡기 전의 변경, 같은 앱의 여러 호출 사이의 겹침, 시각 해상도 한계는 남습니다
  ([결정](https://github.com/mathbook3948/bunaway/blob/main/docs/decisions/0126-storage-concurrent-modification-detection.md)).
- 대용량 stream I/O는 이 옵션의 범위가 아닙니다.

```ts
await storage.writeText({
  path: "C:/Users/me/Documents/messages/current.txt",
  text: "저장할 문자열",
  atomic: true,
});
```

## 반환과 이벤트

성공은 `null`입니다. 템플릿은 저장 성공 뒤 `message.saved`를 발행합니다.
파일 저장이 끝난 뒤 이벤트 전달에 실패해도 파일은 저장된 상태입니다.
여러 파일의 트랜잭션이나 버전 이력이 필요하면 앱에서 관리합니다.

## 취소와 재시도

진행 전 취소는 작업을 막습니다. 이미 시작하거나 끝난 쓰기는 자동 롤백하지 않습니다.
클라이언트가 `TIMEOUT`을 받거나 연결이 끊겼을 때도 파일은 이미 저장됐을 수 있습니다.
파일을 다시 읽어 완료 여부를 확인한 뒤 필요하면 재시도를 안내합니다.

잘못된 입력은 `INVALID_ARGUMENT`, 권한과 운영체제 접근 거부는 `PERMISSION_DENIED`,
취소는 `CANCELLED`, 일반 작업, 응답 실패는 `INTERNAL`일 수 있습니다.
바이트 읽기와 쓰기, 텍스트 및 바이트 append는 [바이너리 저장과 append](/reference/host/storage-bytes/)에서 설명합니다.

## macOS 경로

macOS는 `/`로 시작하는 POSIX 절대 경로를 받습니다. 상대 경로, `.`과 `..`,
빈 경로 요소, 끝의 `/`, NUL과 줄바꿈을 거부합니다. 경로는 NUL을 포함해 1024 bytes 이하,
각 이름은 UTF-8 기준 255 bytes 이하여야 합니다. 그 밖의 경로는 일반 파일 API처럼 따라가므로
`/tmp` 같은 별칭과 symlink, hardlink도 그대로 동작합니다. 어떤 위치를 허용할지는 앱 명령이 정합니다.
OS 접근 거부는 `PERMISSION_DENIED`이며 없는 대상으로 숨기지 않습니다. 작업별 권한과 취소 규칙은
Windows와 같으며 macOS에서도 I/O Worker에서 실행합니다.
