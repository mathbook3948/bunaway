```ts
capabilities(): Promise<HostOutput<"capabilities.get">>
```

앱 백엔드에서 현재 플랫폼 기능 정보를 조회합니다.
UI에서는 [client.capabilities](/reference/client/capabilities/)를 사용합니다.

```ts
import { capabilities } from "@bunaway/backend";

const support = await capabilities();
```

## 응답 필드

| 필드 | 필수 | 값, 제약 |
| --- | --- | --- |
| `name` | 예 | 영숫자, `_ . : -`, 1–128자 |
| `support` | 예 | supported, experimental, unsupported |
| `permission` | 예 | granted, denied, prompt, not-required, unknown |
| `reason` | 아니요 | 문자열, 최대 1,024자 |

현재 Windows는 storage.readText, storage.writeText, log.write, capabilities.get을
supported, not-required로 보고합니다.

## 권한 의미

support는 플랫폼의 구현 상태이고 permission은 현재 OS 권한 상태입니다.
조회는 현재 상태를 반환하며 정책 변경이나 OS 권한 요청은 실행하지 않습니다.
조회 결과와 별도로 파일 범위 및 명령 호출 권한은 정책에 허용해야 합니다.

`capabilities()`에는 인자가 없습니다. 명령이나 `defineApp()`으로 연결한 플러그인 setup에서 호출합니다.
기존 `context.host.call("capabilities.get", null)`도 지원하며 이 작업의 입력은 반드시 null입니다.
실행 범위는 [백엔드 Host API](/reference/backend/host-api/)에서 확인하세요.
잘못된 입력은 `INVALID_ARGUMENT`,
취소는 `CANCELLED`, 유효하지 않은 응답은 `INTERNAL`로 실패합니다.
