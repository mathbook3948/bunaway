```ts
storage.stat({ path }): Promise<StorageMetadata | null>
```

`@bunaway/plugin-storage`의 `storage.stat`은 파일이나 디렉터리의 메타데이터를 반환합니다. 대상이 실제로 없으면 `null`입니다. 네이티브 구현은 Windows와 macOS에서 지원합니다.

```ts
import storage from "@bunaway/plugin-storage";

const metadata = await storage.stat({
  path: "C:/Users/me/Documents/messages/한글 memo.txt",
});

if (metadata?.kind === "file") {
  console.log(metadata.sizeBytes, metadata.modifiedAtMs);
}
```

## 반환 필드

`StorageMetadata`의 필드는 다음과 같습니다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `kind` | `"file" \| "directory"` | 파일 또는 디렉터리 |
| `sizeBytes` | `number \| null` | 파일 크기. 디렉터리는 재귀 계산을 하지 않으므로 `null` |
| `createdAtMs` | `number \| null` | 생성 시각, UTC Unix epoch 밀리초 |
| `modifiedAtMs` | `number \| null` | 수정 시각, UTC Unix epoch 밀리초 |
| `accessedAtMs` | `number \| null` | 접근 시각, UTC Unix epoch 밀리초 |

파일 시스템과 설정에 따라 시각의 정확도가 달라지며, 읽기 작업이 접근 시각을 갱신할 수도 있습니다. `sizeBytes`는 파일에만 제공됩니다. 디렉터리 크기를 계산하거나 내용을 나열하지 않습니다.

다른 프로세스의 변경을 쓰기 전에 감지하려면 파일을 읽기 전에 `modifiedAtMs`와 `sizeBytes`를 기억해 두었다가 쓰기 직전의 값과 함께 비교하고, 앱이 쓴 뒤에는 기준값을 다시 잡습니다. `modifiedAtMs`가 `null`이거나, 앱이 직접 쓴 뒤에도 `modifiedAtMs`가 바뀌지 않으면 이 방법을 쓸 수 없습니다. 이 방법의 한계는 [결정](https://github.com/mathbook3948/bunaway/blob/main/docs/decisions/0126-storage-concurrent-modification-detection.md)에 있습니다.

## 입력과 권한

`path`는 [storage.readText](/reference/host/storage-read-text/)와 같은 경로 계약을 따릅니다. Windows 구현은 드라이브 또는 UNC 공유에서, macOS 구현은 `/`에서 시작하는 절대 경로를 받습니다.

호출 출처의 permissions에 `storage.stat`을 허용합니다. UI에서 직접 호출하려면 해당 뷰의 `commands`에 `plugin.storage.stat`도 허용합니다. 이 권한은 호출자가 지정한 유효한 경로에 적용합니다. 파일별 접근 제한은 앱 명령에서 검사하고 화면에는 그 앱 명령만 허용합니다.

```json
{
  "commands": ["plugin.storage.stat"],
  "host": {
    "permissions": [
      "storage.stat"
    ]
  }
}
```

앱에 `storage`를 등록해야 합니다. 뷰에서 시작한 백엔드 명령은 해당 뷰의 `host.permissions`를 사용합니다. 플러그인 setup과 setup에서 시작한 작업은 `backend.permissions`를 사용합니다. 화면용 함수의 두 번째 인자는 `InvokeOptions`이고 `signal`과 `deadline`은 [호출 취소와 기한](/reference/client/invoke/)의 의미를 따릅니다.

```ts
import storage from "@bunaway/plugin-storage";

const abortController = new AbortController();
const metadata = await storage.stat(
  { path: "C:/Users/me/Documents/messages/current.txt" },
  { signal: abortController.signal },
);
```

## 오류와 조회 규칙

부모 경로나 마지막 경로가 없을 때만 `null`을 반환하고 운영체제의 접근 거부를 `null`로 숨기지 않습니다. 링크는 따라가며 링크가 가리키는 대상의 정보를 반환합니다. 대상이 없는 링크는 `null`입니다.

잘못된 경로는 `INVALID_ARGUMENT`입니다. 작업 권한이 없거나 운영체제가 접근을 거부하면 `PERMISSION_DENIED`이며, 그 밖의 파일 시스템 오류와 `Number.MAX_SAFE_INTEGER`를 초과하는 크기는 `INTERNAL`입니다. 일반 파일과 디렉터리가 아닌 대상(FIFO 등)은 `INVALID_ARGUMENT`입니다. 플러그인 미등록 또는 현재 호스트에서 사용할 수 없는 네이티브 구현은 `UNSUPPORTED`입니다.

결과는 조회 시점의 관찰이며 호출 뒤에도 대상이 존재하거나 값이 유지된다는 보장은 아닙니다.

화면 호출의 취소와 기한 초과는 `CANCELLED`와 `TIMEOUT`으로 실패할 수 있습니다. 조회 작업이 이미 운영체제에 전달된 뒤에는 취소가 해당 작업을 되돌리거나 중단한다고 보장하지 않습니다.

## macOS 메타데이터

macOS도 POSIX 절대 경로의 일반 파일과 디렉터리를 조회합니다. symlink는 따라가며
hardlink는 일반 파일입니다. 생성, 수정과 접근 시각을 UTC Unix epoch 밀리초로 반환합니다.
실제로 없으면 null이고 OS 접근 거부는 `PERMISSION_DENIED`입니다.
다른 프로세스의 삭제나 쓰기를 막지 않으므로 결과는 조회 시점의 관찰입니다.
