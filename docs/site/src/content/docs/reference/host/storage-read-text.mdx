```ts
storage.readText({ path }): Promise<string>
```

앱이 지정한 경로의 파일을 텍스트로 읽습니다. UI에서는 `@bunaway/plugin-storage`의 storage.readText를 직접 호출하거나 앱 명령을 작성합니다.
화면용 함수는 두 번째 인자로 `InvokeOptions`를 받습니다.
signal과 deadline의 의미는 [호출 취소와 기한](/reference/client/invoke/)을 따릅니다.

```ts
import storage from "@bunaway/plugin-storage";

return storage.readText({
  path: "C:/Users/me/Documents/messages/current.txt",
});
```

## 입력

`storage`는 명령이나 `defineApp()`으로 연결한 플러그인 setup에서 호출합니다.
플러그인 등록과 실행 범위는
[백엔드 Host API](/reference/backend/host-api/)에서 확인하세요.

| 필드 | 필수 | 제약 |
| --- | --- | --- |
| `path` | 예 | 비어 있지 않은 경로 문자열, 최대 4,096자 |

입력은 `path`만 받습니다. 저장 폴더와 파일별 접근 규칙은 앱에서 정합니다.
플러그인은 앱 데이터나 임시 폴더를 자동으로 선택하거나 만들지 않습니다.
Windows 구현은 드라이브 또는 UNC 공유에서, macOS 구현은 `/`에서 시작하는 절대 경로를 받으며 `/`와 역슬래시를 모두 사용할 수 있습니다.
상대 경로, `.`, `..`, 빈 경로 요소, NUL, 개행과 Windows에서 허용하지 않는 파일 이름(예약된 장치 이름, `:`와 같은 금지 문자, 이름 끝의 점과 공백)은 `INVALID_ARGUMENT`로 거부합니다.
`\\?\`, `\\.\`, `\??\`로 시작하는 장치와 NT 경로도 거부합니다.
플러그인은 이 입력 형식만 검사합니다. 대소문자가 다른 표기나 8.3 짧은 이름도 같은 파일로 열립니다.

## 정책

먼저 `storage`를 등록하고 호출 출처의 permissions에 `storage.readText`를 허용합니다.
UI에서 직접 호출하려면 commands에 `plugin.storage.readText`도 허용합니다.
파일별 접근을 제한하려면 앱 명령에서 입력을 검사하고 저장 경로를 정하며, 화면에는 그 앱 명령만 허용합니다.
파일 링크(symlink, junction)와 하드 링크는 일반 경로처럼 따라갑니다. 앱이 정한 폴더 밖을 가리키는 링크는 플러그인이 막지 않으므로,
링크를 만들 수 있는 사용자가 쓰는 폴더라면 앱 명령이 그 위험을 감안해 경로를 정하세요([파일 경로 제한은 앱 명령에서 합니다](/concepts/views-and-policy/#파일-경로-제한은-앱-명령에서-합니다)).
검사한 뒤 사용하기 전에 다른 프로세스가 대상을 바꿀 수 있고, 이것도 앱의 책임입니다. 운영체제의 파일 접근 권한도 필요합니다.

## 결과와 오류

결과는 JSON 문자열입니다. 응답 하나가 메시지 상한(1 MiB) 안에 들어가도록 파일은 512 KiB 이하여야 하고,
JSON으로 인코딩한 결과가 768 KiB를 넘어도 실패합니다. NUL 같은 제어 문자는 JSON에서 여섯 배로 늘어나므로
파일 크기가 상한 안이어도 이 두 번째 검사에 걸릴 수 있습니다. 두 경우 모두 `INVALID_ARGUMENT`입니다.
더 큰 파일은 백엔드에서 `Bun.file`로 직접 읽거나 [`storage.readBytes`의 범위 읽기](/reference/host/storage-bytes/#범위-읽기)로 나눠 읽으세요.
파일이 없으면 성공한 빈 문자열로 바꾸지 않고 실패합니다. 안정된 `NOT_FOUND` 코드는 현재 없습니다.
`INVALID_ARGUMENT`는 잘못된 입력과 디렉터리 또는 FIFO처럼 일반 파일이 아닌 대상, `PERMISSION_DENIED`는 작업 권한, 운영체제 접근 거부와 풀 수 없는 링크 순환,
`CANCELLED`는 요청 종료, `INTERNAL`은 공유 잠금 충돌 등 일반 파일 작업 실패에 사용합니다.

처음 실행하는 UI는 읽기 실패를 표시하고 저장 기능을 사용할 수 있게 합니다.
파일 누락 외에 권한 거부나 파일 작업 오류로도 읽기가 실패합니다.
이 API는 지정한 텍스트 파일을 읽습니다. 바이너리 읽기나 디렉터리 목록, 파일 선택 기능은 제공하지 않습니다.

## macOS 경로

macOS는 `/`로 시작하는 POSIX 절대 경로를 받습니다. 상대 경로, `.`과 `..`,
빈 경로 요소, 끝의 `/`, NUL과 줄바꿈을 거부합니다. 경로는 NUL을 포함해 1024 bytes 이하,
각 이름은 UTF-8 기준 255 bytes 이하여야 합니다. 그 밖의 경로는 일반 파일 API처럼 따라가므로
`/tmp` 같은 별칭과 symlink, hardlink도 그대로 동작합니다. 어떤 위치를 허용할지는 앱 명령이 정합니다.
OS 접근 거부는 `PERMISSION_DENIED`이며 없는 대상으로 숨기지 않습니다. 작업별 권한과 취소 규칙은
Windows와 같으며 macOS에서도 I/O Worker에서 실행합니다.
