```ts
storage.readText({ path }): Promise<string>
```

앱이 지정한 경로의 파일을 텍스트로 읽습니다. UI에서는 `@bunaway/plugin-storage`의 storage.readText를 직접 호출하거나 앱 명령을 작성합니다.
화면용 함수는 두 번째 인자로 `InvokeOptions`를 받습니다.
signal과 deadline의 의미는 [호출 취소와 기한](/reference/client/invoke/)을 따릅니다.

```ts
import { storage } from "@bunaway/plugin-storage";

return storage.readText({
  path: "C:/Users/me/Documents/messages/current.txt",
});
```

## 입력

`storage`는 명령이나 `defineApp()`으로 연결한 플러그인 setup에서 호출합니다.
플러그인 등록과 실행 범위는
[백엔드 Host API](/reference/backend/host-api/)에서 확인하세요.

| 필드 | 필수 | 제약 |
| --- | --- | --- |
| `path` | 예 | 비어 있지 않은 경로 문자열, 최대 4,096자 |

입력은 `path`만 받습니다. 저장 폴더와 파일별 접근 규칙은 앱에서 정합니다.
플러그인은 앱 데이터나 임시 폴더를 자동으로 선택하거나 만들지 않습니다.
현재 Windows 구현은 드라이브 또는 UNC 공유에서 시작하는 절대 경로를 받으며 `/`와 역슬래시를 모두 사용할 수 있습니다.
상대 경로, `.`, `..`, 빈 경로 요소, NUL, 개행과 Windows에서 허용하지 않는 파일 이름은 `INVALID_ARGUMENT`로 거부합니다.
Windows에서는 저장된 이름의 대소문자와 긴 파일명을 그대로 사용해야 합니다.
같은 파일을 가리키는 다른 대소문자 표기나 8.3 짧은 이름은 `PERMISSION_DENIED`로 거부합니다.
Windows에서 상위 디렉터리를 작업 중 고정하려면 운영체제의 디렉터리 목록 접근 권한도 필요합니다. 실제 목록을 읽지는 않으며, 이 접근이 거부되면 `PERMISSION_DENIED`로 실패합니다.

## 정책

먼저 storagePlugin을 등록하고 호출 출처의 permissions에 `storage.readText`를 허용합니다.
UI에서 직접 호출하려면 commands에 `plugin.storage.readText`도 허용합니다.
파일별 접근을 제한하려면 앱 명령에서 입력을 검사하고 저장 경로를 정하며, 화면에는 그 앱 명령만 허용합니다.
Windows 구현은 파일 링크를 따라가지 않습니다. 운영체제의 파일 접근 권한도 필요합니다.

## 결과와 오류

결과는 JSON 문자열이며 응답 메시지 크기 제한도 적용됩니다.
파일이 없으면 성공한 빈 문자열로 바꾸지 않고 실패합니다. 안정된 `NOT_FOUND` 코드는 현재 없습니다.
`INVALID_ARGUMENT`는 잘못된 입력, `PERMISSION_DENIED`는 작업 권한, 운영체제 접근 거부와 링크 또는 경로 별칭 거부,
`CANCELLED`는 요청 종료, `INTERNAL`은 일반 파일 작업 실패 등에 사용합니다.

처음 실행하는 UI는 읽기 실패를 표시하고 저장 기능을 사용할 수 있게 합니다.
파일 누락 외에 권한 거부나 파일 작업 오류로도 읽기가 실패합니다.
이 API는 지정한 텍스트 파일을 읽습니다. 바이너리 읽기나 디렉터리 목록, 파일 선택 기능은 제공하지 않습니다.

## macOS 경로

macOS는 POSIX 정규 절대 경로를 받습니다. `/tmp`와 `/var`의 symlink 별칭 대신
`/private/tmp`와 `/private/var` 같은 실제 경로를 사용하세요. 상대 경로, `.`과 `..`,
빈 경로 요소와 끝의 `/`를 거부합니다. 경로는 NUL을 포함해 1024 bytes 이하,
각 이름은 UTF-8 기준 255 bytes 이하여야 합니다. symlink와 여러 hardlink가 있는 파일을
거부하며 OS 접근 거부를 없는 대상으로 숨기지 않습니다. 작업별 권한과 취소 규칙은
Windows와 같으며 macOS에서도 I/O Worker에서 실행합니다.
