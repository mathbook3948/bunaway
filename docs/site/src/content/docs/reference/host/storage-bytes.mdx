```ts
storage.readBytes({ path, offset?, length? }): Promise<string>
storage.writeBytes({ path, bytes }): Promise<null>
storage.appendBytes({ path, bytes }): Promise<null>
storage.appendText({ path, text }): Promise<null>
```

`@bunaway/plugin-storage`의 Windows와 macOS 작업입니다. 두 번째 인자의 signal과 deadline은
[호출 취소와 기한](/reference/client/invoke/)을 따릅니다.
모든 작업은 Promise를 반환하고 호스트의 I/O Worker에서 실행합니다.

## 바이트와 경로

`bytes`와 `readBytes` 결과는 표준 알파벳과 필요한 `=` padding을 사용한 canonical base64 문자열입니다.
빈 바이트는 `""`입니다. 공백, URL-safe 알파벳, 생략한 padding과 0이 아닌 padding bits는 거부합니다.
바이트 입력과 한 번의 읽기 결과의 상한은 각각 256 KiB입니다. base64와 경로, 메시지 envelope를
포함한 JSON 전송이 1 MiB 상한 안에 들어가도록 정한 값입니다. `offset`과 `length` 없이 파일 전체를 읽을 때
파일이 이 상한보다 크면 `INVALID_ARGUMENT`로 실패하며, 큰 파일은 아래의 범위 읽기로 나눠 읽습니다. 바이트 작업은 UTF-8로 디코딩하지 않으므로 0과 임의의 바이트를 보존합니다.
`appendText`는 문자열을 UTF-8로 인코딩하며 전체 요청의 1 MiB 상한을 따릅니다.

`path`는 [텍스트 읽기](/reference/host/storage-read-text/)와 같은 앱 지정 절대 경로입니다.
Windows drive와 UNC 경로를 허용하며 extended-length와 device 경로, 상대 경로, ADS와
Windows에서 쓸 수 없는 이름을 거부합니다. Unicode와 공백을 허용합니다.
링크는 일반 경로처럼 따라가며 일반 파일이 아닌 대상은 `INVALID_ARGUMENT`입니다.

## 범위 읽기

`offset`(바이트 위치, 0 이상의 정수)과 `length`(1 이상 256 KiB 이하의 정수) 중 하나라도 주면 파일 전체 대신
그 범위만 읽습니다. `offset`의 기본값은 0이고 `length`의 기본값은 256 KiB입니다. 범위가 파일 끝을 넘으면
있는 만큼만 돌려주고, `offset`이 파일 끝 이후이면 `""`를 돌려줍니다. 범위 읽기는 `offset` 앞의 바이트를 읽지 않으므로
파일 크기에 상한이 없습니다. 읽는 동안 파일이 줄어들면 읽은 부분만 돌려줍니다. 호출마다 파일을 새로 열기 때문에
호출 사이에 파일이 바뀌면 조각들이 서로 맞지 않을 수 있습니다.

```ts
import storage from "@bunaway/plugin-storage";

await storage.writeBytes({ path: "C:/notes/data.bin", bytes: "AP8=" });
await storage.appendBytes({ path: "C:/notes/data.bin", bytes: "gA==" });
const encoded = await storage.readBytes({ path: "C:/notes/data.bin" }); // "AP+A"
const tail = await storage.readBytes({ path: "C:/notes/data.bin", offset: 2, length: 1 }); // "gA=="
```

백엔드에서 바이트 배열을 변환할 때는 `Buffer.from(bytes).toString("base64")`와
`Buffer.from(encoded, "base64")`를 사용할 수 있습니다. 화면은 `btoa`와 `atob`를 사용할 수 있습니다.
화면에서 입력한 경로를 그대로 승인하기보다 앱 명령이 저장 위치와 대상 접근 규칙을 정하세요.

## 권한과 저장 동작

`storage`를 등록하고 작업별로 `storage.readBytes`, `storage.writeBytes`,
`storage.appendBytes`, `storage.appendText` 권한을 허용합니다. 직접 화면 호출에는
같은 이름 앞에 `plugin.`을 붙인 명령 권한도 필요합니다.
읽기, 대체 쓰기, append와 텍스트 작업의 권한은 각각 독립적입니다.

대체 쓰기는 기존 내용을 덮어쓰고 성공 후 남은 꼬리를 잘라냅니다.
빈 바이트 대체는 파일을 비웁니다. append는 append 모드로 파일 끝에 추가하며
기존 내용을 자르지 않습니다. 없는 파일과 상위 디렉터리는 만들고 빈 append도 없는 파일을 만듭니다.
읽기 대상이 없으면 `INVALID_ARGUMENT`입니다.

이 작업들은 원자적 저장이나 여러 요청의 트랜잭션을 제공하지 않습니다.
네이티브 write가 일부만 완료되면 반복해서 남은 내용을 씁니다. 동시에 실행하는 다른 프로세스의
append가 그 사이에 들어갈 수 있으므로 레코드 단위 순서와 충돌 처리는 앱에서 관리합니다.
실패, 종료나 이미 시작한 작업의 취소는 부분 쓰기를 되돌리지 않습니다.
완료 여부가 불명확한 append를 자동 재전송하면 내용이 중복될 수 있습니다.

잘못된 입력은 `INVALID_ARGUMENT`, 권한과 OS 접근 거부는 `PERMISSION_DENIED`,
취소는 `CANCELLED`, 큰 읽기와 일반 I/O 실패는 `INTERNAL`입니다.
파일 핸들 API, stream I/O, 대화상자 범위의 일시 허용과 영속화는 후속 작업입니다.

## macOS 경로

macOS는 `/`로 시작하는 POSIX 절대 경로를 받습니다. 상대 경로, `.`과 `..`,
빈 경로 요소, 끝의 `/`, NUL과 줄바꿈을 거부합니다. 경로는 NUL을 포함해 1024 bytes 이하,
각 이름은 UTF-8 기준 255 bytes 이하여야 합니다. 그 밖의 경로는 일반 파일 API처럼 따라가므로
`/tmp` 같은 별칭과 symlink, hardlink도 그대로 동작합니다. 어떤 위치를 허용할지는 앱 명령이 정합니다.
OS 접근 거부는 `PERMISSION_DENIED`이며 없는 대상으로 숨기지 않습니다. 작업별 권한과 취소 규칙은
Windows와 같으며 macOS에서도 I/O Worker에서 실행합니다.
