기본 export(`default`)를 `clipboard`로 가져와 앱에 등록하고 호출합니다.

`@bunaway/plugin-clipboard`를 설치하고 앱의 `plugins`에 `clipboard`를 등록합니다. Windows와 macOS 어댑터를 제공합니다. URL bookmark와 사용자 정의 binary 형식은 Windows에서만 제공합니다.

```ts
import { defineApp } from "@bunaway/backend";
import clipboard from "@bunaway/plugin-clipboard";

export default defineApp({ modules: [], plugins: [clipboard] });
```

화면과 앱 백엔드는 같은 패키지에서 `clipboard`를 가져옵니다.

```ts
import clipboard from "@bunaway/plugin-clipboard";

await clipboard.writeText({ text: "안녕하세요 😀" });
const text = await clipboard.readText(null);
await clipboard.clear(null);
```

## 입력과 결과

| 함수 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| `clipboard.readText` | `null` | `Promise<string \| null>` | `clipboard.readText` |
| `clipboard.writeText` | `{ text: string }` | `Promise<null>` | `clipboard.writeText` |
| `clipboard.clear` | `null` | `Promise<null>` | `clipboard.clear` |
| `clipboard.readImage` | `null` | `Promise<{ width, height, rgba } \| null>` | `clipboard.readImage` |
| `clipboard.writeImage` | `{ width, height, rgba }` | `Promise<null>` | `clipboard.writeImage` |
| `clipboard.getFormats` | `null` | `Promise<format[]>` | `clipboard.getFormats` |
| `clipboard.hasFormat` | `{ format }` | `Promise<boolean>` | `clipboard.hasFormat` |
| `clipboard.readFormats` | `{ formats: format[] }` | `Promise<Array<{ format, data }>>` | `clipboard.readFormats` |
| `clipboard.writeFormats` | `{ items: Array<{ format, data }> }` | `Promise<null>` | `clipboard.writeFormats` |
| `clipboard.waitForChange` | `null` | `Promise<{ sequence, changedAt }>` | `clipboard.waitForChange` |

빈 클립보드나 지원하는 텍스트 형식이 없는 클립보드는 `null`입니다. 텍스트 형식이 있고 내용만 비어 있으면 `""`입니다. Windows가 일반 텍스트를 Unicode 텍스트로 변환해 제공하는 경우도 읽습니다. macOS는 `public.utf8-plain-text`를 읽고 씁니다.

읽기와 쓰기의 텍스트는 Unicode 문자 16,384개까지입니다. 이모지 등 보조 평면 문자는 하나로 셉니다. NUL과 짝이 맞지 않는 UTF-16 surrogate는 거부합니다. 줄바꿈, 한글과 이모지는 변환 없이 보존합니다. Windows의 외부 텍스트 메모리 블록은 종료 NUL을 포함해 최대 65,538바이트입니다. macOS의 UTF-8 텍스트와 HTML은 최대 65,536바이트이며 RTF는 최대 16,384바이트입니다. 더 큰 데이터나 잘못된 텍스트는 읽기에 실패합니다. 긴 내용을 잘라 반환하지 않습니다.

쓰기는 기존의 모든 클립보드 형식을 텍스트로 교체합니다. `clear`는 이미지와 사용자 정의 형식까지 모두 지웁니다. 두 작업의 성공 결과는 `null`입니다. 텍스트 쓰기 권한으로 지우기나 읽기를 허용하지 않습니다.

## 이미지

`width`와 `height`는 각각 1부터 4,096까지의 정수입니다. `rgba`는 행을 위에서 아래로 나열하고 padding 없이 이어 붙인 RGBA 8-bit 픽셀의 canonical base64 문자열입니다. 한 픽셀은 빨강, 초록, 파랑, alpha 순서의 4바이트이며 premultiplied alpha를 사용하지 않습니다. 디코딩한 길이는 `width * height * 4`와 같아야 하고 524,288바이트까지 허용합니다. 예를 들어 512×256 이미지는 상한에 해당합니다. 빈 이미지나 padding bit가 잘못된 base64를 거부합니다.

```ts
await clipboard.writeImage({ width: 1, height: 1, rgba: "/wAAgA==" });
const image = await clipboard.readImage(null);
if (image) console.log(image.width, image.height, image.rgba);
```

Windows 쓰기에는 sRGB `CF_DIBV5`와 명시적인 BGRA/alpha mask를 사용합니다. 읽기는 `CF_DIBV5`를 우선하고 없으면 `CF_DIB`를 사용합니다. 24/32-bit `BI_RGB`, 또는 표준 BGRA mask의 32-bit `BI_BITFIELDS`를 지원합니다. Legacy `BI_RGB`의 사용하지 않는 네 번째 바이트는 alpha가 아니며 불투명 픽셀로 반환합니다. 다른 compression, mask, color profile 또는 지원 크기를 벗어난 외부 이미지는 `INTERNAL`입니다. 지원 bitmap 형식이 없으면 `null`입니다. PNG, JPEG, 파일 경로와 data URL은 이 API의 입력이 아닙니다.

이미지 값은 복사된 JSON 데이터입니다. 네이티브 이미지 리소스 ID를 발급하지 않으며 별도 release 호출이 필요하지 않습니다. 읽은 HGLOBAL을 빌리거나 앱 종료 뒤 네이티브 픽셀 포인터를 보관하지 않습니다.

## 다중 형식과 발견

`format`은 다음 기본 형식 또는 아래의 사용자 정의 binary 식별자입니다. 각 `data`는 해당 형식의 값이며 잘못된 조합과 모르는 형식은 거부합니다.

| `format` | `data` | Windows 형식 (macOS 형식) |
| --- | --- | --- |
| `text/plain` | Unicode 문자열 | `CF_UNICODETEXT` |
| `text/html` | HTML fragment 문자열 | 등록 이름 `HTML Format` |
| `text/rtf` | `{\rtf1` 등으로 시작하는 ASCII RTF 문자열 | 등록 이름 `Rich Text Format` |
| `application/x-bunaway-file-list` | 절대 경로의 문자열 배열. Windows는 Windows 경로, macOS는 POSIX 경로 | wide `CF_HDROP` (`public.file-url`) |
| `image/bmp` | `{ width, height, rgba }` 이미지 값 | `CF_DIBV5` 또는 `CF_DIB` (`public.tiff`) |
| `application/x-bunaway-bookmark` | `{ url: string }` | 등록 이름 `UniformResourceLocatorW` |
| `application/x-bunaway-binary/<name>` | canonical base64 문자열 | 식별자와 같은 등록 이름 |

`image/bmp`는 기존 bitmap 작업 식별자이며 `data`는 BMP 파일 bytes가 아닌 위 RGBA 값입니다. `getFormats`는 여섯 기본 형식 중 현재 읽을 수 있는 형식을 반환합니다. Windows가 변환해 제공할 수 있는 형식도 포함하며 임의의 등록 이름이나 모든 Windows 형식을 열거하지 않습니다. 사용자 정의 binary 형식은 이름을 지정해 `hasFormat`과 `readFormats`로 조회합니다. 가용성은 데이터가 크기와 codec 제한을 통과한다는 보장이 아닙니다.

```ts
await clipboard.writeFormats({ items: [
  { format: "text/plain", data: "안녕하세요" },
  { format: "text/html", data: "<strong>안녕하세요</strong>" }
] });
const formats = await clipboard.getFormats(null);
const hasHTML = await clipboard.hasFormat({ format: "text/html" });
const items = await clipboard.readFormats({ formats: ["text/plain", "text/html"] });
```

한 번에 1부터 5개의 서로 다른 형식을 요청합니다. `readFormats`는 요청 순서대로 결과를 반환하고 없는 형식의 `data`는 `null`입니다. 한 번의 clipboard 열기 구간에서 모든 결과를 복사하며 지원하지 않는 외부 데이터를 발견하면 전체 호출이 `INTERNAL`로 실패합니다. `writeFormats`는 기존의 모든 형식을 지정한 값으로 교체합니다. 텍스트와 이미지의 전용 쓰기도 기존 형식을 모두 교체합니다. 반환 데이터와 쓰기 입력의 JSON UTF-8 크기는 각각 900,000바이트까지로 제한해 공통 프로토콜 envelope의 공간을 남깁니다.

HTML은 전체 문서가 아닌 fragment를 받습니다. CF_HTML의 fragment byte offset과 UTF-8을 검사하지만 HTML을 정제하거나 실행하지 않습니다. 표시할 때의 처리 방식은 앱이 결정합니다. RTF도 markup을 해석하지 않으며 Unicode 문자는 `\u` 등의 RTF escape로 전달합니다. HTML과 RTF의 문자열 상한과 Unicode 검사는 일반 텍스트와 같습니다. ASCII 제한은 RTF에만 적용합니다.

파일 목록은 최대 64개이며 각 경로는 읽기와 쓰기 모두 UTF-16 code unit 1,024개까지입니다. 이모지 등 보조 평면 문자는 두 단위로 셉니다. Windows는 `C:\folder\file.txt` 또는 `\\server\share\file.txt` 형식의 절대 경로만 받으며 NUL, control character, wildcard와 device 경로는 거부합니다. 경로를 읽거나 복사해도 실제 파일을 열거나 존재 여부를 확인하지 않습니다. 파일 접근 권한은 기존 저장소 정책으로 별도로 허용해야 합니다.

## Windows URL bookmark와 사용자 정의 binary 형식

`application/x-bunaway-bookmark`의 `data`는 `{ url }`입니다. `url`은 공백과 control character가 없는 절대 HTTP 또는 HTTPS URL이며 UTF-16 code unit 2,048개까지 허용합니다. HTTP(S) 스킴은 대소문자와 무관하게 검사하며 URL 문자열은 정규화하지 않고 보존합니다. Windows의 `UniformResourceLocatorW`에는 제목이 없으므로 `title`을 받거나 반환하지 않습니다. 파일 접근 bookmark나 URL 열기 권한을 부여하지 않습니다. 일반 텍스트 붙여넣기도 필요하면 같은 `writeFormats` 호출에 `text/plain`을 함께 지정합니다.

```ts
await clipboard.writeFormats({ items: [
  { format: "application/x-bunaway-bookmark", data: { url: "https://example.com/" } },
  { format: "text/plain", data: "https://example.com/" },
  { format: "application/x-bunaway-binary/memo.v1", data: "AP+A/w==" }
] });
const items = await clipboard.readFormats({ formats: [
  "application/x-bunaway-bookmark", "application/x-bunaway-binary/memo.v1"
] });
```

사용자 정의 형식은 `application/x-bunaway-binary/<name>`만 허용합니다. `<name>`은 소문자 ASCII 글자로 시작하고 소문자 글자, 숫자, 점, 밑줄과 하이픈으로 이루어진 1부터 64자 이름입니다. native 등록 이름은 전체 식별자와 같습니다. 다른 Windows 등록 이름이나 native handle 형식을 지정할 수 없습니다. Windows의 등록 이름은 대소문자를 구분하지 않으므로 이 계약은 소문자로 고정합니다.

`data`는 canonical base64이며 디코딩한 bytes는 262,144바이트까지 허용합니다. 빈 문자열은 빈 bytes이고 없는 형식은 `null`입니다. NUL과 임의의 byte 값은 보존하며 잘못된 padding bit, 비정규 base64와 상한 초과를 거부합니다. 기존 호출당 다섯 항목 상한과 JSON 예산도 적용합니다. 이 데이터는 불투명한 값이며 플러그인이 해석하거나 실행하지 않습니다.

Windows 메모리에는 ASCII `BUNBIN01` 8바이트, little-endian unsigned 32-bit payload 길이와 payload bytes를 기록합니다. 다른 앱도 같은 이름과 이 표현을 사용해야 합니다. 읽을 때 header, 버전, 길이와 payload 상한을 검사합니다. 외부 메모리 블록은 기존 형식과 같은 540,796바이트까지 허용하며 payload 뒤의 allocator padding은 반환하지 않습니다. framing 없는 외부 bytes는 `INTERNAL`입니다.

어댑터 수명마다 서로 다른 사용자 정의 이름을 최대 64개 등록합니다. `hasFormat`과 `readFormats`도 native 이름 확인을 위해 등록할 수 있습니다. 상한에 도달하면 새 이름 요청은 `BUSY`로 실패하며 쓰기는 기존 내용을 지우기 전에 실패합니다. 이미 등록한 이름과 기본 형식은 계속 사용할 수 있습니다. Windows는 등록 이름을 해제하는 API를 제공하지 않으며 앱 종료 뒤에도 클립보드 데이터를 소유합니다.

## 변경 이벤트 (Windows)

Windows는 `clipboard.changed` 이벤트와 `clipboard.waitForChange` 함수로 클립보드가 바뀐 사실을 알립니다. payload는 `{ sequence, changedAt }`입니다. `sequence`는 `GetClipboardSequenceNumber`의 값으로 0부터 4,294,967,295까지의 정수이며 이 값이 한 바퀴 돌 수 있습니다. `changedAt`은 변경을 관찰한 시각이며 Unix epoch 밀리초입니다. 클립보드 내용, 형식 이름과 변경한 프로그램의 정보는 담지 않습니다. 내용이 필요하면 앱이 `readText` 등을 권한과 함께 호출합니다.

받으려는 뷰의 events에 `clipboard.changed`를 허용하고 구독해야 합니다. 구독 전이나 연결이 없는 동안의 변경은 저장하거나 재생하지 않습니다. 창이 없는 앱의 백엔드는 `await clipboard.waitForChange(null)`로 다음 변경을 받습니다. 현재 대기자에게만 전달하며 대기는 최대 16개이고 초과하면 `BUSY`입니다. 호출 취소, 컨텍스트 폐기와 앱 종료는 `CANCELLED`로 끝냅니다. 백엔드에는 `clipboard.waitForChange` 권한이 필요하며 대기는 앱 실행 유지 조건을 바꾸지 않습니다.

```ts
const change = await clipboard.waitForChange(null);
const text = await clipboard.readText(null);
```

- 연속한 변경: 발행 전에 쌓인 갱신 메시지는 같은 `sequence`를 읽으므로 하나로 합칩니다. 짧은 간격의 변경은 하나의 알림이 될 수 있어 알림 수가 변경 횟수와 같다고 가정하면 안 됩니다. 알림을 받은 뒤 현재 내용을 읽으십시오.
- 알 수 없는 sequence: Windows가 `GetClipboardSequenceNumber`로 0을 반환하면(창 스테이션의 클립보드 접근 권한이 없는 경우) 변경 식별 값을 알 수 없다고 보고 합치지 않습니다. 이때는 갱신마다 `sequence: 0`으로 알립니다.
- 자기 쓰기: 이 플러그인의 `writeText`, `writeFormats`, `writeImage`와 `clear`도 다른 프로그램의 변경과 같은 알림을 냅니다. 구분하는 값은 제공하지 않습니다. 알림을 받고 곧바로 클립보드에 쓰는 앱은 자기 쓰기가 다시 알림을 만들어 무한히 반복할 수 있습니다. 읽은 내용이 이미 원하는 값이면 쓰지 않도록 내용을 비교하거나, 쓰기 직후 받은 알림 한 번을 무시하는 상태를 앱이 직접 관리하십시오.
- 수명: 어댑터를 만들 때 숨은 창을 `AddClipboardFormatListener`로 등록하고, 종료할 때 `RemoveClipboardFormatListener`와 창 파괴를 수행해 대기를 `CANCELLED`로 끝냅니다. 등록에 실패하면 다른 작업은 계속 쓸 수 있고 `waitForChange`는 `INTERNAL`이며 이벤트는 발행하지 않습니다. 원인은 호스트 진단용 `cause`에만 보존하고 호출자에게 전달하는 오류에는 포함하지 않습니다.
- macOS: `waitForChange`는 `UNSUPPORTED`이며 `clipboard.changed`를 발행하지 않습니다.

## 정책과 취소

화면에서 직접 호출하려면 뷰의 명령과 Host 권한을 각각 허용합니다.

```json
{
  "commands": ["plugin.clipboard.readText", "plugin.clipboard.writeText", "plugin.clipboard.clear"],
  "host": { "permissions": ["clipboard.readText", "clipboard.writeText", "clipboard.clear"] }
}
```

백엔드 명령은 호출한 뷰의 권한을 유지합니다. setup에서 호출할 때는 루트 `backend.permissions`에 필요한 권한을 지정합니다. 설치나 등록으로 권한을 부여하지 않으며 리소스 범위는 받지 않습니다. 각 권한은 데스크톱 전체 클립보드에 적용됩니다.

화면 함수의 마지막 인자는 선택적인 `NativeInvokeOptions`입니다. `signal`로 취소하고 `deadline`으로 Unix epoch 밀리초의 절대 기한을 지정합니다. 백엔드는 현재 명령의 취소와 기한을 이어받고 별도 옵션을 받지 않습니다. 자세한 규칙은 [invoke](/reference/client/invoke/)를 따릅니다.

Windows에서 다른 프로그램이 클립보드를 점유하면 10ms 간격으로 재시도합니다. 250ms가 지난 뒤에도 열 수 없으면 `BUSY`입니다. 대기 중 취소, 호출 컨텍스트 폐기나 앱 종료는 남은 재시도를 중단합니다. OS 호출 자체는 동기 실행이므로 이미 시작한 읽기나 변경을 중단하거나 완료한 변경을 되돌리지 않습니다. 외부 프로그램의 지연 렌더링 때문에 OS 호출이 오래 걸릴 수 있습니다.

## macOS 형식과 제한

macOS는 텍스트, HTML, RTF, 파일 목록과 RGBA 이미지 작업을 UI 메인 스레드에서 실행합니다.
HTML과 ASCII RTF는 각각 `public.html`과 `public.rtf`를 사용합니다. HTML은
CF_HTML header가 없는 UTF-8 markup이며 정제하거나 실행하지 않습니다.
기존 `image/bmp` 작업의 `data`는 같은 RGBA JSON 값이고 실제 클립보드 형식은
`public.tiff`입니다. 부호 없는 8-bit RGB 또는 unassociated RGBA, top-left orientation,
단일 strip의 비압축 TIFF만 읽습니다. 출력도 같은 RGBA TIFF이며 투명 픽셀의 RGB를
보존합니다. 압축, 다중 페이지, planar, 회전된 orientation, ICC profile과 다른
pixel layout은 `INTERNAL`입니다. 외부 TIFF는 528,384바이트까지이며 픽셀 제한은
공통 계약의 524,288바이트입니다. `SampleFormat`이 없으면 unsigned integer로 읽습니다.
있으면 RGB는 3개, RGBA는 4개의 값이 모두 `1`이어야 합니다. signed, floating-point,
undefined sample과 잘못된 개수는 `INTERNAL`입니다. 다른 앱에서 만든 모든 TIFF의 지원을 뜻하지 않습니다.

macOS의 파일 목록은 `/`로 시작하는 절대 POSIX 경로의 배열입니다. 개수와 길이 한도는 Windows와 같고
NUL과 control character, 루트가 아닌 경로의 끝 `/`는 거부하며 `file://` URL이나 Windows 경로는 `INVALID_ARGUMENT`입니다.
경로는 정규화하거나 존재를 확인하지 않습니다. 쓰기는 파일마다 `public.file-url`을 가진
`NSPasteboardItem` 하나를 만들고, 같은 호출의 다른 형식은 첫 항목에 함께 둡니다. 읽기는
모든 항목의 `public.file-url`에서 로컬 `file:` URL만 경로로 바꿉니다. 디렉터리 URL의 끝 `/`는
경로에서 제외합니다. 원격 host의 URL과 파일 참조 URL(`/.file/id=`)은 건너뛰고, 남은 경로가 없으면
`null`입니다. 형식이 잘못된 URL, 64개를 넘는 파일, 한도를 넘거나 control character가 있는 경로는
`INTERNAL`입니다. `getFormats`와 `hasFormat`은 첫 항목에 `public.file-url`이 있는지로 판단하므로,
참조 URL만 있는 클립보드는 `true`이지만 읽으면 `null`일 수 있고, `public.file-url`이 둘째 이후 항목에만 있으면 `false`이지만 읽으면 경로를 돌려줍니다. 파일 목록을 복사하거나 읽어도
파일 접근 권한은 늘지 않습니다.

macOS에서 bookmark 또는 사용자 정의 binary 형식을 포함한 쓰기는 기존 내용을 지우기 전에
`UNSUPPORTED`로 실패합니다. 발견 목록에는 포함하지 않고 `hasFormat`은 `false`,
`readFormats`의 해당 결과는 `null`입니다.

macOS 쓰기는 모든 형식을 `NSPasteboardItem`에 준비한 뒤 기존 내용을
교체합니다. 준비 실패는 기존 내용을 보존하고 교체 실패는 `INTERNAL`이며 롤백하지
않습니다. 동기 OS 호출이 시작한 뒤의 취소는 완료한 변경을 되돌리지 않습니다.
읽은 데이터는 복사해서 반환하고 native 포인터를 보관하지 않습니다. 다중 형식 읽기 중 다른 프로그램이 내용을 바꾸면 `BUSY`로 실패하며 서로 다른 시점의 데이터를 섞어 반환하지 않습니다.
실제 macOS arm64 CI의 실행 근거와 검증 범위는
[플러그인 README](https://github.com/mathbook3948/bunaway/tree/main/plugins/clipboard)를 참고하세요.

## 오류

| 오류 | 의미 |
| --- | --- |
| `INVALID_ARGUMENT` | 잘못된 입력 형식, 길이와 JSON 예산 초과, 잘못된 RGBA/base64, binary 이름, URL, 경로, RTF 또는 Unicode 텍스트 |
| `PERMISSION_DENIED` | 호출 출처에 해당 작업 권한이 없음 |
| `UNSUPPORTED` | 등록하지 않은 작업이거나 플랫폼 어댑터가 없음 |
| `BUSY` | Windows 클립보드를 정해진 시간 동안 열지 못하거나 사용자 정의 이름 등록 상한에 도달하거나 macOS 다중 형식 읽기 중 내용이 변경됨 |
| `INTERNAL` | 외부 데이터가 크기, JSON 예산 또는 codec 제한을 벗어나거나 네이티브 메모리, 클립보드 작업이 실패함 |
| `CANCELLED`, `TIMEOUT` | 취소되거나 호출 기한을 넘김 |

메모리 준비에 실패하면 기존 내용은 유지합니다. Windows가 기존 내용을 비운 다음 등록에 실패하면 `INTERNAL`이고 이전 내용은 복원하지 않습니다. 다중 형식 쓰기에서 일부 등록에 실패하면 성공한 형식은 남을 수 있습니다. 미등록 핸들은 해제하고 이미 Windows에 이전한 핸들은 다시 해제하지 않습니다. 자세한 소유권과 실제 Windows 검증은 [플러그인 README](https://github.com/mathbook3948/bunaway/tree/main/plugins/clipboard)를 참고하세요.
