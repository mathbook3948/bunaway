기본 export(`default`)를 `tray`로 가져와 앱에 등록하고 호출합니다.

`@bunaway/plugin-tray`를 설치하고 앱의 `plugins`에 `tray`를 등록합니다.
Windows와 macOS에서 제공합니다. macOS는 아래 [macOS 메뉴 막대 아이콘](#macos-메뉴-막대-아이콘)을 따르고, 이 문단 이후의 설명은 따로 적지 않으면 Windows 기준입니다. Windows에서 등록한 플러그인이 앱 정의의 `desktop.tray` 설정으로 아이콘을 만들고 `tray`로 제어합니다.
이 API는 트레이나 앱 창을 새로 만들거나 제거하지 않으며 기존 실행 유지와 종료 규칙을 따릅니다.

```ts
import tray from "@bunaway/plugin-tray";

await tray.setTooltip({ tooltip: "백그라운드에서 실행 중" });
await tray.setClickBehavior({ showOnLeftClick: false, menuOnRightClick: true });
const snapshot = await tray.get(null);
const input = await tray.waitForEvent(null);
```

## 입력과 결과

| 함수 | 입력 | 결과 |
| --- | --- | --- |
| `tray.get` | `null` | snapshot 또는 설정된 트레이가 없으면 `null` |
| `tray.getBounds` | `null` | 물리 화면 좌표의 `{ x, y, width, height }` 또는 `null` |
| `tray.setTooltip` | `{ tooltip: string }` | `null` |
| `tray.setIcon` | `{ ico: string \| null }` | `null` |
| `tray.setClickBehavior` | `{ showOnLeftClick, menuOnRightClick }` | `null` |
| `tray.setVisible` | `{ visible: boolean }` | `null` |
| `tray.focus` | `null` | OS가 요청을 수락하면 `true`, 거절하면 `false` |
| `tray.popUpContextMenu` | `{ position?: { x, y } }` | 메뉴가 닫히면 `null` |
| `tray.waitForEvent` | `null` | 다음 입력 payload |

모든 결과는 Promise입니다. snapshot은 `{ id: "main", tooltip, icon, showOnLeftClick,
menuOnRightClick, visible }`입니다. icon은 앱 아이콘이면 `"app"`, 실행 중 지정한 ICO이면 `"custom"`입니다.
이미지 bytes나 내부 HWND를 반환하지 않습니다. snapshot은 OS 설정이나 작업 표시줄에 보이는지를
판정하지 않으며 앱이 선택한 설정을 나타냅니다. shell의 bounds를 얻을 수 없으면 null입니다.

tooltip은 빈 문자열을 허용하며 최대 127 UTF-16 코드 단위입니다. 이모지는 일반적으로 두 단위를
사용합니다. NUL과 잘못된 surrogate는 거부합니다. 실행 중 setter는 길이를 잘라 적용하지 않습니다.
시작 설정도 NUL과 잘못된 surrogate를 native 자원 생성 전에 거부합니다.
native 길이 보정에서는 surrogate를 나누지 않습니다.

ico는 canonical base64로 인코딩한 ICO 파일 bytes입니다. 파일 경로와 URL을 받지 않습니다.
전체 파일은 최대 65,536 bytes, 프레임은 최대 32개입니다. ICO 안의 PNG 또는 40-byte
BITMAPINFOHEADER와 uncompressed DIB 프레임을 받습니다. DIB는 1, 4, 8, 16, 24, 32 bits와
완전한 색상 데이터 및 AND mask를 요구합니다. 프레임 크기는 최대 256×256이며 디렉터리와
내부 이미지 크기가 같아야 합니다. 사용하지 않는 프레임도 모두 검사하므로 선택되지 않는 프레임이
깨진 ICO도 거부합니다. 가장 큰 해상도(너비와 높이 중 큰 값)의 프레임을 사용하고, 같은 크기의
프레임이 여럿이면 비트 깊이가 높은 프레임을, 그래도 같으면 먼저 나온 프레임을 사용합니다.
Windows가 지원하지 않는 이미지는 거부합니다. `ico: null`은 앱 아이콘으로 복원합니다. 바뀐 이미지는 Explorer 복구 재등록에도 유지합니다.

## 표시와 숨김

`tray.setVisible({ visible: false })`는 아이콘을 작업 표시줄 알림 영역에서 숨기고 `true`는 다시 표시합니다.
Windows의 `NIS_HIDDEN` 상태를 사용하므로 아이콘 등록, tooltip, 아이콘 이미지와 메뉴 연결은 그대로 유지되고,
같은 값을 다시 지정해도 오류가 아닙니다. 숨긴 동안에도 `setTooltip`과 `setIcon`은 적용되며 다시 표시하면 반영되어 있습니다.
Explorer가 다시 시작해도 숨김 상태를 유지합니다. 현재 값은 snapshot의 `visible`로 읽으며, 앱이 마지막에 지정한 값입니다.
시작 기본값은 `true`입니다.

숨긴 아이콘에는 shell이 마우스 알림을 보내지 않으므로 `tray.input`과 `tray.hover`가 발생하지 않고, `getBounds`는 `null`,
`focus`는 `false`입니다. 트레이를 제거하는 동작이 아니므로 앱의 실행 유지와 종료 규칙은 바뀌지 않습니다.
숨기는 순간 포인터가 아이콘 위에 있었다면 bounds를 읽을 수 없어 `tray.hover`의 leave는 마우스 이동이 멈춘 뒤 기존 대체 규칙의 지연 뒤에 전달됩니다.
연결한 메뉴는 숨긴 동안에도 `popUpContextMenu`로 표시할 수 있습니다.
Windows 11은 사용자가 설정에서 아이콘을 숨길 수 있어, `visible: true`가 화면 표시를 보장하지는 않습니다.
shell이 상태 변경을 거부하면 `INTERNAL`이며 이전 값을 유지합니다.

## 클릭 동작과 입력

두 click behavior의 시작 기본값은 true입니다. showOnLeftClick은 왼쪽 release와 double-click에서
기존 창 복원을 요청하는지를 정합니다. menuOnRightClick은 오른쪽 release와 context-menu
알림에서 메뉴를 여는지를 정합니다. 메뉴 내용은 [menu](/reference/plugins/menu/) API로 관리합니다.
동작을 꺼도 입력 알림은 계속 전달합니다. Quit과 `beforeQuit`, 창 없는 실행 유지 조건을 바꾸지 않습니다.

`tray.input`의 payload는 `{ id: "main", button, state, position }`입니다.
button은 left, right, middle, none이며 state는 down, up, double-click, context-menu입니다.
keyboard에서도 발생할 수 있는 context-menu는 button none으로 구분합니다.
position은 알림 처리 시 관측한 물리 포인터 좌표 `{ x, y }`이고 조회 실패는 null입니다.
double-click은 두 번째 down 메시지를 나타내며 down과 up 알림이 함께 올 수 있습니다.
연결한 뷰의 events에 tray.input을 허용하고 구독해야 화면에 전달합니다.

## 지정 위치 팝업

`tray.popUpContextMenu`는 `menu.setTrayMenu`로 연결한 메뉴를 앱이 정한 위치에 표시합니다
(Electron `tray.popUpContextMenu`에 대응). 오른쪽 클릭 팝업과 같은 메뉴, 같은 선택 경로를 씁니다.

```ts
const popup = new AbortController();
const shown = tray.popUpContextMenu({ position: { x: 320, y: 200 } }, { signal: popup.signal });
// 다른 작업이나 이벤트에서 닫기
popup.abort();
await shown.catch(() => {});
```

- `position`은 화면 전체 기준의 물리 픽셀 좌표이며 `menu.showContextMenu`의 `x`, `y`와 같습니다.
  음수 좌표도 허용하고, 생략하면 호출 시점의 포인터 위치를 씁니다. 화면 밖 좌표는 OS가 보정합니다.
- 선택은 오른쪽 클릭 팝업과 같이 `menu.clicked`(`source: "tray"`, `windowId: null`)로 전달합니다.
  이 함수의 결과는 선택한 항목을 담지 않으며, 선택하거나 Esc나 바깥 클릭으로 닫으면 `null`입니다.
- 닫기는 호출의 AbortSignal 취소입니다. 별도 close 작업은 없습니다. 팝업을 기다리는 동안 같은
  UI 스레드의 일반 작업은 네이티브 메뉴 루프가 끝날 때까지 대기하므로, 대기 중인 close 요청은
  처리할 수 없기 때문입니다. 취소, 컨텍스트 폐기와 앱 종료는 팝업을 닫고 `CANCELLED`로 끝나며
  `menu.clicked`를 보내지 않습니다.
- 연결한 메뉴가 없으면 `INVALID_ARGUMENT`입니다. `setTrayMenu(null)`로 메뉴를 숨긴 상태와
  호스트 기본 Open/Quit 메뉴를 쓰는 상태도 연결한 메뉴가 없는 경우입니다.
  `setClickBehavior`의 `menuOnRightClick`은 이 호출에 영향을 주지 않습니다.
- 팝업이 이미 열려 있으면 `BUSY`이며 중첩하지 않습니다. 팝업 중 오른쪽 클릭은 무시합니다.
- 앱이 foreground가 아니어도 호출할 수 있으며, 트레이 메뉴는 role을 거부하므로 선택이 다른 앱에
  입력으로 전달되지 않습니다. OS가 foreground 전환을 거절하면 바깥 클릭으로는 닫히지 않을 수 있으며,
  이때도 Esc나 AbortSignal 취소로 닫습니다.

## 입력 대기와 hover

창 없는 백엔드는 waitForEvent를 사용합니다. 현재 대기자에게만 다음 알림을 전달하고 이전 입력은
재생하지 않습니다. 대기는 최대 16개이며 초과하면 BUSY입니다. 호출 취소, 컨텍스트 폐기와 앱 종료는
CANCELLED로 끝냅니다. setup에서 시작한 장기 대기는 setup을 먼저 반환하고 실패를 관찰해야 합니다.
대기 자체는 앱 실행 유지 조건을 바꾸지 않습니다. waitForEvent는 `tray.input`만 기다리며 hover를 전달하지 않습니다.

### tray.hover

포인터가 아이콘 위에 올라오면 `enter`, 머무는 동안 `move`, 벗어나면 `leave`를 `tray.hover` 이벤트로
전달합니다. payload는 `{ state, position }`이고 state는 enter, move, leave입니다.
position은 이벤트 시점의 물리 포인터 좌표 `{ x, y }`이며 조회 실패는 null입니다.
클릭 계열인 `tray.input`과 분리한 이벤트라서 `tray.input`의 state와 `waitForEvent`는 바뀌지 않습니다.
연결한 뷰의 events에 tray.hover를 허용하고 구독해야 화면에 전달합니다. hover용 대기 함수는 없습니다.
Windows shell은 mouse move 알림만 보내고 벗어남은 알리지 않으므로 다음 규칙으로 판단합니다.

- 첫 mouse move 알림이 `enter`입니다. 이후 알림은 50ms 이상 간격일 때만 `move`로 전달하고 그 사이 알림은 버립니다.
- hover 중에는 100ms마다 포인터 좌표를 `Shell_NotifyIconGetRect`의 아이콘 영역과 비교하고, 영역 밖이면 `leave`를 전달합니다.
- 포인터 좌표를 얻지 못하면 확인할 수 없으므로 벗어난 것으로 처리합니다. `leave`의 position은 null입니다.
- 아이콘 영역을 얻지 못하면(예: 숨은 알림 영역의 아이콘) 포인터 위치를 판정할 수 없습니다. 이때는 최근 200ms 안에
  mouse move 알림이 계속 오는 동안만 hover를 유지하고, 알림이 200ms 넘게 끊기면 `leave`를 전달합니다.
  포인터가 멈춰 있으면 `leave`가 오고 다시 움직일 때 새 `enter`가 옵니다.
- `leave`의 position은 벗어났다고 판단한 시점에 읽은 좌표입니다.

한계: 영역을 읽을 수 있으면 `leave`는 실제로 벗어난 시점보다 최대 약 100ms, 영역이 없으면 마지막 mouse move
알림보다 최대 약 300ms(200ms 유예와 100ms 판단 주기) 늦습니다. 마지막 `move`는 보장하지 않으며
50ms 안의 움직임은 합쳐서 전달하지 않고 버립니다. 영역을 얻지 못하는 아이콘에서는 정지한 포인터를
아이콘 위로 구분하지 못합니다. 트레이 컨텍스트 메뉴 같은 native modal 루프가 도는 동안에는 `leave` 판단이
멈추고, 루프가 끝난 뒤에 판단합니다. 그동안 포인터가 벗어났어도 `leave`는 루프 종료 뒤에 전달합니다.

호스트가 트레이를 해제하면 `leave` 없이 판단을 멈춥니다. 플러그인 종료는 구독만 정리하므로
그 뒤에는 판단이 계속돼도 `tray.hover`를 전달하지 않습니다.

예외 처리는 경로에 따라 다릅니다. `enter`와 `move`는 창 프로시저의 mouse move 알림 안에서 전달하므로
이벤트 전달 중 예외는 다른 트레이 알림 처리와 같은 경로로 전파됩니다. `leave`는 100ms 타이머에서
전달하며 호출자가 없습니다. 이 경로에서 포인터나 영역 조회, 이벤트 전달이 실패하면 오류를 로그로 남기고
`leave` 없이 판단을 멈추며, 다음 mouse move 알림이 새 `enter`로 다시 시작합니다.
판단 타이머는 프로세스 종료를 막지 않습니다.

## 권한, 실패와 정리

각 함수는 같은 이름의 독립 Host 권한을 요구합니다. 화면 직접 호출에는
`plugin.tray.setTooltip` 같은 명령도 허용해야 합니다. 등록이나 설치가 권한을 부여하지 않습니다.
권한은 앱 전체의 설정된 트레이에 적용되므로 대상별 접근 규칙은 앱 명령에서 검사합니다.

잘못된 입력과 지원하지 않는 ICO는 INVALID_ARGUMENT, 권한 없음은 PERMISSION_DENIED입니다.
다른 플랫폼, 미등록 작업이나 설정된 트레이가 없는 앱의 변경, focus 및 popUpContextMenu는 UNSUPPORTED입니다.
native shell 변경 실패는 INTERNAL이며 이전 tooltip과 이미지 설정을 유지합니다.
새 icon 적용 뒤 이전 HICON 정리에 실패해도 INTERNAL일 수 있습니다. 이 경우 새 icon 설정은
이미 적용되어 있고 남은 이전 자원을 종료 정리에서 다시 해제합니다.
완료한 동기 변경을 취소로 되돌리지 않습니다. 대기 기한 초과는 TIMEOUT입니다.

호스트가 custom HICON을 소유하고 교체와 종료 때 해제하며 앱 아이콘은 빌린 핸들로 유지합니다.
플러그인 종료는 입력 구독과 대기자를 정리합니다. 여러 아이콘과 GUID, 초기 독립 이미지 옵션,
생성/제거 API와 제거 뒤 상주 정책, balloon은 후속 작업입니다.

## macOS 메뉴 막대 아이콘

macOS에서는 앱이 `tray.create`로 메뉴 막대 아이콘 하나를 만들고 `tray.destroy`로 제거합니다
(Electron `new Tray`와 `tray.destroy`, Tauri `TrayIconBuilder`에 대응). `desktop.tray` 설정은 macOS에서
계속 지원하지 않으며, 이 아이콘은 앱의 실행 유지와 종료 규칙을 바꾸지 않습니다.

```ts
import tray from "@bunaway/plugin-tray";

await tray.create({ title: "Notes", tooltip: "Notes" });
await tray.setMenu({
  items: [
    { type: "item", id: "open", label: "Open" },
    { type: "separator" },
    { type: "item", id: "quit", label: "Quit" },
  ],
});
const choice = await tray.waitForMenuClick(null); // { id: "open" }
await tray.destroy(null);
```

| 함수 | 입력 | 결과 |
| --- | --- | --- |
| `tray.create` | `{ title?: string, tooltip?: string }` (기본값은 빈 문자열) | `{ id: "main", title, tooltip, hasMenu }` |
| `tray.destroy` | `null` | `null` (이미 없으면 그대로 `null`) |
| `tray.getStatusItem` | `null` | 같은 모양의 값 또는 아이콘이 없으면 `null` |
| `tray.setTitle` | `{ title: string }` | `null` |
| `tray.setTooltip` | `{ tooltip: string }` | `null` |
| `tray.setMenu` | `{ items: MenuItem[] \| null }` | `null` |
| `tray.waitForMenuClick` | `null` | 선택한 항목의 `{ id }` |

- title은 메뉴 막대 단추의 글자로 최대 256 UTF-16 코드 단위입니다. 아이콘 이미지는 아직 지원하지 않아
  title이 비어 있으면 아이콘이 보이지 않습니다. tooltip은 Windows와 같은 규칙(최대 127 단위)입니다.
  둘 다 NUL과 잘못된 surrogate를 거부합니다.
- 메뉴 항목은 `{ type: "item", id, label, enabled? }`(`enabled` 기본값 true)와 `{ type: "separator" }`의 평면 목록이며
  최대 100개입니다. id는 1~128자이고 목록 안에서 유일해야 합니다. label은 1~256 단위입니다.
  `items: null`은 메뉴를 제거합니다. 하위 메뉴, 체크, 단축키와 이미지는 지원하지 않습니다.
- 메뉴가 있으면 아이콘을 누를 때 macOS가 메뉴를 엽니다(Electron과 Tauri의 기본 동작과 같습니다). 선택한 항목의 id는
  `waitForMenuClick`으로 받습니다. 현재 대기자에게만 전달하며 이전 선택은 재생하지 않고, 대기는 최대 16개이고
  초과하면 `BUSY`입니다. 비활성 항목과 구분선은 선택되지 않습니다.
- `setMenu`가 실패하면 이전 메뉴를 그대로 유지합니다. 메뉴를 교체하면 이전 메뉴에서 열려 있던 선택은 새 목록의 id로 해석하지 않고 버립니다.
- 아이콘이 이미 있을 때 `create`는 `BUSY`입니다. 아이콘이 없을 때 `setTitle`, `setTooltip`, `setMenu`,
  `waitForMenuClick`은 `UNSUPPORTED`입니다. 플러그인을 종료하면 아이콘을 제거하고 대기자를 `CANCELLED`로 끝냅니다.
- `getBounds`, `setIcon`, `setClickBehavior`, `setVisible`, `focus`, `popUpContextMenu`, `tray.input`과 `tray.hover`는
  macOS에서 아직 제공하지 않습니다. 이미지, 클릭과 double-click 이벤트, 숨김과 복원은 후속 작업입니다.
- 각 함수는 같은 이름의 독립 Host 권한을 요구합니다. 잘못된 입력은 `INVALID_ARGUMENT`, 권한 없음은 `PERMISSION_DENIED`입니다.

## 이전 앱 정의에서 옮기기

이전에는 desktop.tray 설정만으로 호스트가 아이콘을 만들었습니다. 이제 패키지를 설치하고
같은 app.ts에 `tray`를 등록합니다. 설정과 Open/Quit, 숨김 시작 및 종료 규칙은 유지합니다.
등록이 없으면 시작을 UNSUPPORTED로 거부합니다. 메뉴를 바꾸지 않는 앱에는 menu이 필요 없습니다.

```ts
import { defineApp } from "@bunaway/backend";
import tray from "@bunaway/plugin-tray";

export default defineApp({
  modules: [],
  plugins: [tray],
  desktop: { tray: { tooltip: "Notes" }, closeBehavior: "hide" },
});
```
