기본 export(`default`)를 `os`로 가져와 앱에 등록하고 호출합니다.

`@bunaway/plugin-os`를 설치하고 앱의 `plugins`에 `os`를 등록합니다. Windows와 macOS에서 제공합니다.
화면과 백엔드는 같은 패키지의 `os`를 사용합니다.

```ts
import os from "@bunaway/plugin-os";

const info = await os.info(null);
const locale = await os.locale(null);
```

| 함수 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| `os.info` | `null` | `Promise<OSInfo>` | `os.info` |
| `os.usage` | `null` | `Promise<OSUsage>` | `os.usage` |
| `os.locale` | `null` | `Promise<OSLocale>` | `os.locale` |
| `os.beep` | `OSBeepInput` | `Promise<null>` | `os.beep` |
| `os.listPrinters` | `null` | `Promise<OSPrinter[]>` | `os.listPrinters` |
| `os.getDefaultPrinter` | `null` | `Promise<string \| null>` | `os.getDefaultPrinter` |
| `os.listGpus` | `null` | `Promise<OSGpu[]>` | `os.listGpus` |
| `os.listAppProcesses` | `null` | `Promise<OSAppProcess[]>` | `os.listAppProcesses` |
| `os.getMediaAccessStatus` | `OSMediaAccessInput` | `Promise<OSMediaAccessStatus>` | `os.getMediaAccessStatus` |

`OSInfo`는 `platform: "windows"` 또는 `"macos"`, OS의 `type`, `release`, `version`, 실행 중 프로세스의
`architecture`, `hostname`과 `runtime: { name: "bun", version, pid }`를 반환합니다.
architecture는 하드웨어 종류나 translation 상태를 뜻하지 않습니다. PID는 같은 프로세스의
호스트와 백엔드가 공유합니다. 경로, 환경 변수나 사용자 이름은 포함하지 않습니다.

`OSUsage`는 `pid`, 논리 CPU 개수 `logicalCpuCount`, 현재 프로세스의 누적 CPU 시간
`cpuTime: { userMicros, systemMicros }`, bytes 단위
`memory: { systemTotalBytes, systemFreeBytes, processResidentBytes }`와
`translation: { active, processMachine, nativeMachine }`을 반환합니다. CPU 시간은 백분율이
아니며 같은 프로세스의 모든 Worker를 포함합니다. 메모리는 호출 시점의 snapshot입니다.
translation은 Windows `IsWow64Process2` 결과입니다. `active`는 WOW translation 여부이며
`processMachine`은 translation 중인 machine 값, translation이 없으면 0입니다.
`nativeMachine`은 호스트 machine 값입니다. 두 숫자는 Windows IMAGE_FILE_MACHINE 값이며
프로세스 이름이나 임의 PID의 정보를 조회하지 않습니다. `os.usage`는 독립 권한입니다.

macOS의 `translation`은 `sysctl.proc_translated`로 Rosetta 2 변환 여부를 읽습니다. 변환 중이면
`active`가 `true`, `processMachine`이 x86_64(`0x8664`), `nativeMachine`이 ARM64(`0xaa64`)입니다.
변환하지 않으면 `active`는 `false`, `processMachine`은 0이고 `nativeMachine`은 프로세스 architecture에
해당하는 값(Apple silicon은 `0xaa64`, Intel은 `0x8664`)입니다.

`OSLocale`은 Windows 사용자의 형식 설정인 `locale`, 해당 locale의 ISO 지역 코드인
`countryCode`, 순서가 있는 사용자 표시 언어 목록 `preferredLanguages`와 시스템 기본 UI
언어 `systemLanguage`를 반환합니다. 지역 코드가 없으면 `null`입니다. 현재 위치나 IP 기반
국가를 조회하지 않습니다. 지역 코드는 `US` 같은 두 글자 값 외에 Caribbean의 `029` 같은
세 자리 숫자 문자열일 수 있으며 앞의 0을 보존합니다. 시스템 언어는 Windows의 기본 UI 언어이며 사용자 표시 언어와
다를 수 있습니다. 언어 설정은 호출마다 읽고 결과를 캐시하지 않습니다.

macOS에서는 CoreFoundation의 현재 locale과 선호 언어 목록을 읽습니다. `locale`은 `ko-KR`처럼
하이픈으로 잇는 태그이고, 지역 코드는 그 태그의 지역 부분입니다. macOS에는 선호 언어와 별개인
시스템 UI 언어가 없어 `systemLanguage`는 `preferredLanguages`의 첫 항목입니다.

`os.beep({ kind })`는 Windows `MessageBeep`로 사용자의 사운드 설정에 따른 시스템 소리를 재생합니다.
`kind`는 `"default"`, `"info"`, `"warning"`, `"error"` 중 하나이며 생략하면 `"default"`입니다.
`"default"`는 사운드 구성표의 Windows Default Beep(`MB_OK`)이고 나머지는 각각 정보(`MB_ICONASTERISK`),
경고(`MB_ICONEXCLAMATION`), 오류(`MB_ICONHAND`) 소리입니다.
`os.beep({})`처럼 빈 객체를 전달할 수 있고 다른 필드나 `null`은 `INVALID_ARGUMENT`입니다.
재생을 요청하면 바로 `null`을 반환하며 재생 완료를 기다리지 않습니다. 사용자가 시스템 소리를
끄거나 오디오 장치가 없으면 소리가 나지 않아도 성공할 수 있습니다. `MessageBeep` 호출 자체가 실패하면
`INTERNAL`입니다. 주파수와 길이는 지정할 수 없습니다.

macOS에서는 `kind`와 관계없이 System Settings에서 고른 경고음(`AudioServicesPlayAlertSound`)을 재생합니다.
macOS에는 종류별 시스템 소리가 없으므로 `kind`는 검증만 하고 소리를 바꾸지 않습니다. 재생 요청 뒤
바로 `null`을 반환하며 소리가 났는지는 확인하지 않습니다.

`os.listPrinters(null)`은 이 PC에 설치된 로컬 프린터와 연결한 네트워크 프린터를 `{ name, isDefault }` 배열로
반환합니다. `name`은 Windows가 프린터를 식별하는 이름(연결 프린터는 `\\server\share` 형태)이고 `isDefault`는
사용자의 기본 프린터와 이름이 같은 항목에만 `true`입니다. 이름은 대소문자를 구분하지 않고 비교합니다.
순서는 Windows 열거 순서입니다. 프린터가 없으면 빈 배열입니다. 이름은 1~259자이고 목록은 최대 1024개입니다.
더 많으면 일부만 돌려주지 않고 `INTERNAL`입니다. 서버 이름, 드라이버, 포트, 위치, 상태는 반환하지 않으며
프린트 서버에 연결해 상세 정보를 읽지 않습니다. Windows `EnumPrintersW`(level 4)를 사용합니다.

`os.getDefaultPrinter(null)`은 기본 프린터 이름이거나, 기본 프린터가 없으면 `null`입니다(Windows `GetDefaultPrinterW`).
`os.getDefaultPrinter`는 기본 프린터 조회가 실패하면 `INTERNAL`입니다. `os.listPrinters`는 열거와 기본 프린터 조회가
둘 다 성공해야 하며, 어느 쪽이 실패해도(인쇄 스풀러 중지, 이름이 259자를 넘는 프린터 등) 목록 전체가 `INTERNAL`입니다.
프린터 이름은 사용자 환경 정보이므로 `os.listPrinters`와 `os.getDefaultPrinter`는 각각 독립 권한입니다.
macOS에서는 두 작업 모두 `UNSUPPORTED`입니다.

`os.listGpus(null)`은 Windows DXGI(`CreateDXGIFactory1`, `IDXGIFactory1::EnumAdapters1`, `IDXGIAdapter1::GetDesc1`)가 열거하는
그래픽 어댑터를 `{ name, vendorId, deviceId, dedicatedVideoMemoryBytes, software }` 배열로 반환합니다.
`name`은 어댑터 설명 문자열(최대 127자), `vendorId`와 `deviceId`는 DXGI가 보고하는 PCI ID(NVIDIA는 `0x10de`),
`dedicatedVideoMemoryBytes`는 어댑터 전용 비디오 메모리 바이트(시스템 메모리를 공유하는 어댑터는 0),
`software`는 Microsoft Basic Render Driver 같은 소프트웨어 렌더러이면 `true`입니다. 순서는 DXGI 열거 순서이며
호출마다 새로 읽고 캐시하지 않습니다. 어댑터가 없으면 빈 배열입니다. 조회가 실패하거나 어댑터가 16개를 넘으면
일부만 돌려주지 않고 `INTERNAL`입니다. GPU가 없는 환경에서는 소프트웨어 어댑터만 나올 수 있습니다.
드라이버 버전, 렌더러 지표와 hardware acceleration 설정은 반환하거나 바꾸지 않습니다. 하드웨어 식별 정보는
fingerprinting에 쓸 수 있으므로 `os.listGpus`는 독립 권한이며 필요한 뷰만 허용합니다. macOS에서는 `UNSUPPORTED`입니다.

`os.listAppProcesses(null)`은 이 앱이 띄운 프로세스 트리를 `{ pid, parentPid, kind, metrics }` 배열로 반환합니다.
Windows는 호스트와 백엔드를 하나의 Bun 프로세스로 실행하므로 그 프로세스가 `kind: "app"`으로 한 번 나오며 항상 첫 항목입니다.
`kind: "webview2"`는 WebView2 브라우저, 렌더러, GPU, 유틸리티 프로세스와 그 하위 프로세스이고, 앱이 직접 시작한 자식 같은
나머지 하위 프로세스는 `"other"`입니다. 분류는 프로세스 스냅샷의 이미지 이름(`msedgewebview2.exe`)과 부모 관계만 사용하며
경로, 명령줄, 다른 프로세스의 메모리는 읽지 않습니다. `metrics`는 `{ workingSetBytes, cpuTime: { userMicros, systemMicros } }`로
`os.usage`와 같은 단위(누적 CPU 마이크로초)이며, 제한된 조회 권한으로도 열 수 없거나 조회 중에 끝난 프로세스는 목록에 남고 `metrics`가 `null`입니다.
프로세스 목록은 한 시점의 스냅샷이고 지표는 항목마다 이어서 읽으므로 값 사이의 시점은 조금씩 다릅니다. 부모보다 먼저 생성된 자식은 재사용된 프로세스 ID로 보고
제외합니다. 임의 프로세스를 지정하는 입력은 없고, 프로세스가 256개를 넘으면 일부만 돌려주지 않고 `INTERNAL`입니다.
프로세스 구성과 메모리는 앱 내부 정보이므로 `os.listAppProcesses`는 독립 권한입니다. macOS에서는 `UNSUPPORTED`입니다.
GPU 프로세스의 그래픽 메모리, 렌더러 내부 지표와 startup 시간은 반환하지 않습니다.

`os.getMediaAccessStatus({ mediaType })`는 Windows 설정의 개인정보 보호 > 카메라 또는 마이크 접근 상태를 읽기 전용으로 조회합니다.
`mediaType`은 `"camera"`와 `"microphone"`만 받으며 다른 값이나 추가 필드는 `INVALID_ARGUMENT`입니다. 결과는 Electron
`systemPreferences.getMediaAccessStatus`와 같은 값 집합 중 Windows에서 의미가 있는 값입니다.

| 결과 | 의미 |
| --- | --- |
| `granted` | 사용자 설정이 켜져 있음 |
| `denied` | 사용자가 설정을 끔 |
| `restricted` | 기기 정책이 끔(사용자 설정과 무관) |
| `not-determined` | 저장된 사용자 설정이 없음 |
| `unknown` | 레지스트리를 읽지 못했거나 예상 밖의 값 |

값은 `CapabilityAccessManager\ConsentStore\webcam` 또는 `microphone` 키의 `Value`(`Allow`/`Deny`)를 `HKLM`(기기 정책), `HKCU`(사용자 설정)
순서로 읽어 만듭니다. 레지스트리 경로는 상수이고 호출자 입력은 경로에 들어가지 않으며 읽기만 합니다. 값이 없을 때를 `granted`로 가정하지 않습니다.
이 조회는 OS가 앱 전체에 허용하는지만 답합니다. 데스크톱 앱별 항목(`NonPackaged` 하위 키)은 조회하지 않으므로 앱별로
꺼져 있어도 `granted`가 나올 수 있고, 사용자가 설정을 바꾸면 다음 호출부터 반영됩니다. 상태가 `denied`이면 WebView의 `getUserMedia`가
조용히 실패하므로 앱은 먼저 안내 화면을 보여줄 수 있습니다. OS 권한을 요청하는 API는 Windows에 없으므로 `request` 작업은 제공하지 않습니다
(Electron의 `askForMediaAccess`도 macOS 전용). 개인정보 설정 화면을 여는 API는 현재 제공하지 않습니다(`opener.openUrl`은 `http:`와 `https:`만 엽니다). 개인정보 설정은 fingerprinting과 앱 동작 분기에 쓸 수
있으므로 `os.getMediaAccessStatus`는 독립 권한입니다. macOS에서는 `UNSUPPORTED`입니다.

이모지 패널을 여는 API는 제공하지 않습니다. Windows에는 이모지 패널을 여는 공식 API가 없고
Win+. 키 입력을 합성하는 방법만 있어 현재 포커스를 가진 창에 의존하므로 지원하지 않습니다.

화면 직접 호출에는 뷰의 `commands`에 `plugin.os.info`, `plugin.os.usage`, `plugin.os.locale`, `plugin.os.beep`, `plugin.os.listPrinters`, `plugin.os.getDefaultPrinter`, `plugin.os.listGpus`, `plugin.os.listAppProcesses` 또는 `plugin.os.getMediaAccessStatus`를,
`host.permissions`에 같은 작업의 `os.info`, `os.usage`, `os.locale`, `os.beep`, `os.listPrinters`, `os.getDefaultPrinter`, `os.listGpus`, `os.listAppProcesses` 또는 `os.getMediaAccessStatus`를 허용합니다. 백엔드 명령은
호출한 뷰의 권한을 유지하며 setup 호출은 `backend.permissions`를 사용합니다.
각 작업의 권한은 독립적입니다. hostname을 공개해도 되는 뷰만 `os.info`를 허용합니다.

화면 함수의 마지막 인자는 `NativeInvokeOptions`입니다. `signal`과 `deadline`은
[invoke](/reference/client/invoke/)의 규칙을 따릅니다. 이미 시작한 동기 OS 조회를 중단하지는 않습니다.

잘못된 입력은 `INVALID_ARGUMENT`, 권한 거부는 `PERMISSION_DENIED`, 등록하지 않은 작업이나
플랫폼은 `UNSUPPORTED`, OS 조회 실패와 계약 밖 결과는 `INTERNAL`입니다. 종료된 어댑터와
취소는 `CANCELLED`, 호출 기한 초과는 `TIMEOUT`입니다.

신뢰된 백엔드는 단순 런타임 조회에 `node:os`, `process`, `Bun.version`을 직접 사용할 수
있습니다. 이 플러그인은 화면과 앱 명령의 권한 중재 경로 및 Windows 언어 설정 조회를 제공합니다.
