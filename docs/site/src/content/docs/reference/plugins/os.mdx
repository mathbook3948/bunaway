`@bunaway/plugin-os`를 설치하고 앱의 `plugins`에 `osPlugin`을 등록합니다. Windows에서 제공합니다.
화면과 백엔드는 같은 패키지의 `os`를 사용합니다.

```ts
import { os, osPlugin } from "@bunaway/plugin-os";

const info = await os.info(null);
const locale = await os.locale(null);
```

| 함수 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| `os.info` | `null` | `Promise<OSInfo>` | `os.info` |
| `os.usage` | `null` | `Promise<OSUsage>` | `os.usage` |
| `os.locale` | `null` | `Promise<OSLocale>` | `os.locale` |

`OSInfo`는 `platform: "windows"`, OS의 `type`, `release`, `version`, 실행 중 프로세스의
`architecture`, `hostname`과 `runtime: { name: "bun", version, pid }`를 반환합니다.
architecture는 하드웨어 종류나 translation 상태를 뜻하지 않습니다. PID는 같은 프로세스의
호스트와 백엔드가 공유합니다. 경로, 환경 변수나 사용자 이름은 포함하지 않습니다.

`OSUsage`는 `pid`, 논리 CPU 개수 `logicalCpuCount`, 현재 프로세스의 누적 CPU 시간
`cpuTime: { userMicros, systemMicros }`, bytes 단위
`memory: { systemTotalBytes, systemFreeBytes, processResidentBytes }`와
`translation: { active, processMachine, nativeMachine }`을 반환합니다. CPU 시간은 백분율이
아니며 같은 프로세스의 모든 Worker를 포함합니다. 메모리는 호출 시점의 snapshot입니다.
translation은 Windows `IsWow64Process2` 결과입니다. `active`는 WOW translation 여부이며
`processMachine`은 translation 중인 machine 값, translation이 없으면 0입니다.
`nativeMachine`은 호스트 machine 값입니다. 두 숫자는 Windows IMAGE_FILE_MACHINE 값이며
프로세스 이름이나 임의 PID의 정보를 조회하지 않습니다. `os.usage`는 독립 권한입니다.

`OSLocale`은 Windows 사용자의 형식 설정인 `locale`, 해당 locale의 ISO 지역 코드인
`countryCode`, 순서가 있는 사용자 표시 언어 목록 `preferredLanguages`와 시스템 기본 UI
언어 `systemLanguage`를 반환합니다. 지역 코드가 없으면 `null`입니다. 현재 위치나 IP 기반
국가를 조회하지 않습니다. 지역 코드는 `US` 같은 두 글자 값 외에 Caribbean의 `029` 같은
세 자리 숫자 문자열일 수 있으며 앞의 0을 보존합니다. 시스템 언어는 Windows의 기본 UI 언어이며 사용자 표시 언어와
다를 수 있습니다. 언어 설정은 호출마다 읽고 결과를 캐시하지 않습니다.

화면 직접 호출에는 뷰의 `commands`에 `plugin.os.info`, `plugin.os.usage` 또는 `plugin.os.locale`을,
`host.permissions`에 같은 작업의 `os.info`, `os.usage` 또는 `os.locale`을 허용합니다. 백엔드 명령은
호출한 뷰의 권한을 유지하며 setup 호출은 `backend.permissions`를 사용합니다.
각 작업의 권한은 독립적입니다. hostname을 공개해도 되는 뷰만 `os.info`를 허용합니다.

화면 함수의 마지막 인자는 `NativeInvokeOptions`입니다. `signal`과 `deadline`은
[invoke](/reference/client/invoke/)의 규칙을 따릅니다. 이미 시작한 동기 OS 조회를 중단하지는 않습니다.

잘못된 입력은 `INVALID_ARGUMENT`, 권한 거부는 `PERMISSION_DENIED`, 등록하지 않은 작업이나
플랫폼은 `UNSUPPORTED`, OS 조회 실패와 계약 밖 결과는 `INTERNAL`입니다. 종료된 어댑터와
취소는 `CANCELLED`, 호출 기한 초과는 `TIMEOUT`입니다.

신뢰된 백엔드는 단순 런타임 조회에 `node:os`, `process`, `Bun.version`을 직접 사용할 수
있습니다. 이 플러그인은 화면과 앱 명령의 권한 중재 경로 및 Windows 언어 설정 조회를 제공합니다.
