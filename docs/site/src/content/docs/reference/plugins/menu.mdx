기본 export(`default`)를 `menu`로 가져와 앱에 등록하고 호출합니다.

`@bunaway/plugin-menu`를 설치하고 앱의 `plugins`에 `menu`를 등록합니다.
Windows에서 제공합니다. `menu`는 화면과 앱 백엔드가 함께 사용하는 호출 API입니다.
트레이 연결에는 @bunaway/plugin-tray 설치와 tray 등록, 앱 정의의 `desktop.tray`가 필요합니다.
등록 순서는 상관없습니다. menu을 먼저 등록해도 초기화 후 트레이에 연결할 수 있습니다.

```ts
import menu from "@bunaway/plugin-menu";

await menu.create({
  menuId: "tray-menu",
  items: [
    { id: "open", type: "item", label: "열기" },
    { id: "notifications", type: "checkbox", label: "알림", checked: true },
    { id: "separator", type: "separator" },
    { id: "quit", type: "item", label: "종료" },
  ],
});
await menu.setTrayMenu({ menuId: "tray-menu" });
```

사용자 정의 항목은 선택 이벤트만 전달합니다. `open`이나 `quit`이라는 ID에 호스트 동작을
자동으로 연결하지 않습니다. 앱 명령이나 백엔드 서비스에서 창 표시와 종료를 처리합니다.
트레이 왼쪽 클릭의 기존 창 복원과 종료 확인 규칙은 그대로 적용합니다.

## 리소스와 항목

| 함수 | 입력 | 결과 |
| --- | --- | --- |
| `menu.create` | `{ menuId, items }` | 생성한 `{ menuId, items }` |
| `menu.get` | `{ menuId }` | `{ menuId, items }` 또는 없는 ID의 `null` |
| `menu.list` | `null` | 생성 순서의 메뉴 ID 배열 |
| `menu.replace` | `{ menuId, items }` | 교체한 리소스 |
| `menu.remove` | `{ menuId }` | 제거했으면 `true`, 없는 ID이면 `false` |
| `menu.insert` | `{ menuId, parentId?, index, item }` | 변경한 리소스 |
| `menu.removeItem` | `{ menuId, itemId }` | 변경한 리소스 |
| `menu.updateItem` | `{ menuId, itemId, changes }` | 변경한 리소스 |
| `menu.setTrayMenu` | `{ menuId: string \| null }` | `null` |
| `menu.getTrayMenu` | `null` | 연결한 메뉴 ID 또는 `null` |
| `menu.setWindowMenu` | `{ menuId: string \| null }` | `null` |
| `menu.getWindowMenu` | `null` | 연결한 메뉴 ID 또는 `null` |
| `menu.setWindowMenuVisible` | `{ visible: boolean }` | `null` |
| `menu.getWindowMenuVisible` | `null` | `boolean` |
| `menu.setWindowMenuAutoHide` | `{ autoHide: boolean }` | `null` |
| `menu.getWindowMenuAutoHide` | `null` | `boolean` |
| `menu.showContextMenu` | `{ menuId, x, y }` | 선택한 항목 ID 또는 닫았을 때 `null` |
| `menu.waitForClick` | `null` | 다음 `{ menuId, itemId, source, windowId }` |

모든 결과는 Promise입니다. 리소스는 앱 수명에 속하며 창이나 화면 재연결에 종속되지 않습니다.
메뉴 ID는 앱 전체에서, 항목 ID는 한 메뉴의 모든 하위 항목에서 고유합니다.
ID는 영문자, 숫자, `_`, `.`, `-`로 된 1~128자입니다.
리소스는 최대 32개, 각 리소스는 하위 항목을 포함해 최대 256개, 깊이는 최대 8단계입니다.
조회 결과를 수정해도 원래 리소스는 바뀌지 않습니다.

`type`은 `item`, `separator`, `checkbox`, `radio`, `submenu`입니다.
`visible` 기본값은 `true`입니다. separator를 제외한 항목의 `label`은 필수이고
`enabled` 기본값은 `true`입니다. `role`을 지정한 item만 label을 생략할 수 있습니다. label은 1~512 Unicode 코드 포인트이며 `😀`는 하나로 셉니다. NUL, 탭, 줄바꿈과
잘못된 surrogate를 거부합니다. `&`는 문자로 표시하며 mnemonic을 만들지 않습니다.
숨긴 항목은 네이티브 메뉴에서 제외합니다.

checkbox와 radio의 `checked` 기본값은 `false`입니다. radio는 `group`을 지정해야 하며
같은 부모 아래 같은 group에서 checked 항목은 하나만 허용합니다. 다른 유형은 group을
지정할 수 없습니다. 일반 item의 checked는 `false`여야 합니다. submenu는 `items` 배열을
가집니다. 선택은 checked 상태를 자동 변경하지 않습니다.

## 항목 icon

`type: "item"`(role 항목 포함)과 `submenu`는 선택 필드 `icon`을 가질 수 있습니다. 값은 tray의
`setIcon`과 같은 ICO 바이트의 base64 문자열(65,536 bytes 이하)이며 `null`이거나 생략하면 아이콘이 없습니다.
`get` 결과에는 `icon: null`로 채워서 반환합니다. checkbox와 radio는 같은 열에 체크 표시를 그리므로,
separator는 그릴 항목이 없으므로 `icon`을 받지 않고 `INVALID_ARGUMENT`로 거부합니다.

```ts
await menu.create({
  menuId: "main-menu",
  items: [{ id: "save", type: "item", label: "저장", icon: saveIcoBase64 }],
});
await menu.updateItem({ menuId: "main-menu", itemId: "save", changes: { icon: otherIcoBase64 } });
await menu.updateItem({ menuId: "main-menu", itemId: "save", changes: { icon: null } });
```

Windows는 시스템 작은 아이콘 크기(`SM_CXSMICON`, 보통 16px)에 맞는 ICO 프레임을 골라 항목 앞에 그립니다.
크기를 덮는 가장 작은 프레임을 우선하고 없으면 가장 큰 프레임을 줄여 씁니다. 알파 채널이 없는 아이콘은
AND mask로 투명 영역을 정하고 검정 픽셀도 불투명으로 표시합니다. 형식이 틀리거나 Windows가 해석하지 못하는
ICO는 `INVALID_ARGUMENT`, 비트맵 생성 실패는 `INTERNAL`입니다. 트레이 팝업, 창 메뉴바와 컨텍스트 팝업은 각자
네이티브 비트맵을 만들고 메뉴 교체, 항목 제거와 연결 해제 때 함께 해제하므로 같은 icon을 여러 곳에 써도
수명이 겹치지 않습니다. 한 메뉴 안에서 같은 icon 문자열은 비트맵 하나를 공유합니다.

제한 사항입니다. 메뉴바 최상위 항목에는 icon이 표시되지 않으며 하위 메뉴 항목에만 표시됩니다.
아이콘 크기는 메뉴를 만들 때의 `SM_CXSMICON` 기준이라, DPI가 다른 모니터로 옮기면 흐릴 수 있습니다.

## 항목 accelerator 표시

`item`(role 포함), `checkbox`, `radio`는 선택 필드 `accelerator`로 항목 오른쪽에 단축키 문구를 표시할 수 있습니다.
**표시 전용입니다.** 이 값은 단축키를 등록하지 않고 키를 눌러도 `menu.clicked`가 발생하지 않습니다.
Electron과 Tauri는 accelerator를 표시하면서 등록도 하지만, 여기서는 키 입력 처리를 앱이 맡습니다
(`globalShortcut`이나 페이지의 키 처리로 구현한 단축키를 메뉴에 보여 줄 때 사용합니다).

형식은 `Ctrl`, `Alt`, `Shift`, `Win` 수식어를 `+`로 이은 뒤 키 하나입니다. 키는 영문자, 숫자, `F1`~`F24`,
`Backspace`, `Tab`, `Enter`, `Escape`, `Space`, `PageUp`, `PageDown`, `End`, `Home`, `Left`, `Up`, `Right`,
`Down`, `Insert`, `Delete`입니다. 대소문자는 구분하지 않고 `Ctrl+Alt+Shift+Win` 순서의 표기로 정규화하며,
`Control`, `CommandOrControl`, `CmdOrCtrl`은 `Ctrl`, `Super`는 `Win`으로 받습니다. 수식어가 중복되거나
알 수 없는 키, 64자를 넘는 값은 `INVALID_ARGUMENT`입니다. submenu와 separator에는 지정할 수 없습니다.
기본값은 `null`이며 `get` 결과에도 `accelerator: null`로 채웁니다. role 항목은 `accelerator`를 생략하면 role의
기본 문구(`Ctrl+C` 등)를 표시하고, 지정하면 그 값을 대신 표시합니다. 메뉴바 최상위 항목에는 accelerator 열이
없어 표시하지 않습니다. label 길이 상한에는 포함하지 않습니다.

```ts
await menu.updateItem({ menuId: "main-menu", itemId: "save", changes: { accelerator: "CmdOrCtrl+S" } });
await menu.updateItem({ menuId: "main-menu", itemId: "save", changes: { accelerator: null } });
```

## sublabel과 접근성 label

항목에는 보조 문구(`sublabel`)나 접근성 전용 label 필드가 없습니다. 정의되지 않은 필드는 무시되지 않고 `INVALID_ARGUMENT`로 거부됩니다. 보조 정보는
`label`에 포함해 주세요. `accelerator`는 단축키 표시 문자열 전용이므로 보조 문구로 쓰지 마세요.

## 항목 삽입, 제거와 변경

`insert`의 index는 대상 배열의 0부터 길이까지입니다. 0은 prepend, 배열 길이는 append입니다.
`parentId`를 생략하거나 `null`로 지정하면 최상위에 삽입하고, 지정하면 해당 submenu에 삽입합니다.
`removeItem`은 submenu의 하위 항목도 제거합니다. `updateItem.changes`는 `label`, `enabled`,
`visible`, `checked`, `icon`, `accelerator`를 받습니다. separator는 visible만, submenu는 checked와 accelerator를 제외한 변경을 받고,
checkbox와 radio는 `icon: null`을 포함한 모든 icon 변경을 `INVALID_ARGUMENT`로 거부합니다.
`role`은 바꿀 수 없으므로 유형, ID와 role을 바꾸려면 replace를 사용합니다. 변경 후 전체 트리를 검증하며 실패하면 이전 리소스와
트레이 연결을 유지합니다.

## 트레이 연결과 이벤트

시작할 때는 기존 Open/Quit 메뉴입니다. 리소스를 연결하면 다음 우클릭부터 사용자 정의 메뉴를
표시합니다. 연결한 리소스의 변경은 다음 팝업에 반영됩니다. 표시 중인 팝업은 기존 정의를
유지하고 정의가 교체된 뒤의 이전 선택은 이벤트로 전달하지 않습니다.
`setTrayMenu({ menuId: null })` 또는 연결한 리소스 제거는 트레이 메뉴를 표시하지 않게 합니다.
아이콘과 숨긴 HWND는 유지하며 앱 실행 유지 조건도 바꾸지 않습니다.
`getTrayMenu(null)`의 null은 사용자 정의 리소스가 연결되지 않았다는 뜻입니다.
앱 종료 때 리소스를 해제합니다.

`menu.clicked`의 트레이 payload는 `{ menuId, itemId, source: "tray", windowId: null }`입니다.
트레이 팝업에는 소유 앱 창이 없으므로 windowId는 null입니다.
이벤트를 받으려는 뷰에서 `menu.clicked`를 허용하고 구독합니다. 이벤트를 영구 보관하지 않습니다.

연결한 메뉴를 앱이 정한 화면 좌표에 표시하려면 [tray](/reference/plugins/tray/)의
`tray.popUpContextMenu`를 사용합니다. 선택은 우클릭 팝업과 같이 이 payload로 전달합니다.

창이 없는 앱의 백엔드는 `await menu.waitForClick(null)`로 다음 사용자 정의 메뉴 선택을 받습니다.
현재 대기자에게만 전달하며 이전 선택은 재생하지 않습니다. 대기는 최대 16개이고 초과하면 BUSY입니다.
호출 취소, 컨텍스트 폐기와 앱 종료는 대기를 CANCELLED로 끝냅니다. 완료한 대기 결과는 복사본입니다.
백엔드에는 `menu.waitForClick` 권한, 화면 직접 호출에는 해당 명령과 Host 권한이 필요합니다.
대기가 앱 실행 유지 조건을 바꾸지는 않습니다. setup에서 시작한 장기 작업은 setup을 먼저 반환하고 실패를 관찰해야 합니다.

## 창 메뉴바와 컨텍스트 팝업

`setWindowMenu`는 앱의 창에 메뉴바를 연결합니다. `menuId: null`이면
분리합니다. `getWindowMenu`는 창의 연결을 조회합니다. 창 메뉴에는 tray 플러그인이
필요하지 않습니다. 창을 고르는 입력은 없으며 뷰 ID나 HWND를 받지 않습니다.

`setWindowMenuVisible`은 연결한 메뉴바를 숨기거나 다시 표시하고(Electron `setMenuBarVisibility`),
`getWindowMenuVisible`은 현재 값을 돌려줍니다(`isMenuBarVisible`). 기본값은 `true`입니다. 숨겨도
연결과 메뉴 리소스는 유지하며 창의 바깥 크기는 바뀌지 않고 메뉴바 높이만큼 내용 영역이 커집니다.
숨긴 상태에서 연결한 메뉴나 교체한 메뉴도 표시하기 전까지 보이지 않습니다. 메뉴가 없는 창에도
값을 저장하며 이후 연결한 메뉴에 적용합니다. 닫힌 창의 값은 조회할 수 없습니다.

`setWindowMenuAutoHide`는 Alt 키를 단독으로 눌렀다 뗄 때 메뉴바를 표시하거나 숨기게 하고
(Electron `setAutoHideMenuBar`, `isMenuBarAutoHide`), `getWindowMenuAutoHide`가 현재 값을 돌려줍니다.
기본값은 `false`입니다. 켜는 것만으로 지금 보이는 메뉴바를 숨기지는 않으며(Electron과 같음), 켠 창에
새로 연결하거나 교체한 메뉴는 숨긴 채 시작합니다. 켠 창에서 표시 중인 메뉴바는 Alt를 다시 단독으로 누르거나,
Esc를 누르거나, 항목을 실행하거나, 창 틀에서 Alt 뒤에 Windows가 연 메뉴 모드가 끝나거나, 창이
비활성화되면 숨깁니다. 포커스가 창 틀에 있든 페이지 안에 있든 같은 Alt 입력을 따르고, Alt와 다른 키를
함께 누르면 단독 입력으로 세지 않습니다. 이 규칙은 auto-hide를 켠 창에만 적용합니다.

auto-hide를 켠 창에서는 `getWindowMenuVisible`이 지금 메뉴바가 실제로 보이는지를 돌려줍니다
(Alt로 잠깐 띄운 동안 `true`, Electron `isMenuBarVisible`과 같음). `setWindowMenuVisible`로 표시해도
같은 규칙으로 다시 숨습니다. 메뉴바가 보이는 동안 내용 영역은 메뉴바 높이만큼 줄고 숨기면 원래대로
돌아옵니다. 숨겨진 동안에는 메뉴바가 없으므로 Alt와 글자 키로 메뉴를 바로 여는 니모닉은 동작하지 않고,
페이지를 클릭해도 표시한 메뉴바는 그대로 남으며, 전체화면에 들어갈 때 메뉴바를 숨기지 않습니다.
닫힌 창의 값은 조회할 수 없습니다.

```ts
await menu.create({
  menuId: "main-menu",
  items: [{
    id: "file", type: "submenu", label: "파일",
    items: [{ id: "save", type: "item", label: "저장" }],
  }],
});
await menu.setWindowMenu({ menuId: "main-menu" });
await menu.setWindowMenu({ menuId: null });

const popup = new AbortController();
const selected = await menu.showContextMenu(
  { menuId: "main-menu", x: 320, y: 200 },
  { signal: popup.signal },
);
```

`x`, `y`는 화면 전체 기준의 물리 픽셀 좌표입니다. 왼쪽이나 위쪽 모니터의 음수 좌표도
허용합니다. 팝업은 메뉴바 연결을 바꾸지 않고 리소스의 별도 네이티브 복사본을 표시합니다.
일반적으로 선택하면 ID, Esc나 바깥 클릭으로 닫으면 `null`을 반환합니다.
호출의 AbortSignal 취소, 컨텍스트 폐기와 앱 종료는 팝업을 닫고 `CANCELLED`로 끝냅니다.
예제의 `popup.abort()`를 다른 작업이나 UI 이벤트에서 호출할 수 있습니다.
팝업을 기다리는 동안 같은 UI 스레드의 일반 변경 작업은 네이티브 메뉴 루프가 끝날 때까지
대기할 수 있습니다. 취소는 별도 중단 경로로 처리합니다. 팝업 중 또 다른 팝업을 열지 않습니다.

하나의 리소스를 창 메뉴바 여러 개 또는 메뉴바와 트레이에 동시에 연결하면 `BUSY`입니다.
먼저 분리하거나 리소스를 복사해 다른 ID로 만듭니다. 같은 리소스로 컨텍스트 팝업을 표시할
수는 있습니다. 리소스 변경은 연결된 메뉴바를 교체하며 제거하면 자동으로 분리합니다.
창을 닫으면 메뉴바의 네이티브 핸들을 먼저 해제하지만 앱 범위 리소스는 유지합니다.
재생성한 창에는 다시 연결해야 합니다.

메뉴바 선택 이벤트의 source는 `"window"`, 팝업은 `"context"`이며 windowId는 소유 창의
ID입니다. 팝업의 반환값과 `menu.clicked`는 같은 선택을 나타내므로 앱 작업을 둘 다에서
중복 실행하지 않습니다. `waitForClick`도 세 source를 모두 받습니다.
연결과 분리는 창의 바깥 크기를 유지하고 콘텐츠 영역을 변경합니다. 기본 메뉴바 숨김과
자동 숨김은 제공하지 않으며 분리로 제거합니다.

## 편집 role과 창 role

`type: "item"`은 선택 필드 `role`을 가질 수 있습니다. checkbox, radio, submenu와 separator는 role을
받지 않습니다. 편집 role은 `undo`, `redo`, `cut`, `copy`, `paste`, `selectAll`이고, 창 role은 `close`, `minimize`, `quit`입니다.

```ts
await menu.create({
  menuId: "main-menu",
  items: [{
    id: "edit", type: "submenu", label: "편집",
    items: [
      { id: "undo", type: "item", role: "undo" },
      { id: "redo", type: "item", role: "redo" },
      { id: "sep", type: "separator" },
      { id: "cut", type: "item", role: "cut" },
      { id: "copy", type: "item", role: "copy", label: "복사하기" },
      { id: "paste", type: "item", role: "paste" },
      { id: "all", type: "item", role: "selectAll" },
    ],
  }],
});
```

role 항목을 선택하면 메뉴를 연 창의 페이지에서 현재 포커스된 document에 편집 명령을 직접 실행합니다.
키 이벤트를 만들지 않으므로 페이지의 `keydown` 처리와 키보드 자판 배열에 영향받지 않고,
다른 앱에는 입력을 보내지 않습니다. 포커스는 최상위 document에서 같은 origin의 iframe 안으로 따라갑니다.
cross-origin iframe에 포커스가 있으면 아무것도 실행하지 않습니다.
`selectAll`은 `selectstart`, `copy`와 `cut`은 해당 ClipboardEvent를 발생시키며 페이지가 이를 막을 수 있습니다.
`undo`, `redo`, `cut`은 `beforeinput` 이벤트를 만들지 않습니다.
`paste`는 호스트가 클립보드의 일반 텍스트를 읽어 포커스된 요소에 삽입합니다. `paste` 이벤트 대신
`beforeinput`(`insertText`)이 발생하고, 일반 텍스트가 아닌 클립보드 내용은 삽입하지 않습니다.
클립보드가 비었거나 다른 프로세스가 점유 중이면 `paste`는 아무것도 하지 않습니다.
`paste`는 포커스를 확인한 뒤 텍스트를 넣으므로, 그 사이 포커스가 cross-origin iframe으로 옮겨지면
해당 프레임이 텍스트를 받을 수 있습니다.
창이 닫히는 중이거나 WebView가 없으면 선택은 조용히 무시하고 호스트 진단에만 기록합니다.
role 항목은 `menu.clicked`를 보내지 않고 `waitForClick` 대기자도 깨우지 않으며,
`showContextMenu`는 `null`을 반환합니다.

`label`을 생략하면 role의 기본 label을 사용하고 `get` 결과에도 채워서 반환합니다.
기본 label과 메뉴에 표시하는 단축키 문구는 다음과 같습니다. 문구는 표시용이며
실제 키 입력은 페이지가 직접 처리합니다. `label`을 지정해도 단축키 문구는 유지합니다.

| role | 기본 label | 표시 단축키 |
| --- | --- | --- |
| `undo` | Undo | Ctrl+Z |
| `redo` | Redo | Ctrl+Y |
| `cut` | Cut | Ctrl+X |
| `copy` | Copy | Ctrl+C |
| `paste` | Paste | Ctrl+V |
| `selectAll` | Select All | Ctrl+A |
| `close` | Close | Ctrl+W |
| `minimize` | Minimize | Ctrl+M |
| `quit` | Exit | 없음 |

창 role은 메뉴를 연 창 또는 앱에 명령을 실행합니다. 표시 단축키는 표시 전용이며 키 입력을 가로채거나 등록하지 않습니다.
필요하면 `accelerator`로 표시 문구를 바꿉니다.
`close`는 제목 표시줄의 닫기 단추와 같은 경로로 창에 닫기 요청을 보냅니다. `closable: false`인 창은 닫히지 않고,
`windows.closeRequested`를 구독한 문서의 응답과 `closeBehavior`도 그대로 적용됩니다.
`minimize`는 `windows.minimize`와 같이 창을 최소화합니다. `minimizable: false`인 창에서는 실행하지 않고 호스트 진단에만 기록합니다.
전체 화면 창은 호스트가 상태 변경을 거부하므로 같은 방식으로 진단에만 기록합니다.
`closable: false`나 `minimizable: false`여도 항목을 비활성으로 표시하지 않으며, 선택하면 아무 일도 일어나지 않습니다.
`quit`은 트레이의 Quit과 같은 종료 요청을 `"quit-command"` 사유로 `beforeQuit`에 전달합니다. 앱이 취소하면 아무것도 닫지 않습니다.
창 role은 창이 닫히는 중이면 편집 role처럼 조용히 무시합니다.

트레이 메뉴는 앱 창에 속하지 않아 편집 role은 입력이 다른 앱에 들어갈 수 있고 창 role은 대상 창이 없으므로 role을 거부합니다. 트레이에서 종료하려면 일반 항목의 `menu.clicked`에서 `DesktopContext.quit()`를 호출합니다.
role 항목이 있는 리소스의 `setTrayMenu`와, 트레이에 연결한 리소스에 role을 넣는
`replace`와 `insert`는 `INVALID_ARGUMENT`입니다. 창 메뉴바와 컨텍스트 팝업에서만 사용합니다.

## 정책과 오류

각 함수는 같은 이름의 독립 Host 권한을 요구합니다. 예를 들어 생성은 `menu.create`,
트레이 연결은 `menu.setTrayMenu`입니다. 화면 직접 호출은 `plugin.menu.create` 같은 명령도
허용해야 합니다. 리소스는 앱 전체에 공유되므로 허용된 작업은 다른 뷰가 만든 메뉴에도 적용됩니다.
대상별 접근 규칙이 필요하면 앱 명령에서 검사합니다. 등록과 설치가 권한을 부여하지 않습니다.

없는 리소스의 변경, 잘못된 항목이나 삽입 위치는 `INVALID_ARGUMENT`입니다.
중복 메뉴 ID, 중복 연결, 입력이 차단된 소유 창과 32개 초과는 `BUSY`, 권한 없음은 `PERMISSION_DENIED`입니다.
미등록 작업, 다른 플랫폼과 트레이 없는 앱의 트레이 연결은 `UNSUPPORTED`입니다.
없는 창이나 닫히는 창의 메뉴 작업은 `INVALID_ARGUMENT`입니다.
취소는 `CANCELLED`, 기한 초과는 `TIMEOUT`이며 완료한 동기 변경을 되돌리지 않습니다.
네이티브 메뉴 생성 오류는 호스트 진단에 기록합니다.

accelerator는 표시 전용이며 단축키 등록은 제공하지 않습니다. 메뉴는 accelerator로 표시한 조합을 가로채지 않으므로,
일반 실행에서 WebView에 포커스가 있을 때 `Ctrl+S` 같은 조합은 페이지의 키 이벤트로 전달되고 같은 값을 표시해도 달라지지
않습니다. Alt와 F10 같은 Windows 기본 메뉴 탐색 키, `--devtools` 실행에서 WebView2가 직접 처리하는 브라우저 가속키는
이 규칙의 대상이 아닙니다. 같은 조합을 `globalShortcut`으로도 등록하면 그 등록은 포커스와 관계없이 동작합니다.
키 처리와 충돌 해소는 앱이 맡습니다.
role의 표시 단축키를 포함해 `Ctrl+...` 단축키는 자동 실행하지 않습니다.
라벨의 `&`는 문자 그대로 표시합니다. Windows의 기본 메뉴 탐색 키만 사용합니다.
