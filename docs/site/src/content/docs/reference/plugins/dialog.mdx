`@bunaway/plugin-dialog`을 설치하고 기본 export `dialog`을 앱의 `plugins`에 등록합니다.
파일과 폴더의 경로를 선택하고 메시지 대화상자로 사용자에게 선택을 받습니다. Windows와 macOS는 모든 작업을 지원합니다.
다른 플랫폼은 모두 `UNSUPPORTED`입니다. macOS 차이는 [macOS](#macos) 절에 모았습니다.

```ts
import { defineApp } from "@bunaway/backend";
import dialog from "@bunaway/plugin-dialog";

export default defineApp({ modules: [], plugins: [dialog] });
```

## 작업과 입력

```ts
dialog.openFile(input: OpenFileInput, options?: NativeInvokeOptions): Promise<DialogResult>
dialog.selectFolder(input: SelectFolderInput, options?: NativeInvokeOptions): Promise<DialogResult>
dialog.saveFile(input: SaveFileInput, options?: NativeInvokeOptions): Promise<DialogResult>
dialog.showMessage(input: MessageInput, options?: NativeInvokeOptions): Promise<MessageResult>
```

모든 작업에 입력 객체가 필요합니다. 파일 선택의 기본 설정은 `{}`로 지정합니다.
`dialog.showMessage`는 `message`가 필수입니다.
`dialog.openFile`, `dialog.selectFolder`, `dialog.saveFile`, `dialog.showMessage`는 각각 별도 권한입니다.
뷰의 명령은 해당 뷰의 `host.permissions`, setup은 `backend.permissions`에 허용합니다.
화면에서 플러그인을 직접 호출할 때는 `plugin.dialog.openFile`, `plugin.dialog.showMessage` 등 해당 명령도
뷰의 `commands`에 허용해야 합니다.

| 입력 | 작업 | 의미 |
| --- | --- | --- |
| `ownerWindowId?: string` | 전체 | 살아 있는 창 수명 ID. 뷰는 자신의 호출 창만 지정할 수 있습니다. |
| `title?: string` | 전체 | 1~256자의 제목. NUL은 거부합니다. 메시지 대화상자에서 생략하면 Windows가 실행 파일 이름을 표시합니다. |
| `defaultDirectory?: string` | 열기, 폴더, 저장 | 처음 표시할 기존 디렉터리. 경로 해석 실패는 오류입니다. |
| `showHiddenFiles?: boolean` | 열기, 폴더, 저장 | 기본 `false`. `true`이면 숨김 및 시스템 항목을 강제로 표시합니다. 생략하거나 `false`이면 사용자의 탐색기 설정을 따릅니다. |
| `confirmOverwrite?: boolean` | 저장 | `true`이면 기존 파일 덮어쓰기 확인을 켜고 `false`이면 끕니다. 생략하면 Windows 기본 확인을 유지합니다. 열기와 폴더에 지정하면 `INVALID_ARGUMENT`입니다. |
| `multiple?: boolean` | 열기, 폴더 | 기본 `false`. `true`이면 파일 또는 폴더를 여러 개 선택합니다. |
| `filters?: { name: string; extensions: string[] }[]` | 열기, 저장 | 1~32개 필터. 이름은 1~128자, 확장자는 필터당 1~32개입니다. |
| `defaultFileName?: string` | 열기, 저장 | 기본 파일 이름. 1~255자이며 경로 구분자, Windows 예약 문자와 NUL은 거부합니다. |
| `defaultExtension?: string` | 열기, 저장 | 점 없는 기본 확장자. 예: `txt`. |

확장자는 영문자나 숫자로 시작하고 영문자, 숫자, `_`, `-`로 이루어진 1~32자입니다.
필터 확장자 `*`는 모든 파일을 표시합니다. 필터는 표시와 선택 안내이며 파일 내용이나
보안 경계를 검증하지 않습니다. 저장 경로를 선택해도 파일을 쓰지 않습니다.
파일과 폴더 대화상자는 OS 기본 새 폴더 UI를 유지하며, Windows에서 이를 끄는 옵션은 없습니다.

```ts
// 앱 명령 안에서 현재 호출의 권한과 취소를 상속합니다.
const result = await dialog.openFile({
  multiple: true,
  filters: [{ name: "텍스트", extensions: ["txt", "md"] }],
});
if (!result.cancelled) {
  for (const path of result.paths) {
    // 앱의 접근 규칙과 별도 storage 작업 권한으로 다음 작업을 결정합니다.
  }
}
```

## 메시지 대화상자

`dialog.showMessage`는 모달 메시지 대화상자를 표시하고 사용자가 누른 버튼을 반환합니다.
`ownerWindowId`와 `title`은 위 표와 같은 규칙을 따르며, 나머지 입력은 다음과 같습니다.
알 수 없는 필드와 NUL 문자는 거부합니다.

| 입력 | 의미 |
| --- | --- |
| `message: string` | 필수. 1~4096자의 주 안내 문구. |
| `detail?: string` | 1~8192자의 보조 설명. |
| `type?: "none" \| "info" \| "warning" \| "error" \| "question"` | 기본 `"none"`. 아이콘만 바꾸며 버튼 구성이나 결과에는 영향이 없습니다. |
| `buttons?: string[]` | 1~8개 버튼 라벨(각 1~64자). 생략하면 운영체제 언어의 확인 버튼 하나이며 인덱스는 0입니다. `&`를 포함한 라벨 문자는 그대로 표시됩니다. |
| `defaultButton?: number` | 처음 포커스를 받는 버튼 인덱스. 기본 0. |
| `cancelButton?: number` | ESC, 창 닫기 버튼과 Alt+F4가 반환할 버튼 인덱스. |
| `checkbox?: { label: string; checked?: boolean }` | 확인란. `label`은 1~256자이고 `checked` 기본값은 `false`입니다. `label`의 `&`도 그대로 표시됩니다. |

`defaultButton`과 `cancelButton`은 `buttons`의 길이보다 작은 정수여야 합니다. `buttons`를
생략하면 길이를 1로 봅니다. 범위를 벗어난 인덱스, 빈 `buttons` 배열, 9개 이상의 버튼은
대화상자를 표시하기 전에 `INVALID_ARGUMENT`로 거부합니다.

`cancelButton`을 생략하면 버튼이 하나일 때만 0으로 간주합니다. 버튼이 둘 이상이면 ESC,
제목 표시줄의 닫기 버튼과 Alt+F4가 동작하지 않으므로 사용자가 반드시 버튼을 눌러야 합니다.
`cancelButton`을 지정하면 ESC, 닫기 버튼과 Alt+F4가 모두 그 인덱스를 반환합니다.

결과는 `{ button: number; checkboxChecked: boolean }`입니다. `button`은 누른 버튼의 인덱스입니다.
`checkboxChecked`는 항상 포함되며 확인란을 요청하지 않으면 `false`입니다.
파일 선택과 달리 사용자가 ESC나 닫기로 끝내는 경우도 `cancelButton`에 해당하는 일반 버튼 결과이며
`{ cancelled: true }`는 없습니다.

```ts
const result = await dialog.showMessage({
  title: "파일 삭제",
  message: "report.docx를 삭제할까요?",
  detail: "삭제한 파일은 복구할 수 없습니다.",
  type: "warning",
  buttons: ["삭제", "취소"],
  defaultButton: 1,
  cancelButton: 1,
  checkbox: { label: "다시 묻지 않기" },
});
if (result.button === 0) {
  // "삭제"를 눌렀습니다. result.checkboxChecked로 확인란 선택 여부를 확인합니다.
}
```

## 결과, 소유 창과 취소

파일 선택에서 사용자의 Cancel, ESC 또는 대화상자 닫기는 `{ cancelled: true }`입니다.
성공은 `{ cancelled: false, paths: string[] }`입니다. 단일 선택과 저장은 경로 하나를
반환합니다. 다중 선택은 최대 128개이며 결과 순서는 Windows가 반환한 순서입니다.
각 경로는 최대 32,767 UTF-16 코드 단위, 전체 결과 경로는 최대 131,072 코드 단위입니다.
상한을 넘으면 일부 경로를 잘라 반환하지 않고 오류로 끝납니다.

뷰에서 시작한 호출은 호스트가 인증한 정확한 창 인스턴스를 소유 창으로 사용합니다.
`ownerWindowId`를 생략해도 이 관계를 유지합니다. 다른 창 ID는 `PERMISSION_DENIED`입니다.
신뢰된 backend setup은 임의의 살아 있는 앱 창을 지정하거나 생략해 소유 창 없이 표시할 수 있습니다.
없거나 이미 닫힌 창은 `INVALID_ARGUMENT`이며 창을 재생성해도 이전 호출을 새 창에 연결하지 않습니다.

호출 abort, 기한 만료, 문서/세션 종료와 앱 종료는 사용자 취소 결과나 메시지 대화상자의 버튼 결과로 바꾸지 않습니다.
호출자는 기존 SDK의 `CANCELLED` 또는 `TIMEOUT` 오류를 받고 호스트는 열린 대화상자를 닫습니다.
소유 창의 종료가 확정되면 `CANCELLED`입니다. 결과와 취소가 경합하면 완료 전에 관측한 취소를 우선합니다.
웹 호출에서는 기존 `NativeInvokeOptions`의 `signal`과 기한을 사용할 수 있습니다.
백엔드의 명령 호출은 현재 컨텍스트의 취소와 기한을 상속하며 별도 옵션을 받지 않습니다.

```ts
// 화면 코드. 버튼이나 컴포넌트 수명에서 controller.abort()를 호출할 수 있습니다.
const controller = new AbortController();
const result = await dialog.selectFolder({}, { signal: controller.signal });
```

소유 창 규칙은 `dialog.showMessage`에도 같게 적용됩니다. Windows UI 스레드는 파일 선택과 메시지를 합쳐 한 번에 대화상자 하나를 실행합니다. 동시 요청은 기존 호스트의
유한 큐에서 순서대로 실행합니다. 대기 중 취소한 요청은 이후 대화상자를 열지 않습니다.
다른 Promise 기반 UI 작업과 창 파괴 요청도 현재 모달 호출이 끝난 뒤 실행됩니다.
네이티브 재진입으로 중첩 호출을 시도하면 `BUSY`입니다. 앱 백엔드 스레드는 계속 실행합니다.
호출자의 Promise 거부 시점이 네이티브 자원 정리 완료 시점이라는 보장은 없습니다.

## macOS

macOS는 `NSOpenPanel`과 `NSSavePanel`을 메인 스레드에서 앱 모달로 표시합니다. 입력과 결과 형식은
Windows와 같고 다음이 다릅니다.

| 항목 | macOS 동작 |
| --- | --- |
| 소유 창 | sheet가 아닌 앱 모달 패널입니다. `ownerWindowId`는 받지만 패널을 그 창에 붙이지 않으며 소유 창 종료로 패널을 닫지 않습니다. |
| 취소 | 패널이 열려 있는 동안 메인 스레드가 모달 루프에서 대기하므로 호출 abort, 기한 만료와 앱 종료는 열린 패널을 닫지 못합니다. 패널을 열기 전에 관측한 취소는 패널을 열지 않습니다. 패널이 닫힌 시점에 취소가 이미 관측되어 있으면 사용자의 선택 대신 `CANCELLED`로 끝납니다. 선택한 경로가 128개 또는 전체 131,072 코드 단위를 넘으면 Windows와 같이 오류로 끝납니다. |
| 필터 | 패널에는 필터 목록이 없어서 모든 필터의 확장자를 합쳐 허용합니다. `*`가 하나라도 있으면 모든 파일을 허용합니다. 저장 패널은 확장자 없이 입력한 이름에 허용 목록의 첫 확장자를 붙입니다. |
| `defaultFileName` | 저장 패널의 이름 입력란에만 설정합니다. 열기 패널에는 이름 입력란이 없어 무시합니다. |
| `showHiddenFiles` | `true`이면 숨김 항목을 표시합니다. 생략하거나 `false`이면 Finder 설정이 아니라 패널 기본값(숨김 항목 비표시)을 씁니다. |
| `ownerWindowId` 검증 | 창 ID와 호출 출처를 검증하지 않습니다. 다른 창 ID나 닫힌 창을 지정해도 `PERMISSION_DENIED`나 `INVALID_ARGUMENT`가 아니라 앱 모달 패널을 표시합니다. |
| `defaultExtension` | 확장자가 없는 `defaultFileName`에 붙입니다. 사용자가 입력한 이름에는 적용하지 않습니다. |
| `confirmOverwrite` | 저장 패널은 기존 파일을 덮어쓸 때 항상 확인하므로 `false`를 지정해도 확인은 유지합니다. |
| `title` | 창 제목과 패널 상단 메시지로 함께 설정합니다. 최신 macOS는 메시지 줄을 표시합니다. |
| 새 폴더 | 폴더 선택과 저장 패널은 새 폴더 만들기를 허용하고 파일 열기 패널은 허용하지 않습니다. |

### macOS 메시지 대화상자

`dialog.showMessage`는 `NSAlert`를 메인 스레드에서 앱 모달(`runModal`)로 표시합니다. 입력과 결과 형식은
Windows와 같고 다음이 다릅니다.

| 항목 | macOS 동작 |
| --- | --- |
| 버튼 | 입력 순서대로 추가하며 첫 버튼이 가장 오른쪽입니다. `buttons`를 생략하면 시스템이 현지화한 확인 버튼 하나를 둡니다. 결과의 `button`은 누른 버튼의 입력 순서 번호입니다. |
| 기본 버튼과 취소 버튼 | `defaultButton`(생략 시 0)은 Return, 취소 버튼(`cancelButton`, 버튼이 하나뿐이면 0)은 Escape의 key equivalent로 연결합니다. 버튼 하나에는 키가 하나만 걸리므로 둘이 같은 버튼이면 Return만 연결하고 Escape는 연결하지 않습니다. 버튼이 하나뿐인 대화상자(`buttons`를 생략한 경우 포함)가 여기에 해당하므로, 공통 규칙과 달리 Escape로 닫히지 않고 버튼을 눌러야 합니다. 취소 버튼을 정하지 않은 여러 버튼 대화상자에서도 Escape를 연결하지 않으며, AppKit이 제목이 `Cancel`인 버튼에 따로 연결하는 동작은 막지 않습니다. Electron의 `showMessageBox`처럼 key equivalent로 연결하는 방식입니다. |
| `type` | `none`, `info`, `question`은 정보 스타일, `warning`은 경고 스타일, `error`는 위험 스타일입니다. 앱 아이콘 위에 겹치는 시스템 스타일만 쓰며 별도 아이콘은 두지 않습니다. |
| `title` | `NSAlert`는 제목 표시줄이 없어 무시합니다. |
| `checkbox` | 대화상자의 확인란으로 표시하고 닫힌 뒤의 상태를 `checkboxChecked`로 돌려줍니다. 확인란이 없으면 `false`입니다. |
| 소유 창과 취소 | 파일 패널과 같습니다. 소유 창에 붙이지 않고, 열린 대화상자는 호출 abort와 기한 만료로 닫히지 않습니다. 열기 전에 관측한 취소는 대화상자를 열지 않고, 닫힌 시점에 이미 관측되어 있으면 사용자의 선택 대신 `CANCELLED`로 끝납니다. |

반환값은 경로 문자열뿐입니다. security-scoped bookmark를 만들지 않으므로 앱이 샌드박스로 실행될 때
선택한 위치에 대한 지속 접근은 보장하지 않습니다. 결과 순서는 AppKit이 반환한 순서입니다.

## 파일 접근과 검증 범위

선택 결과는 경로 문자열입니다. storage 권한, 파일 핸들, 지속 접근 토큰이나 다른 앱의
접근 권한을 만들지 않습니다. 선택한 뒤 파일이 바뀌거나 삭제될 수 있으므로 실제 읽기와
쓰기에서 앱의 대상 검증과 기존 storage 권한을 적용하세요. 최근 항목 목록에 추가하지 않으며,
저장 가능 여부를 확인하는 임시 파일도 생성하지 않습니다.

계약 테스트는 입력, 작업별 권한, 소유 창 범위, 사용자 취소와 호출 실패, 정리와 재진입을 검사합니다.
Windows 통합 테스트는 실제 UI Worker와 Common Item Dialog에서 파일/폴더/저장 경로 선택,
user Cancel 명령, 동시 호출, 호스트 abort와 shutdown을 검사하도록 구성했습니다.
메시지 대화상자는 Linux 계약 테스트로 입력 검증, ESC와 cancel 버튼 규칙, 결과 형식을 검사합니다.
Windows 통합 테스트는 실제 TaskDialog의 버튼 클릭, 확인란, ESC와 abort를 검사하도록 구성했습니다.
실제 사람의 키보드/마우스, 여러 모니터, overwrite 확인 UI와 실제 소유 창 파괴는 별도 수동 검증입니다.
macOS는 Linux 계약 테스트로 입력을 패널과 `NSAlert` 설정으로 바꾸는 규칙, 취소와 재진입을 검사하고, macOS CI에서
실제 패널의 설정을 AppKit에서 다시 읽어 확인하며 열린 모달 패널을 예약한 취소로 닫습니다.
macOS CI는 `NSAlert`의 문구, 버튼 순서와 키, 확인란 설정을 AppKit에서 다시 읽고, 예약한 버튼 클릭으로 모달 알림이 누른 버튼과 확인란 상태를 돌려주는지 확인합니다.
파일 목록에서 항목을 선택하는 사용자 조작과 키보드(Return, Escape) 입력은 자동화하지 않았습니다.

## 제공하지 않는 대화상자

인증서 신뢰 확인 대화상자는 제공하지 않습니다. Electron의 `dialog.showCertificateTrustDialog`는 앱이
인증서 검증 처리기에서 받은 인증서 객체를 입력으로 받습니다. 이 프로젝트에는 그 인증서를 넘겨줄 WebView
인증서 오류 경로와 인증서 모델이 없고, dialog 플러그인이 임의의 인증서를 입력받는 계약도 없습니다.
Tauri에는 대응 기능이 없습니다. 인증서 오류와 사용자 신뢰 판단은 WebView 보안 설정의 범위입니다.

동기 대화상자(Electron의 `showMessageBoxSync`, `showOpenDialogSync`, `showSaveDialogSync`)도 제공하지
않습니다. 모든 작업이 Promise로 결과를 돌려주며 대화상자가 떠 있는 동안에도 앱 백엔드 스레드는
계속 실행합니다. 동기 변형은 백엔드 진행을 막으므로 추가하지 않습니다.
제공하는 작업은 `openFile`, `selectFolder`, `saveFile`, `showMessage` 네 가지이며 계약 테스트가
이 목록을 검사합니다.
