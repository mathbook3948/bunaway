기본 export(`default`)를 `updater`로 가져와 앱에 등록하고 호출합니다.

`@bunaway/plugin-updater` 패키지를 설치하고 앱의 `plugins`에 `updater`를 등록합니다. Windows와
macOS에서 같은 코드로 제공합니다. 화면과 백엔드는 같은 패키지의 `updater`를 사용합니다.
이 플러그인은 업데이트가 있는지만 조회합니다. 다운로드, 서명 검증, 설치와 재시작은 하지 않습니다.

```ts
import updater from "@bunaway/plugin-updater";

const update = await updater.check(null);
if (update.updateAvailable) {
  console.log(update.version, update.notes);
}
```

| 함수 | 입력 | 결과 | 권한 |
| --- | --- | --- | --- |
| `updater.check` | `null` | `Promise<UpdaterCheckResult>` | `updater.check` |

## 설정

엔드포인트는 호출 인자가 아니라 앱의 `src-bunaway/bunaway.json`에 고정합니다. 화면이 요청할 주소를 정할
수 없으므로 화면이 임의의 서버에 요청을 보내게 하는 데 쓰일 수 없습니다.

```json
{
  "plugins": {
    "updater": {
      "endpoint": "https://updates.example.com/{{target}}/{{arch}}/{{channel}}/{{current_version}}",
      "channel": "stable"
    }
  }
}
```

- `endpoint`(필수): 2048자 이하의 절대 URL 템플릿입니다. 자리표시자는 `{{target}}`, `{{arch}}`,
  `{{channel}}`, `{{current_version}}` 네 개만 쓸 수 있고 경로와 질의에만 둘 수 있습니다. 값은
  URL 인코딩되어 들어갑니다(`1.0.0+build`는 `1.0.0%2Bbuild`). 알 수 없는 자리표시자, 스킴이나 호스트 안의
  자리표시자, 사용자 정보(`user:pass@`), 프래그먼트는 거부합니다.
- `channel`: 소문자 영숫자와 `-`로 된 32자 이하 이름이며 기본값은 `stable`입니다.
- `target`은 Windows가 `windows`, macOS가 `darwin`이고 `arch`는 `x86_64` 또는 `aarch64`입니다.
  이 값은 앱이 아니라 실행 중인 호스트에서 정해집니다. 다른 CPU에서는 `UNSUPPORTED`입니다.

주소는 `https`만 허용합니다. 개발 실행(`bunaway dev`)에서만 호스트가 `localhost`, `127.0.0.1`, `[::1]`인
`http` 주소를 허용하며 패키지된 앱에서는 이를 켤 수 없습니다. 설정이 잘못되면 어댑터를 만들 때
`INVALID_ARGUMENT`로 실패해 시작 단계에서 드러납니다. `plugins.updater`가 없으면 `check`가
`UNSUPPORTED`(`details.reason: "notConfigured"`)로 실패합니다.

## 매니페스트

서버는 Tauri 정적 JSON의 읽기 전용 부분집합을 돌려줍니다. 응답 본문은 압축을 푼 뒤 64 KiB 이하여야 합니다.

```json
{
  "version": "1.2.0",
  "notes": "수정 내용",
  "pub_date": "2026-10-20T09:00:00Z",
  "platforms": {
    "windows-x86_64": { "url": "https://downloads.example.com/app-1.2.0.exe" }
  }
}
```

- `version`: 필수이며 SemVer 2.0.0이어야 합니다. 앞의 `v`, 앞자리 0, 빈 식별자는 거부합니다.
- `platforms["<target>-<arch>"].url`: 업데이트가 있을 때 필요합니다. 동적 서버처럼 최상위 `url`만 있어도 됩니다.
- `notes`, `pub_date`: 선택입니다. `signature` 같은 다른 필드는 읽지도 돌려주지도 않습니다.
- HTTP 204는 업데이트 없음으로 봅니다.

## 결과

`UpdaterCheckResult`는 `updateAvailable`, `currentVersion`, `version`, `notes`, `publishedAt`,
`downloadUrl`을 돌려줍니다. 원격 버전이 현재 버전보다 클 때만 `updateAvailable`이 `true`입니다. 같거나
낮은 버전은 내리지 않으며, 업데이트가 없으면 `version`, `notes`, `publishedAt`, `downloadUrl`이 `null`입니다.
비교는 SemVer 11절을 따릅니다. build metadata는 무시하고 prerelease는 같은 버전의 정식 릴리스보다 낮습니다.
prerelease를 받을지는 채널의 엔드포인트가 정합니다.

- `notes`는 16384자 이하이며 탭과 줄바꿈 외의 제어 문자가 있으면 잘라 보내지 않고 오류로 처리합니다.
  서버가 준 값이므로 HTML로 렌더링하지 말고 일반 텍스트로 표시해야 합니다.
- `publishedAt`은 RFC 3339 시각을 UTC ISO 8601로 정규화한 값입니다.
- `downloadUrl`은 2048자 이하의 `https` 주소이며 사용자 정보가 없어야 합니다. 서명 없이 받은 안내 값이므로
  업데이트의 출처를 증명하지 않습니다. 후속 다운로드와 설치 단계는 이 값을 입력으로 받지 않고, 백엔드가
  매니페스트를 다시 받아 앱에 내장된 공개키로 서명을 확인해야 합니다.

## 요청과 오류

요청은 GET이며 쿠키와 인증 정보를 보내지 않습니다. 리다이렉트는 3번까지 직접 따르며, 매 단계에서 위 주소
규칙을 다시 검사하고 `https`에서 `http`로 낮아지면 거부합니다. 다른 호스트로의 리다이렉트는 허용합니다.
전체 제한 시간은 15초입니다.

| 코드 | `details.reason` |
| --- | --- |
| `UNSUPPORTED` | `notConfigured`, `appVersionMissing`, `appVersionInvalid`, `unsupportedArch` |
| `TIMEOUT` | 제한 시간 초과 |
| `CANCELLED` | 호출 취소, 어댑터 dispose |
| `INTERNAL` | `network`, `httpStatus`(`details.status`), `redirectLimit`, `redirectScheme`, `tooLarge`, `invalidJson`, `invalidManifest`, `invalidVersion`, `platformMissing` |

앱 버전은 패키지 `manifest.json`의 `app.version`(`ctx.app.version`과 같은 값)이며 기록되지 않았으면
`appVersionMissing`입니다. 오류 메시지에는 서버 응답이나 주소를 넣지 않습니다.

## 검증 범위

테스트는 주입한 `fetch`로 버전 비교, 매니페스트 검증, 크기와 시간 상한, 리다이렉트, 오류 분류를 확인합니다.
실제 업데이트 서버와의 왕복은 검증하지 않았습니다. 서명 검증과 다운로드, 설치는 후속 작업입니다.
