## 구현 상태

| 채널 | 상태 | 서명 요구 |
| --- | --- | --- |
| `win-direct` | Inno Setup 설치 파일 생성 구현 | 선택적. 미서명은 경고 포함 |
| `win-store-unpackaged` | Store EXE/MSI용 설치 파일, 제출 자료 생성 구현 | 제출하려면 Trusted Root 체인 서명 필요 |
| `win-store-msix` | 패키징 미지원 | MSIX 실행에는 서명 필요 |
| `mac-direct` | 설정만 허용, 패키징 미지원 | 패키징 실행 미지원 |
| `mac-store` | 설정만 허용, 패키징 미지원 | 패키징 실행 미지원 |

macOS에서는 네이티브 `.app`을 빌드할 수 있습니다. macOS 배포 채널과 MSIX 패키징은 아직 지원하지 않습니다.

## Windows 직접 배포와 Store unpackaged

두 채널 모두 Inno Setup 6.3 이상과 Windows x64 산출물을 사용합니다.

| 옵션 | 기본값 | 동작 |
| --- | --- | --- |
| `scope` | `perUser` | `perUser` 또는 `perMachine`. 후자는 관리자 설치 |
| `webView2` | direct: `bootstrap`, Store: `check` | 런타임 준비 방법 |
| `desktopShortcut` | `false` | 바탕화면 바로가기 생성 |
| `startMenuShortcut` | `true` | 시작 메뉴 바로가기 생성 |
| `autostart` | `false` | perUser 로그인 자동 실행 작업 제공 |
| `associations` | 없음 | 사용자 선택으로 파일과 URL 처리 후보 등록 |
| `uninstall.preserveUserData` | `true` | 제거 시 사용자 데이터 보존 |
| `signing` | 최상위 설정 | [서명 객체](/reference/packaging/signing/) 전체 대체 |

`scope: "perMachine"`과 `preserveUserData: false`는 함께 사용할 수 없습니다.
설치한 사용자와 데이터 소유자가 다를 수 있기 때문입니다.

`preserveUserData`는 `%LOCALAPPDATA%\bunaway\<appId>`의 프레임워크 데이터 폴더에 적용합니다.
앱이 다른 위치에 저장한 파일의 보존과 삭제는 앱에서 관리합니다.

`perMachine` 설치 프로그램만 관리자 권한으로 실행합니다. 설치 마지막의 앱 실행 항목(기본은 선택 해제,
조용한 설치에서는 건너뜀)은 설치를 시작한 사용자의 권한으로 앱을 시작하도록 Inno Setup의 `runasoriginaluser`를 사용합니다.

`desktopShortcut`과 `startMenuShortcut`은 새 바로가기 생성을 제어합니다.
업데이트에서 설정을 끄거나 바탕화면 바로가기 작업 선택을 해제해도 기존 링크는 삭제하지 않습니다.
관리는 현재 설치 설정으로 정해진 시작 메뉴의 앱 링크와 제거 링크, 바탕화면의 앱 링크 경로로 제한합니다.
정해진 경로에 파일이 있으면 다시 만들지 않습니다. 같은 설치의 이전 EXE를 가리키는 앱 링크만
새 EXE로 연결하고 사용자 인자와 작업 디렉터리를 보존합니다. 실행 대상이 그대로면 파일을 저장하지 않습니다.
아이콘 경로가 이전 EXE와 일치하면 새 EXE로 갱신하며 아이콘 인덱스를 유지합니다. 사용자 지정 아이콘은 보존합니다.
다른 설치나 다른 프로그램을 가리키는 링크와 읽을 수 없는 링크는 변경하지 않습니다.

제거 시에는 정해진 경로에서 앱 링크의 실행 대상이 해당 설치의 현재 EXE와 일치할 때만 삭제합니다.
제거 프로그램 링크도 해당 설치의 제거 프로그램을 가리킬 때만 삭제합니다.
검증 실패, 대상 불일치 또는 읽기 오류가 있으면 남깁니다.
사용자가 이름을 바꾸거나 다른 폴더로 이동한 링크는 탐색하지 않아 업데이트나 제거 후 남을 수 있습니다.
이전 EXE의 이름이 바뀌었다면 해당 링크가 작동하지 않을 수도 있습니다.
정해진 경로에 같은 EXE를 가리키는 복사본을 놓으면 원본과 구분하지 못하고 삭제할 수 있습니다.

`bootstrap`은 WebView2 bootstrapper를 준비하고 검증한 뒤 앱 설치 중 런타임을 설치합니다.
설치 때 네트워크가 필요할 수 있습니다.
`check`는 이미 설치된 WebView2를 검사하며 없는 런타임을 다운로드하지 않습니다.
Store unpackaged는 설치 중 다운로드를 허용하지 않으므로 `bootstrap` 설정을 거부합니다.

### 로그인 자동 실행

`autostart: true`는 `perUser` 설치에 로그인 자동 실행 작업을 추가합니다.
새 설치와 업데이트 모두 선택하지 않은 상태로 시작하며 이전 작업 선택을 재사용하지 않습니다.
무인 설치는 `/TASKS="autostart"`로 선택하고 `/TASKS=""`로 해제합니다.
선택하면 런타임 플러그인과 같은 `HKCU` 64비트 Run의 `bunaway.packaged.<appId>`에
현재 EXE와 `--bunaway-autostart`를 등록합니다. 새 등록은 일반 표시 모드이며,
앱은 자동 실행 설정을 조회하거나 변경하려면 `@bunaway/plugin-autostart`를 별도로 등록해야 합니다.
기존 등록이 해당 설치의 EXE를 가리키면 인자와 숨김 모드를 보존하고 실행 경로만 갱신합니다.
작업을 해제하면 해당 설치가 소유한 등록을 제거합니다. 이 동작은 바로가기 선택 해제와 다릅니다.
옵션을 선언하지 않거나 `false`로 설정하면 작업을 제공하지 않고 기존 런타임 등록만 갱신합니다.

전체 명령줄은 런타임과 같은 260 UTF-16 코드 단위 제한을 적용합니다.
Windows의 `StartupApproved` 기록은 쓰거나 지우지 않아 사용자 비활성화 상태를 유지합니다.
설치 `identifier`를 유지하고 앱 `appId`를 바꾸면 기록된 이전 ID의 소유 등록을 정리합니다.
다른 ID로 자동 실행 동의를 넘기지 않으며 새 ID는 작업을 명시적으로 선택해야 등록합니다.
이전 ID의 Windows 활성 상태를 새 ID로 복사하지 않습니다.
이전 설치가 앱 ID를 기록하지 않았다면 현재 ID만 확인할 수 있어 이전 ID의 등록은 남습니다.
설치 `identifier` 자체를 바꾸면 별도 설치이므로 이전 설치를 먼저 제거해야 합니다.

등록이나 제거는 값 이름과 quoted EXE 경로가 현재 설치 또는 기록된 이전 설치와 일치할 때만 수행합니다.
다른 EXE를 가리키는 값은 남기며 선택한 새 등록과 충돌하면 파일 설치 전에 거부합니다.
현재 사용자 SID와 전체 Run 값 이름으로 정한 전역 mutex를 런타임과 공유합니다.
소유 확인, 등록 갱신과 제거를 잠금 안에서 수행해 다른 설치 ID의 설치 프로그램이나
실행 중인 앱이 확인과 변경 사이에 해당 값을 바꾸지 못하게 합니다.
ID를 변경할 때는 관련 ID를 정렬해 한 순서로 잠급니다. 프로세스가 비정상 종료해
잠금이 버려졌다면 값을 다시 확인한 뒤 진행합니다. 각 잠금 대기는 최대 5초이며
획득하지 못하면 등록을 바꾸지 않고 오류를 반환합니다. 런타임 I/O Worker는
잠금을 기다리지 않고 즉시 BUSY로 거부합니다. 이전 버전과 외부 레지스트리
도구는 이 잠금에 참여하지 않으므로 함께 실행하는 경우 같은 보장을 제공하지 않습니다.
조회, 쓰기나 정리가 실패하면 오류와 0이 아닌 종료 코드를 반환합니다.
이미 복사한 파일과 완료한 등록 변경은 되돌리지 않으며 이전 ID와 EXE 복구 기록을 보존합니다.
같은 설치 프로그램을 재시도하거나 현재 설치를 제거해 복구합니다.
미완료 복구가 별도 이전 소유자를 가리키면 추가 ID 또는 경로 변경을 파일 설치 전에 거부합니다.
제거 프로그램도 런타임이 만든 해당 설치의 등록과 남은 복구 소유자를 같은 조건으로 정리합니다.

Run 등록은 설치 폴더 변경에 맞춰 갱신하지만 이전 폴더의 파일과 이동한 바로가기를 탐색하지 않습니다.
바로가기와 이전 EXE 정리는 위의 기존 설치 폴더 및 설정된 링크 경로 정책을 따릅니다.
`perMachine`에서는 로그인 작업과 사용자별 Run 정리를 제공하지 않습니다.
MSIX의 StartupTask와 실제 로그아웃 및 로그인 검증은 별도 범위입니다.

### 파일과 URL 연결

`associations`를 선언하면 설치 프로그램에 선택하지 않은 `fileassociations`와
`urlschemes` 작업이 나타납니다. 업데이트에서는 Inno가 이전 작업 선택을 유지합니다.
무인 설치는 `/TASKS="fileassociations,urlschemes"`로 선택하고 `/TASKS=""`로 해제합니다.
선언하지 않은 종류의 작업은 나타나지 않습니다.

```json
{
  "associations": {
    "files": [{ "extension": ".note", "name": "Notes 문서", "mimeType": "application/x-notes" }],
    "urlSchemes": [{ "scheme": "notes", "name": "Notes 링크" }]
  }
}
```

각 목록은 1–32개 항목을 받습니다. 이름은 최대 128자이며 개행과 NUL을 허용하지 않습니다.
확장자는 점과 영숫자로 시작하고 나머지는 영숫자, `_`, `-`만 받습니다. 점 뒤에는 최대 32자입니다.
scheme은 2~32자이며 영문자로 시작하고 나머지는 영숫자, `+`, `.`, `-`만 받습니다.
영문자 한 개의 scheme은 `desktop.onOpen`이 Windows 드라이브 경로로 해석하므로 거부합니다.
둘 다 소문자로 정규화하며 중복을 거부합니다. MIME은 최대 128자의 `type/subtype` 형식입니다.

앱 EXE의 아이콘과 별도 ProgID를 등록하고 파일과 URL 인자를 각각 따옴표로 감싼 실행 명령을 만듭니다.
MIME은 앱의 처리 후보로 등록하며 공유 MIME 데이터베이스나 확장자의 Content Type을 덮어쓰지 않습니다.
등록은 `scope`에 따라 HKCU 또는 HKLM에 기록합니다. 사용자는 Windows 기본 앱 설정에서 기본 처리 앱을 선택합니다.
설치와 제거는 확장자, URL scheme의 기존 기본값과 Windows UserChoice를 변경하지 않습니다.
이미 등록된 기본 앱은 계속 유지됩니다.

업데이트는 이전 등록에서 해당 설치의 실행 명령과 일치하는 후보를 정리하고 현재 선언과 선택을 적용합니다.
실행 파일명이 바뀌면 후보의 실행 명령과 아이콘도 새 EXE를 사용합니다.
선언을 제거하거나 작업 선택을 해제하면 해당 후보를 정리합니다. 제거 프로그램도 같은 소유 검사로 정리합니다.
사용자가 실행 명령을 다른 앱으로 바꾼 ProgID와 해당 OpenWith 항목은 남깁니다.
선택한 후보의 소유 충돌은 파일 설치와 이전 등록 정리 전에 검사합니다.
레지스트리 쓰기나 설치 후 정리가 실패하면 설치 프로그램은 오류와 0이 아닌 종료 코드를 반환합니다.
설치 후 실패는 이미 복사한 파일, 일부 등록이나 완료된 정리를 되돌리지 않습니다.
등록 변경이 실패하면 이전 EXE 삭제를 생략합니다. 이전 파일을 삭제한 뒤 복구 기록 쓰기가
실패하면 삭제된 파일을 복원하지 않으며 다음 재시도에서 남은 기록을 정리합니다.
오류 원인을 해결한 뒤 같은 설치 프로그램을 다시 실행해 복구하세요.
새 후보는 ProgID를 만들기 전에 복구 기록을 남깁니다. 명령이나 처리 후보 목록을 쓰기 전에 실패해도
권한 문제를 해결한 뒤 재시도하거나 제거하면 앱이 만들던 후보를 정리합니다.
후보의 실행 명령이 다른 앱으로 바뀌면 복구 기록이 있어도 변경하거나 삭제하지 않습니다.
이전 EXE의 등록 정리가 실패한 업그레이드는 Inno 이전 설치 데이터에 소유 EXE와 폴더를 보존합니다.
반복 실패에서도 이 기록을 유지하고 등록과 필요한 설치 후 정리가 성공한 뒤에만 지웁니다.
레지스트리 값이나 후보 목록을 읽지 못하면 정리를 중단하고 등록과 복구 기록을 남깁니다.
일부 하위 키만 삭제된 경우에는 권한을 복구한 뒤 다시 설치하거나 제거해 정리를 마칠 수 있습니다.
새 제거 프로그램도 같은 소유 검사로 실패한 이전 등록을 정리합니다.
복구 소유자는 등록 변경, 바로가기 갱신과 이전 EXE 삭제가 모두 끝날 때 지웁니다.
서로 다른 이전 EXE의 복구가 남아 있으면 다른 실행 파일명이나 설치 폴더로 바꾸는 업데이트는
파일 설치 전에 거부합니다. 현재 설치 프로그램으로 복구를 완료하거나 현재 설치를 제거한 뒤 진행하세요.
등록 변경 뒤 파일 삭제가 실패해도 다음 재시도는 이전 EXE를 계속 정리합니다.
새 제거 프로그램은 덮어쓴 제거 기록에 없는 이전 EXE도 삭제합니다. 안전한 파일명과 같은 설치
폴더를 확인하며, 파일이나 설치 폴더의 상위 경로가 reparse point이면 해당 이전 파일을 남깁니다.
복구에는 실패 원인의 해결과 레지스트리 접근 권한이 필요하며, 실패 전 상태로 자동 rollback하지 않습니다.
이 기능은 기존 바로가기 보존 정책을 바꾸지 않습니다.
같은 AppId의 생성된 설치와 제거 프로그램은 세션과 설치 범위에 관계없이 유지 보수 잠금을 공유합니다.
다른 설치나 제거가 열려 있으면 새 작업을 거부하며 네이티브 종료 정리가 끝날 때까지 잠금을 유지합니다.
현재 EXE, 설치 폴더와 복구 소유자를 한 상태로 읽고 파일 설치 및 기록 변경 전에 다시 확인합니다.
이 세 값이 없으면 빈 값으로 처리하지만, 조회 권한이 없거나 저장 형식이 문자열이 아니면 설치와
제거를 중단합니다. 복구 기록을 읽지 못한 상태로 파일이나 제거 정보를 지우지 않습니다.
마법사가 열린 동안 이전 버전이나 외부 도구가 이 상태를 바꾸면 닫고 다시 시작하세요.
잠금에 참여하지 않는 이전 버전의 설치나 제거를 동시에 실행하는 것은 지원하지 않으며 자동 rollback하지 않습니다.

운영체제가 실행기에 전달한 인자는 [desktop.onOpen](/reference/backend/app-definition/#데스크톱-앱-동작)에서 받습니다.
파일과 URL은 `desktop.onOpenUrls`에서도 `file:` URL을 포함한 절대 URL 목록으로 받을 수 있습니다.
앱이 파일과 URL의 형식과 접근 권한을 검증해야 합니다. 런타임 등록 API, 기본 앱 조회와 MSIX 활성화는 아직 지원하지 않습니다.
Windows 설정에서 후보를 선택한 뒤 실제 파일과 링크를 여는 수동 검증은 별도로 수행하세요.

### win-direct

```json
{
  "bundle": {
    "channels": {
      "win-direct": {
        "scope": "perUser",
        "webView2": "bootstrap",
        "desktopShortcut": false,
        "startMenuShortcut": true,
        "uninstall": { "preserveUserData": true }
      }
    }
  }
}
```

서명 없이도 로컬 실행용 설치 파일을 만들 수 있으며 서명 여부는 보고서에 기록됩니다.
배포 전에는 실제 설치 동작과 SmartScreen 표시를 확인하세요.

### win-store-unpackaged

PE와 설치 파일이 제출용 서명 조건 및 오프라인 설치 조건을 충족하는지 검사합니다.
생성된 제출 자료와 체크리스트를 확인한 뒤 배포자가 Store에 업로드합니다.
`submission.json`의 다운로드 URL은 생성 시 비어 있을 수 있으므로,
배포자가 버전별로 고정된 HTTPS 다운로드 주소를 준비하고 제출 정보를 채워야 합니다.
현재 설정에 임의의 `downloadUrl` 필드를 추가할 수는 없습니다.

## win-store-msix 예약 옵션

| 옵션 | 형식 |
| --- | --- |
| `packageName` | 3–50자. 영숫자로 시작, 나머지 영숫자, `. _ -` |
| `unvirtualizedData` | boolean |
| `minVersion` | 비어 있지 않은 문자열, 최대 64자 |
| `maxVersionTested` | 비어 있지 않은 문자열, 최대 64자 |
| `capabilities` | 비어 있지 않은 문자열의 배열 |
| `signing` | 서명 객체 |

현재는 이 필드의 형식만 검증하며 MSIX 생성에는 사용하지 않습니다.

## macOS 예약 옵션

| 옵션 | mac-direct | mac-store | 형식 |
| --- | --- | --- | --- |
| `format` | 예 | 아니요 | 비어 있지 않은 문자열, 최대 64자 |
| `bundleId` | 예 | 예 | 비어 있지 않은 문자열, 최대 64자 |
| `minVersion` | 예 | 예 | 비어 있지 않은 문자열, 최대 64자 |
| `entitlements` | 예 | 예 | 비어 있지 않은 문자열의 배열 |
| `signing` | 예 | 예 | 서명 객체 |

설정 파일에서는 위 필드를 허용합니다. `format`의 설치 형식은 아직 구현되지 않았습니다.
두 채널의 패키징을 실행하면 `PKG_ADAPTER_MISSING`으로 실패합니다.

## OS 최소 버전

Windows 설치 경로는 Windows 10 build 17763 이상을 기준으로 합니다.
설치할 최소 OS 버전은 `targets[].minVersion`에 지정합니다.
지원 기준보다 낮거나 형식이 잘못된 버전 문자열은 거부합니다.
