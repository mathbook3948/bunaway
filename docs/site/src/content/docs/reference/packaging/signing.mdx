## 설정

```json
{
  "bundle": {
    "signing": {
      "certificateFile": "certificates/release.pfx",
      "passwordEnv": "BUNAWAY_SIGN_PASSWORD",
      "timestampUrl": "https://timestamp.example.com"
    },
    "channels": { "win-direct": {} }
  }
}
```

이 예시의 인증서와 timestamp 서버는 배포자가 준비합니다.
`passwordEnv`는 비밀번호 문자열이 아니라 실행 환경의 변수 이름입니다.

| 필드 | 형식, 의미 |
| --- | --- |
| `certificateFile` | 인증서 파일 경로 참조, 비어 있지 않은 문자열 최대 256자 |
| `thumbprint` | 인증서 저장소 thumbprint 참조, 최대 256자 |
| `subject` | 선택적 subject 참조, 최대 256자 |
| `timestampUrl` | 선택적 유효 HTTP(S) URL, 최대 256자 |
| `passwordEnv` | `[A-Za-z_][A-Za-z0-9_]*`, 최대 128자 |

서명 객체에는 `certificateFile` 또는 `thumbprint`가 최소 하나 필요합니다.
설정 검증은 필드의 형식을 확인합니다. 실제 인증서와 도구를 확인하고 서명하는 작업은 패키징 단계에서 진행합니다.
인증서 비밀번호는 `passwordEnv`에 지정한 환경 변수로 전달합니다.

## 채널별 대체

채널의 `signing` 객체가 있으면 최상위 `signing`을 전체 대체합니다.
예를 들어 채널에 thumbprint만 지정하면 최상위 timestampUrl, passwordEnv는 상속되지 않습니다.
같은 필드를 사용하려면 채널 객체에도 적습니다.

## 서명 결과

서명은 배포할 파일에 적용하며 원본 빌드 산출물은 그대로 유지합니다.
서명에 실패하면 이전에 성공한 채널 산출물을 유지합니다.

## 서명 요구 수준

| 요구 수준 | 의미 |
| --- | --- |
| `optional` | 서명 없이도 실행용 산출물 생성 가능 |
| `required-to-run` | 서명 없으면 설치, 실행 불가 |
| `required-to-submit` | 로컬 사용과 Store 제출 조건이 다름 |

`configured`는 서명 설정이 있는지, `performed`는 서명을 수행했는지 나타냅니다.
[보고서의 ok, usable, submittable](/reference/packaging/report/)로 패키징 성공과 사용 조건, 제출 조건을 확인하세요.
공증과 Store 심사, SmartScreen 평판은 서명 이후에도 별도로 확인해야 합니다.
