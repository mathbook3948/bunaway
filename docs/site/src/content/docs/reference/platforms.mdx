## 현재 앱 개발 경로

bunaway는 **Windows를 먼저 완성하고 다른 플랫폼을 같은 Bun 기반 앱 개발 모델에 맞추는 순서**로 개발합니다.
앱 개발자는 공통 `app.ts`를 작성하고, 플랫폼별 부팅은 프레임워크가 담당합니다.

| 구분 | Windows x64 | macOS arm64 | Linux, 모바일 |
| --- | --- | --- | --- |
| 앱 화면 | WebView2 | WKWebView | 미지원 |
| CLI 앱 생성, 개발, 빌드 | 여러 창 설정 지원 | 단일 창과 뷰 | 네이티브 실행 미지원 |
| 런타임 여러 창과 뷰 | 창 생성, 재생성과 제어 정식 지원 | 미구현 | 미구현 |
| 명령, 이벤트 | 지원 | Bun FFI로 검증 | 네이티브 실행 미지원 |
| 개별 네이티브 플러그인 | 저장, 로그, 기능 조회 | 어댑터 미구현 | 미구현 |
| 앱 열기 요청, 종료 취소, 트레이 | Windows 인자 전달, WebView2 숨김, 종료 취소와 CLI 중단 검증 | `desktop` 미지원 | 미지원 |
| 개발 UI DevTools, CLI 백엔드 inspector | 구현, 실제 GUI 검증은 남음 | 미지원 | 미지원 |
| 앱 실행 파일, 앱 아이콘과 실행 실패 안내 | 콘솔 없는 EXE, 창과 트레이 아이콘, 오류 대화상자 | Bun compiled 앱 번들 | 미지원 |

macOS에서는 네이티브 권한 목록을 비워야 합니다. 네이티브 플러그인 권한이 있으면
앱 시작을 거부합니다. macOS 통합 검사는 명령, 이벤트, 화면 복구와 미지원 기능의 거부를
검증하며 현재 저장 플러그인의 동작이나 재실행 후 데이터 복원을 검증하지 않습니다.

`policy.json.views`에 뷰별로 호출할 명령과 받을 이벤트, 저장 범위를 적습니다.
Windows CLI는 `app.windows` 설정을 지원합니다. 선택 창 제어 플러그인은 등록한 앱의 기능 조회에서 `supported`를 반환하며,
창 제어와 반복 재생성을 실제 GUI 회귀로 확인했습니다.
macOS CLI는 단일 창 설정을 사용합니다.
초기 창 크기는 `minWidth`, `minHeight`, `maxWidth`, `maxHeight`로 보정하며,
창 크기를 바꿀 때도 같은 제약을 적용합니다. 제약의 `null`과 생략은 해당 제한을 해제합니다.
WKWebView의 카메라와 마이크 접근 요청은 거부합니다.
macOS는 화면 초기화가 실패해도 백엔드 플러그인의 종료 작업을 기다립니다.
플러그인 초기화 중 창을 닫아도 정리가 완료되면 정상 종료합니다.
종료 요청 후 5초 안에 정리되지 않으면 앱을 강제 종료하며 실패로 처리합니다.
macOS는 종료 시 앱의 프로세스 그룹에 남은 하위 프로세스를 정리합니다.
`unref()`를 호출한 프로세스도 정리하며, 앱이 강제 종료돼도 같은 그룹을 정리합니다.
앱이 새 세션이나 그룹으로 분리한 프로세스는 앱 코드에서 직접 종료해야 합니다.
[창과 뷰의 정책](/concepts/views-and-policy/)을 함께 읽으세요.

## 개발자와 최종 사용자

| 대상 | 필요한 것 |
| --- | --- |
| 앱 개발자 | Bun 1.4.2, Windows의 PowerShell 7 또는 macOS의 codesign과 GUI 세션 |
| Windows 앱 사용자 | 앱 패키지, WebView2 런타임 |
| macOS 앱 사용자 | 지원하는 기기, OS에서 동작하는 앱 패키지 |

앱 패키지에 고정된 Bun을 포함하므로 최종 사용자는 Bun을 따로 설치할 필요가 없습니다.
현재 공개 registry 배포는 없고 로컬 CLI, SDK tarball 설치를 사용합니다.
빌드는 대상 운영체제에서 하며 교차 빌드는 지원하지 않습니다.

## 플랫폼에서 검증한 동작

Windows의 실제 GUI 검증에는 명령, 이벤트, 파일 권한, 다중 창, 복구, 종료가 포함됩니다.
macOS arm64는 Bun FFI의 단일 창, 명령과 이벤트, 리소스 경계와 렌더러 복구, 종료를 검증했습니다. 파일 저장 검증은 이전 구현의 기록입니다. 새 플러그인과 permissions 모델은 Windows에서 검증했으며 macOS 어댑터는 아직 제공하지 않습니다.
배포 서명과 설치, 스토어 제출은 아직 검증이 남아 있습니다.

macOS Intel과 macOS 다중 창, Linux, Android, iOS 호스트는 현재 지원하지 않습니다.
macOS 빌드는 로컬 실행용 ad-hoc 서명을 사용합니다. 배포에는 Developer ID 서명과 공증, 설치 검증이 필요합니다.
생성 템플릿은 vanilla, Vite, React, Vue, Svelte를 제공합니다.
React, Vue, Svelte 생성 앱은 설치, 타입 검사, CSS와 컴포넌트 HMR, 프로덕션 자산 번들을 Linux에서 검증했습니다.
이 세 템플릿의 실제 Windows와 macOS 창 실행은 아직 검증하지 않았습니다. Windows의 로그와 저장은 개별 패키지로 설치하고 등록합니다.
