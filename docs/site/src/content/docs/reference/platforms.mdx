## 현재 앱 개발 경로

bunaway는 **Windows를 먼저 완성하고 다른 플랫폼을 같은 Bun 기반 앱 개발 모델에 맞추는 순서**로 개발합니다.
앱 개발자는 공통 `app.ts`를 작성하고, 플랫폼별 부팅은 프레임워크가 담당합니다.

| 구분 | Windows x64 | macOS arm64 | Linux, 모바일 |
| --- | --- | --- | --- |
| 앱 화면 | WebView2 | WKWebView | 미지원 |
| CLI 앱 생성, 개발, 빌드 | 단일 창과 뷰 | 단일 창과 뷰 | 네이티브 실행 미지원 |
| 런타임 여러 창과 뷰 | 구현, 세 창 실행 검증 기록 | 미구현 | 미구현 |
| 명령, 이벤트 | 지원 | 기존 실행 기록 | 네이티브 실행 미지원 |
| 개별 네이티브 플러그인 | 저장, 로그, 기능 조회 | 어댑터 미구현 | 미구현 |

`policy.json.views`에 뷰별로 호출할 명령과 받을 이벤트, 저장 범위를 적습니다.
현재 CLI의 앱 설정은 창과 뷰 하나를 지원합니다.
[창과 뷰의 정책](/concepts/views-and-policy/)을 함께 읽으세요.

## 개발자와 최종 사용자

| 대상 | 필요한 것 |
| --- | --- |
| 앱 개발자 | Bun 1.4.2, 해당 플랫폼의 네이티브 개발 도구 |
| Windows 앱 사용자 | 앱 패키지와 WebView2 런타임 |
| macOS 앱 사용자 | 지원하는 기기, OS에서 동작하는 앱 패키지 |

앱 패키지에 고정된 Bun을 포함하므로 최종 사용자는 Bun을 따로 설치할 필요가 없습니다.
현재 공개 registry 배포는 없고 로컬 CLI, SDK tarball 설치를 사용합니다.
빌드는 대상 운영체제에서 하며 교차 빌드는 지원하지 않습니다.

## 플랫폼에서 검증한 동작

Windows의 실제 GUI 검증에는 명령, 이벤트, 파일 권한, 다중 창, 복구, 종료가 포함됩니다.
macOS arm64의 기존 기록은 이관 전의 단일 창, 명령, 이벤트, 파일 저장 검증입니다. 새 플러그인과 permissions 모델은 Windows에서 검증했으며 macOS 어댑터는 아직 제공하지 않습니다.
배포 서명과 설치, 스토어 제출은 아직 검증이 남아 있습니다.

macOS Intel과 macOS 다중 창, Linux, Android, iOS 호스트는 현재 지원하지 않습니다.
macOS 빌드는 로컬 실행용 ad-hoc 서명을 사용합니다. 배포에는 Developer ID 서명과 공증, 설치 검증이 필요합니다.
생성 템플릿은 vanilla, Vite, React, Vue, Svelte를 제공합니다.
React, Vue, Svelte 생성 앱은 설치, 타입 검사, CSS와 컴포넌트 HMR, 프로덕션 자산 번들을 Linux에서 검증했습니다.
이 세 템플릿의 실제 Windows와 macOS 창 실행은 아직 검증하지 않았습니다. Windows의 로그와 저장은 개별 패키지로 설치하고 등록합니다.
