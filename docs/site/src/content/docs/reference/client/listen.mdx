```ts
listen<T extends JsonValue = JsonValue>(name, listener, { onError, signal? }): Promise<AsyncDispose>
client.listen(name, listener, { onError, signal? }): Promise<AsyncDispose>
```

이벤트를 구독하고 알림이 발생할 때마다 콜백을 실행합니다. 구독이 성공하면 비동기 해제 함수를 반환합니다.
직접 import한 `listen`은 기본 연결을 사용하고 연결이 준비될 때까지 기다립니다. 별도의 초기화 코드는 필요 없습니다.

## 예시

```ts
import { listen } from "@bunaway/client";

const unlisten = await listen<string>(
  "message.saved",
  (event) => { console.log("저장 내용:", event.payload); },
  { onError: (error) => { console.error(error.code, error.message); } },
);
// 화면 컴포넌트를 제거할 때
await unlisten();
```

## 인자

| 인자 | 필수 | 의미 |
| --- | --- | --- |
| `name` | 예 | 앱에 선언되고 뷰의 `events`에 허용된 이름 |
| `listener` | 예 | 전달 이벤트 객체를 처리하는 콜백 |
| `onError` | 예 | 활성 구독이 오류로 종료됐을 때 실행하는 콜백 |
| `signal` | 아니요 | 구독 시작 및 활성 구독의 취소 신호 |

구독 시작 자체가 실패하면 `listen()` Promise가 reject합니다. 일반 브라우저에서는 `UNSUPPORTED`로 실패합니다.
직접 import한 `listen<T>`의 `T`는 이벤트 payload 타입입니다. 이 타입 지정은 실행 시 검증기를 추가하지 않습니다.
앱 정의의 이벤트 타입을 추론하려면 [앱 타입을 지정한 클라이언트](/guides/types-and-validation/)를 사용합니다.
연결 종료나 이벤트 전달 오류로 활성 구독이 끝나면 `onError`를 호출합니다.
listener에서 예외가 발생해도 다른 요청과 구독은 계속 처리합니다.

## 이벤트 객체

| 필드 | 의미 |
| --- | --- |
| `payload` | 앱 이벤트 스키마로 정의한 데이터 |
| `event` | 이벤트 이름 |
| `source` | 공개 발신 출처: 뷰 ID 또는 backend |
| `target` | 실제 대상 뷰 ID |
| `subscriptionId` | 구독 식별자 |
| `sequence` | 해당 구독의 1부터 시작하는 순서 |
| `kind`, `protocol` | 이벤트 메시지 종류와 프로토콜 |

이벤트 순서는 구독마다 유지합니다. 서로 다른 발행자나 구독 사이에는 공통 순서가 없습니다.
`broadcast`는 이벤트가 허용된 활성 구독에 전달합니다.

## 해제와 취소

해제 함수를 여러 번 호출해도 한 번만 정리합니다. 동시에 호출하면 같은 작업의 완료를 기다리며 해제 뒤에는 이벤트를 전달하지 않습니다.
연결이 이미 닫혔어도 해제 함수를 호출할 수 있습니다.
전달한 signal을 취소하면 구독 시작을 중단하거나 활성 구독을 해제합니다.

세션마다 최대 128개를 구독합니다. 이벤트 큐가 가득 차면 `BUSY` 오류를 알리거나 구독 또는 세션을 종료합니다.

## 재연결

페이지 종료 때 기본 연결과 구독은 자동으로 정리됩니다. UI 컴포넌트를 제거할 때는 반환한 해제 함수를 호출합니다.

이벤트는 활성 구독에만 전달합니다. 연결이 끝났으면 앱 페이지를 다시 로드한 뒤 `listen()`을 호출하고
`message.read` 같은 명령으로 현재 데이터를 읽습니다.
초기 읽기와 갱신 이벤트의 순서는 앱이 필요한 동기화 방식에 맞춰 설계합니다.
