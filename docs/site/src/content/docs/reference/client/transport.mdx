기본 WebView 연결의 사용법은 [createClient](/reference/client/create-client/)에서 설명합니다.
이 문서는 사용자 정의 연결과 테스트 어댑터를 작성할 때 참고합니다.

`createWebViewTransport(bridge)`는 호스트가 제공하는 WebView 메시지 브리지를 SDK의 `Transport`로 바꿉니다.
닫을 때 `close` 메시지로 호스트에 세션 종료를 알리고 브리지 수신 리스너를 제거합니다.
호스트는 해당 문서의 세션을 철회하고 진행 중 요청과 원격 구독을 정리합니다.
종료 알림을 전송하지 못해도 클라이언트의 리스너와 구독은 정리하며, 원격 정리는 호스트의 연결 종료나 문서 폐기를 따릅니다.

## WebViewBridge

```ts
interface WebViewBridge {
  postMessage(message: unknown): void;
  addEventListener(type: "message", listener: (event: { data: unknown }) => void): void;
  removeEventListener(type: "message", listener: (event: { data: unknown }) => void): void;
}
```

네이티브 WebView가 제공하는 `window.chrome.webview`를 전달하고, 반환값을 createClient의 transport로 사용합니다.
사용자 정의 WebView 클라이언트는 다음처럼 만듭니다.

```ts
import { createClient, createWebViewTransport, type WebViewBridge } from "@bunaway/client";

const bridge = (window as unknown as { chrome: { webview: WebViewBridge } }).chrome.webview;
const client = createClient({
  transport: createWebViewTransport(bridge),
  hello: {
    kind: "hello",
    protocol: { major: 1, minor: 0 },
    features: [],
    buildId: "my-app-ui",
  },
});
window.addEventListener("pagehide", () => { void client.close(); });
```

`transport`와 `hello`를 모두 전달합니다. hello의 protocol은 현재 1.0이고 features는 원하는
기능 이름 배열입니다. buildId는 영숫자와 `_ . : -`를 사용하는 1자에서 128자의 식별자입니다.
옵션을 전달한 클라이언트는 기본 연결을 공유하지 않으며 앱에서 수명을 관리합니다.
직접 import한 함수도 이 사용자 정의 전송으로 전환되지 않습니다.
반환값과 오류는 [createClient](/reference/client/create-client/)에서 확인하세요.

## 사용자 정의 Transport

`Transport`와 `TransportEvent`는 `@bunaway/protocol`의 계약입니다.

| 메서드 | 계약 |
| --- | --- |
| `send(text): Promise<void>` | FIFO 큐에 접수하면 완료. 큐가 가득 차면 실패 |
| `subscribe(listener): Dispose` | 원문 message 또는 closed를 전달하고 동기 해제 함수 반환 |
| `close(): Promise<void>` | 멱등 자원 정리와 원격 세션 종료 전달. 이후 전송 금지 |

이벤트는 `{ kind: "message", text }` 또는 `{ kind: "closed", error? }`입니다.
`subscribe`는 첫 send 전에 등록할 수 있어야 하며, 이미 닫힌 전송에 나중에 등록해도 closed를 관찰해야 합니다.
해제 함수를 반환하기 전에 hello 메시지나 closed를 동기적으로 전달할 수 있습니다.
hello로 연결 준비가 끝나면 10초의 준비 기한이 지나도 연결은 유지됩니다.
등록 중 연결이 종료되면 반환한 해제 함수를 호출하고 전송을 닫습니다.
`subscribe`가 예외를 던져도 `createClient`는 클라이언트를 반환하며, `ready`와 대기 호출이 실패합니다.
유효한 프로토콜 오류는 그대로 전달하고 일반 예외는 `INTERNAL` 오류로 처리합니다.

send는 명령의 실행 결과를 반환하지 않습니다. 앱 명령의 결과는 client.invoke로 받습니다.
전송을 직접 구현할 때의 메시지 형식은 [프로토콜 레퍼런스](/reference/protocol/)를 참고하세요.
