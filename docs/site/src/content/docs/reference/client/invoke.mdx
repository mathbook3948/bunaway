```ts
client.invoke(name, input, options?): Promise<Output>
invoke<T extends JsonValue = JsonValue>(name, input, options?): Promise<T>
```

등록된 앱 명령을 호출하고 결과를 Promise로 받습니다.
아래 예제는 [앱 정의의 타입을 지정한 클라이언트](/guides/types-and-validation/)의 `client.invoke`로 호출합니다. 호출은 연결 준비를 기다립니다.
직접 import한 `invoke`도 같은 기본 연결을 사용하는 함수 API로 계속 지원합니다.

## 인자와 예시

```ts
// UI 초기화 때 만든 타입이 연결된 client를 재사용합니다.
const text = await client.invoke("message.read", null);
await client.invoke("message.save", "새 메시지");
```

| 인자 | 필수 | 의미 |
| --- | --- | --- |
| `name` | 예 | 정확한 명령 이름. `app.ts` 등록과 뷰 정책 허용 모두 필요 |
| `input` | 예 | 명령 input 스키마와 일치하는 JSON 값 |
| `options.signal` | 아니요 | AbortSignal과 호환되는 취소 신호 |
| `options.deadline` | 아니요 | Unix epoch 밀리초의 절대 기한 |

입력이 없음을 `{ const: null }`로 선언했다면 `undefined` 대신 `null`을 전달합니다.
Promise는 그 요청의 output을 반환합니다. 직접 import한 `invoke<T>`의 `T`는 반환값 타입입니다.
이 타입 지정은 실행 시 검증기를 추가하지 않습니다.
앱 타입을 지정한 클라이언트는 명령 이름과 입력, 반환값을 앱 정의에서 추론합니다. 명령이 발행한 이벤트는 `client.listen`의 콜백에서 받습니다.

## 기한

```ts
await client.invoke("message.read", null, { deadline: Date.now() + 5000 });
```

기본 명령 최대 시간은 30초입니다. 더 먼 deadline을 주어도 최대 시간을 연장하지 않습니다.
기한은 invoke를 호출할 때부터 계산하며 연결 준비를 기다리는 시간도 포함합니다.
기한이 이미 지났으면 명령을 보내지 않고 `TIMEOUT`으로 실패합니다. 음수나 유한하지 않은 deadline은 `INVALID_ARGUMENT`입니다.

## 취소

```ts
const controller = new AbortController();
const request = client.invoke("message.read", null, { signal: controller.signal });
controller.abort();
try { await request; } catch (error) { console.error(error); }
```

이미 취소된 신호를 전달하면 `CANCELLED`로 실패합니다.
요청 중 신호를 취소하면 Promise가 `CANCELLED`로 실패합니다.
백엔드 핸들러에서는 `context.signal`로 취소를 확인합니다.
취소는 이미 완료된 저장 작업을 롤백하지 않습니다.

## 오류와 제한

| 코드 | 예 |
| --- | --- |
| `UNSUPPORTED` | 일반 브라우저 등 앱 WebView가 없는 환경, 호환되지 않는 버전 |
| `INVALID_ARGUMENT` | 미등록 명령, 잘못된 입력, 프로토콜 데이터 |
| `PERMISSION_DENIED` | 뷰에 없는 명령, 핸들러 내부 Host API 권한 부족 |
| `BUSY` | 세션의 미완료 요청 128개 등 자원 제한 |
| `TIMEOUT` / `CANCELLED` | 기한 초과, 취소 |
| `INTERNAL` | 핸들러 일반 예외, 잘못된 출력, 연결 실패 |

명령 호출과 구독 및 해제 요청을 합쳐 한 세션에서 최대 1,024개까지 요청할 수 있습니다. 제한에 도달하면 새 요청은 `BUSY`로 실패하며 앱 페이지를 다시 로드해 새 세션을 시작해야 합니다.
기한이 끝난 요청의 늦은 응답은 폐기합니다. 재시도가 필요하면 현재 상태를 확인한 뒤 앱에서 다시 호출합니다. SDK는 요청을 자동 재전송하지 않습니다.
[오류 처리](/guides/cancellation-and-errors/)에서 사용자 재시도와 상태 복원을 설명합니다.
