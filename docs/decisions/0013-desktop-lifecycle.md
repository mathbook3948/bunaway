# Windows 앱 열기와 종료를 앱 정의에 연결한다

결정일: 2026-10-07

## 배경

ADR 0006은 같은 앱 데이터 디렉터리의 중복 실행을 거부하고 마지막 창을 닫으면
종료하도록 정했다. 이 기본 동작만으로는 두 번째 실행의 파일, URL 전달과
저장하지 않은 작업의 종료 취소, 트레이에서 계속 실행하는 앱을 만들 수 없다.

## 결정

앱 정의에 선택적인 `desktop`을 추가한다. Windows Bun 호스트가 `onOpen`,
`beforeQuit`, `closeBehavior`, `tray`를 처리한다. 생략하면 마지막 창 닫기로 종료한다.
현재 macOS 프로세스 런타임은 이 옵션을 `UNSUPPORTED`로 거부한다.
다른 플랫폼을 같은 계약에 맞추는 작업은 ADR 0010의 순서를 따른다.

`host.lock`의 독점 소유와 Job 정리는 유지한다. 두 번째 실행은 앱을 import하거나
Worker, WebView를 생성하지 않고 기존 소유자에게 인자와 호출자의 작업 디렉터리를
전달한 뒤 종료한다. ADR 0006의 중복 실행 오류 동작을 이 전달 동작으로 확장한다.
경로를 정규화한 데이터 디렉터리의 SHA-256으로 named pipe 주소를 구분한다.
소유자는 앱 import 전에 pipe를 열고 초기 요청을 보관한다. 코어 준비 뒤 초기 실행을
먼저 전달하고 두 번째 실행을 순서대로 처리한다.

pipe는 인자 최대 256개와 64 KiB의 JSON을 받는다. 시작 대기 요청과 연결은 각각
32개, 앱 열기 작업은 진행 중인 작업을 포함해 64개로 제한한다. 연결과 전달 기한은
5초다. 조각을 계속 보내더라도 기한을 연장하지 않는다. 접수 응답은 요청이 큐에 들어갔다는
뜻이며 앱의 파일 열기 성공을 뜻하지 않는다. 파일 URL은 Windows의 절대 경로로 변환하며
인코딩된 구분자와 NUL을 거부한다.
앱 열기 실패는 진단에 기록하고 이후 요청 처리는 계속한다. 운영체제에서 전달받은
파일과 URL도 검증할 앱 입력이며 Host 저장 권한을 추가하지 않는다.

마지막 창의 닫기는 뷰를 폐기하기 전에 종료 요청으로 전달한다. `beforeQuit`가
`false`를 반환하거나 실패하면 창, 세션, 백엔드를 유지하고 다음 종료 요청을 받는다.
동시 종료 요청은 같은 검사 결과를 사용한다. 승인한 뒤에만 기존 코어, Worker,
WebView 정리를 시작한다. SIGINT, SIGTERM, 호스트 실패와 OS 강제 종료는 이 훅으로
취소하지 않는다. `beforeQuit`에는 자동 기한이 없으며 앱이 완료해야 한다.
Windows 개발 CLI의 중단도 사용자 종료 요청과 구분한다. 재시작과 CLI 종료는
`beforeQuit`와 트레이 숨김을 우회하지만 기존 코어, 플러그인 StopHook과 Worker 정리를 수행한다.
CLI는 앱 HWND에 별도의 WM_APP 종료 메시지를 보내고 UI가 메인에 `closing`을 전달한다.
준비된 주 창으로 전환하는 `windows.completeSplashscreen`은 주 창을 먼저 표시하고
splash 창을 닫는다. 전환의 닫기는 창별 확인을 유지하지만 트레이 숨김과 `beforeQuit`를
실행하지 않는다. 살아 있는 주 창을 남기는 작업이며 마지막 창의 일반 닫기 계약은 유지한다.
트레이 소유 HWND에도 같은 종료 메시지를 적용하므로 앱 창 생성 전에도 중단을 요청할 수 있다.

`closeBehavior: "hide"`는 복원 경로를 제공하는 트레이 설정을 요구한다.
숨긴 창은 HWND, WebView, 세션을 유지한다. 트레이의 Open이나 두 번째 실행으로
살아 있는 창을 모두 복원하며 Quit은 종료 검사를 거친다. 트레이는 별도의 숨긴 HWND를
소유해 앱 창의 수명과 구별하고 Explorer 재시작 뒤 다시 등록한다.
종료 때 아이콘과 소유 HWND를 정리한다. 이 복원 동작은 살아 있는 창을 대상으로 한다.
이미 닫힌 창의 생성과 재생성은 공개 `windows` API와 [ADR 0004](./0004-multi-window-per-view-policy.md)를 따른다.

URL scheme과 파일 확장자의 OS 등록은 설치 기능이며 이번 변경에 포함하지 않는다.
등록된 열기 명령이 실행기에 URL이나 파일 인자를 전달하면 동일한 앱 열기 계약을 사용한다.
Windows 배포 EXE는 Bun compile로 생성하며 인자와 작업 디렉터리를 직접 읽는다.
`-Wait`와 `--devtools`도 앱 인자로 전달한다. 개발 옵션으로 소비하지 않는다.
초기화 실패나 앱을 종료시키는 호스트 오류는 대화상자로 알리고 앱 데이터의 `logs/startup-error.log`에 기록한다.
앱 설정 확인 전에는 확장자를 제외한 실행 파일 이름으로 로그 디렉터리를 정한다.
데이터 경로를 찾거나 로그를 쓰지 못해도 대화상자는 표시한다. 명령 호출 오류는 SDK 호출 결과로 전달한다.
명령줄은 Windows와 호출한 셸의 길이 제한을 따른다.

## 검증

플랫폼 독립 테스트는 인자 정규화, 시작 큐, IPC 접수, 입력 제한, 열기 순서와 실패 복구,
종료 취소와 중복 요청, 모듈 조립과 제어 패킷 방향을 확인한다.
Windows 실행기는 실제 WebView2에서 창 숨김, 백엔드 타이머 지속, 두 번째 실행으로
복원, 종료 취소 뒤 재시도, 정상 자원 정리 시나리오를 실행한다. 복원 후에도 같은 UI
세션의 이벤트 구독과 명령 호출이 동작하는지 확인한다.
개발 중단은 종료 취소, 트레이 숨김과 완료되지 않은 종료 훅을 우회하며 플러그인 정리를 실행하는지 확인한다.
Linux에서 통과한 계약, 번들, 타입 검사는 Windows GUI 검증 완료를 뜻하지 않는다.
