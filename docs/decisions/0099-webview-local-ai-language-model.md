# 온디바이스 언어 모델 API(localAIHandler, LanguageModelUtility)는 제공하지 않는다

결정일: 2026-10-26.

## 배경

Electron이 실험 기능으로 제공하는 `localAIHandler`와 `LanguageModelUtility`에 대응하는 기능을 Windows에서 제공할지 정해야 했다.
이 기능은 렌더러의 온디바이스 언어 모델 접근(Chromium의 Prompt API `LanguageModel`)을 메인 프로세스의 핸들러와 유틸리티
프로세스로 연결한다.

아래 외부 동작은 각 프로젝트의 공개 문서와 알려진 동작에 따른 것이며 이 저장소의 테스트나 WebView2 런타임 실행으로 검증한 것은
아니다. 확인하지 못한 항목은 그렇게 표시했다.

- Electron은 앱 코드가 메인 프로세스에서 핸들러를 등록해 페이지의 언어 모델 호출을 직접 처리하게 하는 실험 API를 둔다.
  모델 실행은 Electron 유틸리티 프로세스 모델에 묶여 있다. 실험 표시가 있어 API 모양이 바뀔 수 있다. 정확한 시그니처와
  버전별 상태는 이 저장소에서 확인하지 않았다.
- Tauri와 wry에는 대응 기능이 없다. 앱이 필요하면 백엔드(Rust)에서 모델을 호출하고 결과를 `invoke`와 이벤트로 페이지에 넘긴다.
- WebView2가 Prompt API와 Chromium 내장 AI API를 어느 채널과 기본값으로 노출하는지는 공개 문서로 확인하지 못했다.
  Chromium에서 이 API는 플래그, 원본 평가판(origin trial), 확장 프로그램 등 제한된 경로로 열리고 모델은 별도로 내려받는다.
  WebView2에서 같은 경로가 열려 있는지, 기본값이 켜짐인지 꺼짐인지는 알 수 없다.
- 브라우저 인자(`--enable-features`, `--disable-features`)로 켜고 끄는 방식이 WebView2에서 실제로 동작하는지도 확인하지 못했다.
  인자는 환경 생성 때만 넘길 수 있고 같은 사용자 데이터 폴더의 브라우저 프로세스 전체에 적용된다
  ([ADR 0030](./0030-launch-arguments-and-environment.md), [ADR 0065](./0065-webview-content-settings.md)).

이 저장소의 백엔드는 이미 같은 요구를 일반 경로로 채울 수 있다. `network.request`와 `network.exchange`로 로컬 또는 원격 모델
서버를 호출하고, `process.run`과 `process.spawn`으로 모델 실행 파일을 띄우며, UI는 `commands`로 백엔드를 부르고 결과는
이벤트로 받는다. 모든 작업은 호출한 뷰의 Host 권한을 따른다.

## 결정

1. 온디바이스 언어 모델용 핸들러, 유틸리티 프로세스, 모델 선택과 다운로드 API를 코어와 공개 계약에 추가하지 않는다.
2. WebView2의 Prompt API와 내장 AI API를 켜거나 끄는 설정도 추가하지 않는다. WebView2 런타임 기본값을 따른다. 기본값이
   켜짐인지 꺼짐인지는 확인하지 못했고, 결정은 어느 쪽이든 같다. 앱은 이 페이지 내장 API가 있다고 가정하지 않는다.
3. 대안은 백엔드에서 모델을 호출하고 결과를 `commands` 응답이나 이벤트로 UI에 전달하는 것이다. 모델 경로, 다운로드 범위,
   사용할 권한 이름은 앱이 정한다.
4. 아래 조건 중 하나가 생기면 별도 결정에서 다시 검토한다. 그때 코어 계약이 아니라 선택 플러그인으로만 두는 안을 기본으로 하고,
   권한 이름과 모델 경로, 다운로드 범위는 앱 책임으로 둔다.
   - WebView2가 안정 채널에서 Prompt API를 기본 제공한다고 공식 문서로 확인될 때. 이 경우 설정 노출 여부만 후속 항목으로
     분리한다.
   - Electron 문서에서 해당 API의 실험 표시가 사라질 때.
   - 이 저장소의 앱이 페이지에서 직접 호출하는 온디바이스 모델을 요구한다고 확인될 때.

## 근거

- Electron만 제공하고 Tauri는 제공하지 않아 둘이 다르다. 코어는 작게, 기능은 필요한 곳에 맞추는 쪽을 따른다. 쓰는 곳이 없다
  (`plugins`, `packages`, `examples`에서 온디바이스 언어 모델을 요구하는 코드는 없다).
- 기능이 실험 상태이고 Electron의 유틸리티 프로세스 모델에 묶여 있어, 같은 이름의 API를 WebView2 위에 만들면 약속하는 동작이
  Electron과 달라지고 원본 API가 바뀌면 함께 바뀐다. WebView2 쪽 노출 상태를 확인하지 못한 채 계약을 만들 수 없다.
- 백엔드가 모델을 호출하는 방식은 Tauri의 방식과 같고 기존 권한 모델을 그대로 쓴다. 모델 파일 경로와 다운로드 대상은
  파일 시스템과 네트워크 접근이므로 앱이 필요한 권한만 선언하는 편이 맞고, 코어가 모델 저장소를 소유하면 모든 앱에 영향을 주는
  경계가 늘어난다.
- 결정을 미뤄도 앱이 막히지 않는다. 같은 결과를 백엔드 경로로 얻을 수 있다.

## 결과

- 코드, 스키마, 권한, 이벤트 변경은 없다.
