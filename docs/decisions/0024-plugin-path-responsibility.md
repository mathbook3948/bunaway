# 파일 경로를 받는 플러그인은 기능만 맡고, 경로 제한은 앱 명령이 맡는다

결정일: 2026-10-19

## 결정

호출자가 넘긴 파일 경로를 쓰는 플러그인(storage, opener, notification의 이미지 경로, process의 실행 파일 경로, dialog의 시작 폴더)은 입력 형식을 검사하고, 받은 경로를 운영체제에 전달해 링크를 따라간다. log는 호스트가 정한 경로만 쓴다.
어떤 파일과 폴더를 다룰지는 앱 명령이 정하며, 이는 앱 개발자의 책임이다.

- policy는 뷰가 호출할 수 있는 `commands`와 `host.permissions`, `backend.permissions`만 정한다. 허용 폴더(scope) 칸은 두지 않는다. ADR 0013(optional native plugins)의 "범용 scope와 matches 계약은 두지 않는다"를 유지한다.
- 화면에는 경로를 제한하는 앱 명령만 허용한다. `plugin.*` 명령을 화면에 직접 허용하면 그 뷰는 해당 작업의 모든 유효한 입력을 쓸 수 있다.
- 플러그인은 열린 핸들을 고정하거나 최종 경로를 다시 비교하지 않는다. 부모 디렉터리 핸들 고정, reparse point와 hardlink 거부, 최종 핸들 경로 재비교, 파일 식별자 재확인은 두지 않는다. 기능 안전을 위한 검사(아래 목록)는 남긴다.

플러그인이 폴더 범위를 보장하지 않는 대신, 입력 형식 검사만 프레임워크가 최소한의 보장으로 제공한다.

## 플러그인에 남는 검사

- 공통: 스키마 검사(빈 문자열, NUL, 개행, 길이 상한), 요청 취소, 응답 크기 제한, 오류 코드 계약.
- storage: 절대 경로여야 한다. `.`과 `..` 요소를 거부한다. Windows에서는 파일 이름 규칙과 장치 네임스페이스 접두사를 거부한다.
- opener: 경로 문법을 검사한다. 확장자 검사와 열기는 같은 경로로 한다.
- 기능 안전: 재귀 삭제와 용량 계산은 링크를 따라가지 않고, FIFO와 장치 파일은 읽기 전에 거부한다. 무덮어쓰기 복사와 이동은 대상을 덮어쓰지 않는다.

세부 항목은 각 플러그인의 변경에서 코드와 같은 커밋으로 정한다.

## 앱 개발자의 책임

| 상황 | 앱이 할 일 |
| --- | --- |
| 화면에서 이름이나 경로를 받음 | 앱이 정한 폴더 안의 경로로 제한한다 |
| 폴더 안에 밖을 가리키는 symlink 또는 junction이 있을 수 있음 | 링크를 해석해 얻은 실제 경로(예: Node 호환 `fs.realpath`)를 다시 비교한다. 어떤 링크 종류를 해석하는지는 앱이 쓰는 API와 플랫폼에서 확인한다 |
| 폴더 안에 밖의 파일을 가리키는 hardlink가 있을 수 있음 | 경로 해석으로는 잡히지 않는다. 폴더에 다른 프로그램이 파일을 만들 수 있다면 앱이 그 폴더의 파일을 신뢰하지 않거나 별도로 검사한다 |
| 검사와 사용 사이에 다른 프로세스가 경로를 바꾸는 경합이 문제가 됨 | 앱이 그 대책을 둔다 |
| 링크가 네트워크 공유(UNC)를 가리킬 수 있음 | 앱이 그 경로를 거부하거나 신뢰할 수 있는 폴더만 쓴다 |
| 외부 콘텐츠를 표시하는 뷰 | `plugin.*` 명령을 직접 허용하지 않고 앱 명령과 최소 권한만 허용한다 |

## 남는 위험

- 앱 명령이 문자열로 폴더를 제한했지만 폴더 안에 밖을 가리키는 링크가 있으면 폴더 밖을 읽고 쓸 수 있다. 쓰기는 코드 실행으로 이어질 수 있다. 링크가 이미 있는 폴더(압축을 푼 폴더, 동기화 폴더, 공유 폴더)를 다루는 앱이 주로 영향을 받는다.
- 검사와 사용 사이의 경로 교체는 막지 않는다. 그 폴더를 바꿀 수 있는 다른 프로세스나 동시 요청이 있으면 일어날 수 있다.
- 폴더 안의 hardlink는 경로가 폴더 안에 있어 문자열 비교와 실제 경로 비교로 가려내지 못한다.
- 링크가 네트워크 공유(UNC)를 가리키면 플러그인은 그 경로도 그대로 사용한다. 네트워크 공유에 닿는 경로를 허용할지는 앱이 정한다.

## 대안

- 허용 폴더를 정책에 선언한다. 정책이 폴더 값을 갖게 되어 ADR 0013(optional native plugins)의 결정과 어긋나고, 앱 명령의 검사와 이중이 된다.
- 핸들 기반 검사를 유지한다. 플랫폼마다 검사 코드와 시험이 커지고, 화면에 직접 허용한 `plugin.*` 명령의 범위 제한은 되지 못한다. 앱이 정한 폴더 안으로 제한하는 책임은 어느 경우에도 앱에 남는다.

## 영향

[ADR 0002](./0002-host-owned-call-context.md), [ADR 0006](./0006-windows-bun-ui-worker.md), [ADR 0013(optional native plugins)](./0013-optional-native-plugins.md)이 파일 핸들 고정, 링크와 최종 핸들 검사를 플러그인이 맡는다고 적은 부분은 이 결정으로 대체한다. 이 문서들과 아키텍처 문서는 log와 notification의 링크 검사를 제거하는 변경에서 이 결정에 맞게 개정했다. opener와 storage의 Windows 구현은 같은 방식으로 제거했고, storage의 macOS 구현은 이 결정에 따라 macOS 변경에서 방어를 제거한다. storage 레퍼런스는 코드를 바꾸는 같은 커밋에서 고치며, macOS 동작은 그 변경 전까지 각 레퍼런스의 macOS 절이 설명하는 대로다.
