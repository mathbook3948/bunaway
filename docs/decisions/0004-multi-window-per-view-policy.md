# 창은 뷰의 수명을 갖고, 뷰별 정책은 창 단위로 분리한다

2026-10-06: 창, 뷰, 정책, 프로필, 세션 분리는 그대로 유지한다. Windows의 별도 Bun 백엔드,
프로세스 IPC와 message-only 창 전달은 [ADR 0006](./0006-windows-bun-ui-worker.md)의
동일 프로세스 Worker 채널로 대체했다. 마지막 창 종료는 코어와 두 Worker를 정리하고
실제 WebView 자식 종료를 확인한다. Bun 자신이 kill-on-close Job에 먼저 들어가 비정상
종료 시 자손을 회수한다. 아래 프로세스 설명은 기존 호스트의 구현 기록이다.

한 앱이 여러 웹 UI를 띄울 때 단일 HWND, WebView, 활성 세션 구조로는 뷰별 정책 적용, 전달, 종료를 표현할 수 없다. Windows 호스트는 창과 뷰의 관계를 다음처럼 정한다.

- 창은 OS 단위다. HWND와 그 창 전용의 WebView2 controller, environment를 소유한다.
- 뷰는 정책 단위다(`GLOSSARY.md` 정의 유지). `app.json`의 `windows` 배열 각 항목이 정책의 `views` 하나를 지정하며, 한 창에는 정확히 하나의 뷰가 붙는다.
- 앱 하나는 번들 Bun 백엔드 프로세스 하나와 창 N개다. 모든 뷰의 세션, 요청, 구독은 하나의 프로세스 IPC 위에서 호스트가 발급한 호출 컨텍스트로 구분한다.

뷰 분리는 프로세스 경계가 아니라 호스트 라우팅으로 한다. 각 뷰는 자기 WebView2 환경과 user-data 디렉터리(자기 브라우저, 렌더러 프로세스 스택)를 갖고, 활성 세션 컨텍스트, 문서 세대를 따로 둔다. 백엔드에서 오는 응답, 이벤트는 컨텍스트로 대상 뷰를 결정하고, 전달본은 그 뷰의 문서 세대, 활성 컨텍스트, 창 생존 여부로 다시 검사한다. 같은 요청 ID를 서로 다른 뷰가 써도 세션별 pending 상태가 분리돼 응답이 엇갈리지 않는다. 런타임→UI 전달은 숨은 message-only 창 하나로 보내, 보이는 창이 닫히는 중에도 포스트 대상이 사라지지 않는다.

종료 규칙은 창 단위로 좁힌다. 한 창을 닫으면 그 뷰의 세션만 폐기하고 창만 파괴한다. 다른 창, 뷰 세션, Bun은 유지한다. 렌더러 장애는 그 뷰의 WebView2 스택에 한정돼, 그 뷰의 세션 폐기와 재탐색만 일어나고 Bun은 재시작하지 않는다. 브라우저 프로세스 자체가 죽으면 닫기 확인 없이 그 창만 종료 처리한다. 마지막 창이 닫히면 앱 종료로 모든 뷰 세션을 폐기하고 Bun을 정상 종료한 뒤 Job Object가 자식을 정리한다.

프로토콜은 바꾸지 않았다. 기존 `session-open`/`web`/`revoke`/`host-request` 프레임이 이미 컨텍스트와 `viewId`를 실어 뷰별 세션을 표현하므로, 다중 뷰는 호스트가 세션, 전달을 뷰별로 관리하는 구현 문제로 유지한다. `app.json`은 `windows` 배열을 추가하되 `{view, home, title, window}` 단일 창 선언도 그대로 받는다.

창이 닫힌 뒤에도 뷰 세션을 살려 창 재생성 시 복원하는 설계도 검토했지만 채택하지 않았다. 창이 없는 세션은 응답을 받을 곳이 없어 유령 요청만 남고, 세션 유지가 요구하는 수명 주기 규칙(재생성 창과 이전 세션의 재연결)은 새 프로토콜을 요구한다. "창 닫기 = 그 뷰 세션 폐기"가 기존 `revoke` 계약에 그대로 들어맞는다.

Windows에서 세 창(쓰기 가능 편집 뷰, 읽기 전용 뷰, 주 뷰)으로 정책 분리, 공유 요청 ID 전달, 이벤트 필터링, 렌더러 장애 격리, 폐기 세션 차단, 창별 종료 규칙을 [실제 검증](../architecture/windows-host-results.md)했다. 공개 `windows.create`, `windows.recreate`는 설정한 창을 생성하거나 이전 세션을 폐기하고 같은 프로필로 다시 만든다. 재생성 중에는 마지막 창의 자동 종료를 보류한다. [Bun 호스트 실행 결과](../architecture/windows-bun-results.md)에 검증 기록이 있다. 다른 플랫폼의 다중 창과 뷰의 창 간 이동은 미구현이다.
