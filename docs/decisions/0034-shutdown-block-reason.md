# 종료 지연(ShutdownBlockReason) API를 제공하지 않는다

결정일: 2026-10-25. 검토 기준: main `ac8dd4a7`.

## 배경

Windows는 `ShutdownBlockReasonCreate`로 앱이 로그오프와 시스템 종료를 지연시키고 사유 문자열을
종료 화면에 보이게 할 수 있다. 앱 정의에 이 기능을 선택 API로 제공할지 정해야 했다.
세션 종료의 현재 계약은 [ADR 0020](./0020-close-and-quit-lifecycle.md)에 있다.
아래 Win32 동작 설명은 이 저장소의 코드나 테스트로 검증한 것이 아니다. 이 저장소에는 해당 호출을 쓰는
코드가 없고, 결정의 근거는 Win32 동작이 아니라 아래 저장소 내부 사정이다.

- 로그오프, 재시작, 시스템 종료와 Restart Manager의 앱 닫기에서 `WM_QUERYENDSESSION`은 항상 허용한다. `WM_ENDSESSION(TRUE)`는 취소할 수 없는 `"session-end"` 종료이고
  UI 스레드는 최대 4초 동안 `onWillQuit`과 플러그인 StopHook을 기다린다.
- 같은 4초 안에 끝나지 않는 작업(대용량 저장, 업로드, 설치)을 위한 수단은 지금 없다.
- `ShutdownBlockReasonCreate`는 창 하나(HWND)에 사유를 붙이는 호출이다. 차단 중 종료 화면이 사용자에게
  종료를 강제하는 선택을 주는지는 확인하지 않았다. 차단 중 앱이 `WM_QUERYENDSESSION`에 FALSE를 답해야 하는지,
  `WM_ENDSESSION` 뒤 `onQuit`을 어디까지 보장할지는 이 저장소에서 정하지 않았다.

## 결정

1. `ShutdownBlockReasonCreate`와 `ShutdownBlockReasonDestroy`에 대응하는 공개 API, 설정, 이벤트를 추가하지 않는다.
2. 세션 종료의 ADR 0020 계약(항상 허용, 4초 기한, 취소 불가)을 바꾸지 않는다.
3. 종료 전에 끝내야 할 저장은 사용 중에 나눠 저장한다. 세션 종료에서는 `onWillQuit`과 Core 정지가
   4초를 나눠 쓰므로(`onWillQuit`이 최대 3초를 쓰면 Core 정지에 1초가 남는다) 마지막 변경분은 이 시간 안에
   끝나는 만큼만 남긴다. 이 방법으로도 부족한 실제 앱 요구가 확인되면 이 ADR을 개정하는 별도 결정으로 다룬다.
4. 나중에 제공한다면 다음을 먼저 공개 계약으로 정한다.
   - 사유 문자열의 길이, 로컬라이즈, 갱신 방법을 정한다.
   - 작업 완료, 앱 정의의 취소, 프로세스 종료, 사용자의 강제 종료 선택에 따른 해제 규칙을 정한다.
   - 차단 중 UI 스레드의 메시지 처리와 `onQuit`, 네이티브 정리의 보장 범위를 정한다.
   - 이 기능을 모든 앱의 종료 경로가 아니라 선택 플러그인에 둘지 정한다. 코어는 작게 유지한다.

## 근거

- 이 기능을 필요로 하는 앱이 아직 없어 계약을 검증할 소비자가 없다. 그 상태로 공개하면 남는 것은
  앱이 시스템 종료를 임의로 막을 수 있는 경로뿐이다. 사유와 해제 시점, 실패 시 동작은 앱 정의가 책임져야 한다.
- 사유 문자열과 해제 규칙, 차단 중 메시지 처리는 한 번 공개하면 바꾸기 어려운 계약이다. 쓰임이 확인되기 전에
  정하면 ADR 0020이 정한 `onQuit`과 네이티브 정리를 보장하지 않는 범위와 맞물려 다시 고쳐야 할 가능성이 크다.
- 코어의 종료 경로는 하나의 처리기를 공유한다. 선택 기능 하나를 위해 이 경로에 차단 상태를 더하면
  모든 앱의 종료 수명 주기가 복잡해진다.

## 결과

- 코드, 스키마, 권한, 이벤트 변경은 없다.
- TODO-windows.md 해당 항목을 결정 완료로 바꾸고 이 ADR을 가리킨다.
- 실제 요구가 확인되면 소비자와 함께 위 4번 항목을 계약으로 정하는 별도 결정과 구현으로 진행한다.
