# Windows 트레이는 앱당 아이콘 하나로 두고 GUID는 지원하지 않는다

결정일: 2026-10-25. 검토 기준: main `1b45a60c`.

## 배경

아래 Electron과 Tauri 서술은 해당 프로젝트의 공개 문서와 소스 확인에 따른 것이며 이 저장소의 테스트로 검증한 것은 아니다.

Windows 트레이가 여러 아이콘, 아이콘별 고유 ID와 Windows GUID를 지원할지, 트레이 자원을 제거한 뒤 앱의 실행 유지와
종료 규칙을 어떻게 정할지 결정해야 했다. 지금 Windows 트레이는 앱 선언 `desktop.tray`가 아이콘 하나를 소유한다.
`tray.*` 작업은 그 아이콘 하나를 대상으로 하며 아이콘 식별자를 받지 않는다. 숨김은 `tray.setVisible`로 제공하고
앱 수명을 바꾸지 않는다. 생성과 제거 작업은 Windows에 없다.

- Electron은 `new Tray()`를 여러 번 만들 수 있다. Windows에서는 `guid` 옵션으로 아이콘을 GUID에 묶을 수 있고,
  서명된 실행 파일이 고정된 경로에 있어야 한다. 트레이 인스턴스를 `destroy()`해도 앱은 종료되지 않는다.
- Tauri 2는 `TrayIconBuilder::with_id`로 여러 트레이 아이콘을 만들 수 있고 `remove_tray_by_id`로 제거한다.
  Windows GUID 옵션은 없다. 트레이 제거도 앱 종료와 연결되지 않는다.
- Windows의 `NOTIFYICONDATA`는 아이콘을 `uID`나 `guidItem`으로 구분한다. GUID로 등록하면 실행 파일의 경로나 서명이
  달라졌을 때 등록이 실패할 수 있다.

## 결정

1. Windows 트레이는 앱당 아이콘 하나로 유지한다. 여러 아이콘과 아이콘별 ID는 지금 추가하지 않는다. 필요해지면
   `tray.*` 작업과 이벤트에 선택 필드 `trayId`를 더하고, 생략하면 `desktop.tray`가 만든 기본 아이콘을 가리키게 하여
   현재 호출이 그대로 동작하게 한다.
2. Windows GUID는 지원하지 않는다. 아이콘 식별은 호스트가 내부 `uID`로 하며 앱이 GUID를 지정하는 옵션을 두지 않는다.
3. 트레이 아이콘 제거 뒤 수명 규칙은 제거 작업이 생길 때 정한다. 지금은 제거 작업이 없어 아이콘이 앱 종료까지 남으며
   아이콘 숨김이 앱 수명을 바꾸지 않는 현재 규칙이 그대로 적용된다. 제거 작업을 추가하면 숨김과 같이 앱 수명에
   영향을 주지 않는 규칙으로 시작한다. Electron과 Tauri도 같은 규칙이다.

## 근거

- 두 프레임워크 모두 여러 아이콘을 제공하지만, 이 저장소의 단일 창 모델과 선언형 트레이는 앱당 하나로 충분하고
  여러 아이콘이 필요한 앱은 확인되지 않았다. 쓰는 곳이 없는 기능을 위해 모든 트레이 작업의 입력과 이벤트에 식별자를
  넣지 않는다. 선택 필드 하나로 나중에 더해도 기존 호출이 깨지지 않는다.
- GUID는 Electron만 제공한다. 서명과 고정 경로를 요구해 개발 빌드나 이동 설치에서 등록이 실패할 수 있고, 앱이
  만날 수 있는 실패 방식이 늘어난다. Tauri가 제공하지 않는 점과도 맞아 코어 계약에 넣지 않는다.
- 제거 뒤 수명은 제거 작업이 없는 지금은 관측할 수 없는 규칙이다. 두 프레임워크가 같으므로 작업이 생길 때 그 방식을
  따른다.

## 결과

- 이벤트, 권한, 스키마, 네이티브 코드 변경은 없다.
- `tray.mdx`의 Windows 한계 문단에 여러 아이콘과 GUID를 지원하지 않는다는 점과 이 결정 링크를 적는다.
