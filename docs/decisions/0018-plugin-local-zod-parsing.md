# ADR 0018: 네이티브 플러그인의 실행 경계에서 Zod 파싱

상태: 채택
날짜: 2026-10-12

## 배경

플러그인 입력과 결과를 JSON Schema로 전송하고 공통 검증기로 해석하면
Zod의 변환, 기본값, 사용자 검사와 record 키 처리를 동일하게 재현해야 한다.
변환할 수 없는 기능을 계속 분류하는 방식은 선언과 실제 실행의 차이를 남긴다.
플러그인은 이미 실행 Worker에 설치 코드로 로드되므로 스키마를 전송할 필요가 없다.

## 결정

플러그인 제작자는 Zod 4로 입력과 출력 스키마를 선언한다. defineNativePlugin은
플랫폼 팩터리가 만드는 어댑터를 감싸고 실행 전 input.parseAsync, 실행 후 output.parseAsync를
각각 한 번 호출하고 완료를 기다린다. 타입은 z.input과 z.output으로 추론한다. 원본 입력이 아닌
파싱한 입력으로 어댑터를 실행하고 파싱한 결과를 반환한다.

manifest와 등록 메시지는 이름, 버전, 플랫폼 지원과 작업 이름을 전달한다.
검사 함수는 설치한 플러그인 번들에 포함하며 JSON이나 structured clone으로 보내지 않는다.
Core와 client, NativeRegistry는 등록과 JSON 전달을 처리하며 의미 검사를 재실행하지 않는다.
호스트의 출처 확인, 작업 권한, 승인, 취소와 자원 회수 순서는 유지한다.

입력과 결과는 파싱 전후 모두 기존 JSON, 크기, 깊이와 Unicode 제한을 따른다.
동기 및 비동기 Zod 검사를 지원한다. I/O Worker는 입력 파싱을 완료한 뒤 승인을 요청한다.
SDK의 NativePluginAdapter.prepare는 파싱한 입력을 가진 일회성 실행 함수를 반환한다.
승인 직후 이 함수가 동기 네이티브 작업을 실행하므로 승인과 실행 사이에는 await가 없다.
결과 파싱은 비동기로 기다린다. 입력 파싱 중 취소되면 실행 함수를 폐기한다.
Zod 콜백 자체는 취소할 수 없으며 늦은 완료와 실패도 관찰하되 취소된 호출은 실행하지 않는다.
입력 실패는 INVALID_ARGUMENT, 결과 실패는 INTERNAL이며 콜백 예외도 같은 안전한 오류로 정리한다.
UI 어댑터 실행 자체의 비동기와 취소는 기존 계약을 유지한다.

앱 명령, 이벤트와 프로토콜 envelope의 기존 JSON Schema는 이 변경의 대상이 아니다.
창 이벤트의 공개 JSON Schema도 유지한다. 같은 값을 반환하는 창 snapshot 작업은
로컬 Zod transform 안에서 이 이벤트 계약의 기존 검증기를 재사용하므로 필드를 복제하지 않는다.

## 영향과 검증

기존 s DSL과 네이티브 작업의 JSON Schema 선언을 제거한다. 플러그인 제작자는 Zod로
이관하고 다시 빌드해야 한다. 저수준 HostAPI는 JsonValue를 주고받고 공개 플러그인 함수가
구체적인 입력과 결과 타입을 제공한다. 기존 manifest와 플러그인 산출물도 다시 빌드해야 한다.

공식 플러그인은 기존 값 범위와 오류 코드를 보존한다. 고정된 Zod 4.6.5의 문자열 max는
Unicode 코드 포인트 수를 센다. 기존 경계 테스트와 Zod 원본 비교,
입력과 결과 변환 횟수, UI 어댑터의 receiver와 취소 컨텍스트, 실제 Worker와 패키지 빌드를 검증한다.

## 현재 Zod 버전의 한계

Zod 4.6.5는 같은 파싱에서 비동기 검사가 시작된 뒤 다른 검사 콜백이 동기 예외를
던지면 parseAsync에서도 먼저 시작한 Promise를 놓칠 수 있다. SDK 없이 Zod만 호출한
경우에도 재현된다. 이 조합의 Worker 종료는 이번 변경으로 해결되지 않는다.
일반적인 검증 실패는 refine에서 false를 반환하거나 검사 이슈로 보고한다.
SDK는 Zod 내부를 수정하거나 전역 unhandledRejection을 무시하지 않는다.
