# ADR 0018: 네이티브 플러그인의 실행 경계에서 Zod 파싱

상태: 채택
날짜: 2026-10-12

## 배경

플러그인 입력과 결과를 JSON Schema로 전송하고 공통 검증기로 해석하면
Zod의 변환, 기본값, 사용자 검사와 record 키 처리를 동일하게 재현해야 한다.
변환할 수 없는 기능을 계속 분류하는 방식은 선언과 실제 실행의 차이를 남긴다.
플러그인은 이미 실행 Worker에 설치 코드로 로드되므로 스키마를 전송할 필요가 없다.

## 결정

플러그인 제작자는 Zod 4로 입력과 출력 스키마를 선언한다. defineNativePlugin은
플랫폼 팩터리가 만드는 어댑터를 감싸고 실행 전 input.parseAsync, 실행 후 output.parseAsync를
각각 한 번 호출하고 완료를 기다린다. 타입은 z.input과 z.output으로 추론한다. 원본 입력이 아닌
파싱한 입력으로 어댑터를 실행하고 파싱한 결과를 반환한다.

manifest와 등록 메시지는 이름, 버전, 플랫폼 지원과 작업 이름을 전달한다.
검사 함수는 설치한 플러그인 번들에 포함하며 JSON이나 structured clone으로 보내지 않는다.
Core와 client, NativeRegistry는 등록과 JSON 전달을 처리하며 의미 검사를 재실행하지 않는다.
호스트의 출처 확인, 작업 권한, 승인, 취소와 자원 회수 순서는 유지한다.

입력과 결과는 파싱 전후 모두 기존 JSON, 크기, 깊이와 Unicode 제한을 따른다.
동기 및 비동기 Zod 검사를 지원한다. I/O Worker는 먼저 UI Worker에 컨텍스트와 작업 권한을
확인하고 허용된 호출만 입력을 파싱한다. 거부된 호출은 검사 콜백도 실행하지 않는다.
입력 검사 허가는 실행 승인을 대신하지 않는다. 입력 파싱을 완료한 뒤 컨텍스트와 권한을
다시 확인해 실행을 승인하며, 파싱 중 권한이 사라진 호출은 실행하지 않는다.
SDK의 NativePluginAdapter.prepare는 파싱한 입력을 가진 일회성 실행 함수를 반환한다.
승인 직후 이 함수가 동기 네이티브 작업을 실행하므로 승인과 실행 사이에는 await가 없다.
Windows UI와 I/O의 grant, macOS의 operation 수락 응답은 입력 검사, 비동기 실행과
결과 파싱 완료를 기다리지 않고 채널 용량을 반환한다. 취소, 컨텍스트 폐기와 종료는
진행 중 요청 정보와 용량을 즉시 해제하고 취소 신호를 중단한다. Windows UI와 macOS는
같은 요청 수명 관리 코드를 사용한다. 완료와 실패는 별도로 관찰하며 취소된 호출의
늦은 결과는 버린다. 이전 호출의 완료가 새 호출의 상태를 지우지 않도록 수명을 구분한다.
입력 파싱 중 취소되면 실행 함수를 폐기한다.
Zod 콜백 자체는 취소할 수 없으며 늦은 완료와 실패도 관찰하되 취소된 호출은 실행하지 않는다.
입력 실패는 INVALID_ARGUMENT, 결과 실패는 INTERNAL이며 콜백 예외도 같은 안전한 오류로 정리한다.
UI 어댑터 실행 자체의 비동기와 취소는 기존 계약을 유지한다.

앱 명령, 이벤트와 프로토콜 envelope의 기존 JSON Schema는 이 변경의 대상이 아니다.
창 이벤트의 공개 JSON Schema도 유지한다. 같은 값을 반환하는 창 snapshot 작업은
로컬 Zod transform 안에서 이 이벤트 계약의 기존 검증기를 재사용하므로 필드를 복제하지 않는다.

## 영향과 검증

기존 s DSL과 네이티브 작업의 JSON Schema 선언을 제거한다. 플러그인 제작자는 Zod로
이관하고 다시 빌드해야 한다. 저수준 HostAPI는 JsonValue를 주고받고 공개 플러그인 함수가
구체적인 입력과 결과 타입을 제공한다. 기존 manifest와 플러그인 산출물도 다시 빌드해야 한다.

공식 플러그인은 기존 값 범위와 오류 코드를 보존한다. 고정된 Zod 4.6.5의 문자열 max는
Unicode 코드 포인트 수를 센다. 기존 경계 테스트와 Zod 원본 비교,
입력과 결과 변환 횟수, UI 어댑터의 receiver와 취소 컨텍스트, 실제 Worker와 패키지 빌드를 검증한다.

## Zod 의존성 패치와 배포

Zod 4.6.5는 형제 검사 중 동기 예외가 발생하거나 union이 먼저 성공하면 이미 시작한
Promise를 놓칠 수 있다. 검사 체인에서는 앞의 검사가 끝나지 않으면 뒤 검사의 실패도
반환하지 못한다. SDK 밖에서도 재현되므로 Zod의 Promise 소유권을 패치한다.

패치는 patches/zod@4.6.5.patch에 보관한다. 검사 목록, 객체, 배열, tuple, union,
intersection, record, map, set와 properties 검사에서 시작한 Promise와 후속 Promise를
즉시 관찰한다. 원래 Promise를 반환하므로 오류는 호출자에게 계속 전달된다.
검사 체인은 먼저 시작한 검사가 끝나지 않아도 다른 검사의 예외를 즉시 반환한다.
정상 결과를 합치는 순서, 콜백 실행 횟수, when과 abort 정책은 유지한다.
전역 unhandledRejection 처리기는 설치하지 않는다.

저장소에서는 Bun의 patchedDependencies를 사용한다. 이 설정은 소비자 앱에 상속되지
않으므로 CLI tarball에 같은 수정 파일과 Zod 라이선스를 포함한다. 앱과 네이티브 Worker를
번들할 때 CLI가 Zod 버전 및 원본 또는 수정 파일의 SHA-256을 확인하고 수정본을 사용한다.
SDK가 스키마 내부를 순회하거나 콜백을 재실행하지 않는다. 소비자의 node_modules는
변경하지 않으며 ESM, CommonJS와 소스 조건을 모두 처리한다. 다른 버전이나 알 수 없는
수정본은 빌드를 거부한다. 브라우저 전용 의존성에는 이 정책을 적용하지 않는다.

플러그인은 Zod 4.6.5를 외부 의존성으로 선언하고 CLI로 다시 빌드한다. 자체 번들 안에
Zod를 미리 넣거나 CLI 밖에서 원본 Zod를 직접 실행한 코드는 이 수정의 적용 대상이 아니다.
CLI의 일반 플러그인 빌드는 의존성을 외부 import로 남긴다.

실제 Worker 회귀는 입력과 출력, I/O와 UI 실행, 늦은 실패와 끝나지 않는 형제 검사를
검증한다. 별도 소비자 프로젝트에 배포 tarball과 원본 Zod를 설치하고, 설치된 CLI가 만든
제품 및 개발 앱 Worker에서 같은 회귀를 실행한다. 변조한 Zod 파일의 빌드 거부도 검사한다.

공식 Zod 릴리스가 이 Promise 소유권 문제를 수정하면 같은 회귀와 정상 동작 검사를
패치 없이 통과시키고 설치된 앱에서도 확인한다. 그 뒤 버전을 올리면서 Bun 패치,
체크섬 목록, CLI의 수정 파일 포함과 교체 코드를 함께 제거한다.
