# 앱 전체 기본 메뉴바를 자동으로 연결하지 않는다

결정일: 2026-10-25. 검토 기준: main `bb18c2f8`.

## 배경

아래 Electron과 Tauri 서술은 해당 프로젝트의 공개 문서 확인에 따른 것이며 이 저장소의 테스트로 검증한 것은 아니다.

앱이 메뉴를 연결하지 않아도 창에 기본 메뉴바를 자동으로 붙일지 정해야 했다.

- Electron은 앱이 메뉴를 정하지 않으면 기본 애플리케이션 메뉴(편집, 보기, 창, 도움말 등)를 Windows 창에도 붙이고,
  `Menu.setApplicationMenu(null)`로 없앤다. 기본 메뉴에는 reload와 개발자 도구 항목이 포함되어 배포 앱은 보통 이를 제거한다.
- Tauri 2는 macOS에서만 기본 앱 메뉴를 붙이고, Windows와 Linux 창은 앱이 메뉴를 설정하지 않으면 메뉴바가 없다.
- 이 저장소는 창 메뉴바를 `menu.attachToWindow`로 연결하고(단일 창 모델, [ADR 0026](./0026-single-webview-single-window.md)),
  편집 role과 창 role 항목을 `type: "item"`의 `role`로 제공한다. 앱이 같은 항목으로 표준 메뉴를 직접 구성할 수 있다.
- 메뉴바는 창의 콘텐츠 영역을 줄이므로 자동 연결은 모든 앱의 창 크기와 레이아웃에 영향을 준다.

## 결정

1. 앱이 연결하지 않은 창에는 메뉴바를 붙이지 않는다. 기본 메뉴 자동 연결과 이를 끄는 옵션을 추가하지 않는다.
2. 앱이 표준 메뉴를 원하면 role 항목으로 직접 만들어 `menu.attachToWindow`로 연결한다.
3. 메뉴 항목 템플릿을 미리 채워 주는 헬퍼도 두지 않는다. 사용처가 확인되면 별도 결정에서 다룬다.

## 근거

- 두 프레임워크가 Windows에서 다르다. Electron은 자동 연결하고 Tauri는 하지 않는다. 자동 연결은 코어 계약을 늘리고
  모든 앱의 콘텐츠 영역을 바꾸며, 배포 앱이 대부분 끄는 동작이므로 코어를 작게 두고 앱이 명시적으로 연결하는 쪽을 따른다.
- 앱이 쓸 수 있는 role 항목이 이미 있어 같은 결과를 앱 코드에서 만들 수 있다.

## 결과

- 이벤트, 권한, 스키마, 네이티브 코드 변경은 없다.
