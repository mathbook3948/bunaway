# 전체화면에 모니터 지정 인자를 두지 않고 디스플레이 변경 때 다시 맞춘다

결정일: 2026-10-25. 검토 기준: main `ee1d2a1d`.

## 배경

지정한 모니터에서 전체화면으로 전환하는 방법과, 전체화면 중 모니터가 제거되거나 해상도가 바뀔 때의
동작을 정해야 했다.

- Electron의 `setFullScreen(flag)`는 boolean 하나만 받고 모니터 인자가 없다. 창이 놓인 모니터에서 전체화면이
  되며, 다른 모니터에서 쓰려면 창을 먼저 그 모니터로 옮기고 호출한다.
- Tauri의 `setFullscreen(fullscreen)`도 boolean 하나이고 현재 모니터를 쓴다. Tauri 2.12부터는 별도 API
  `setFullscreenOnMonitor(position)`이 있어 물리 좌표를 포함하는 모니터에서 전체화면이 된다(좌표를 포함하는
  모니터가 없으면 아무것도 하지 않는다).
- 이 저장소의 `windows.setFullscreen`도 `MonitorFromWindow(MONITOR_DEFAULTTONEAREST)`로 고른 현재 모니터의
  전체 영역을 채운다. 모니터 선택에 필요한 `windows.center`, `windows.moveToAnchor`,
  `windows.moveNextToRect`의 `monitorId`와 `monitors.list`가 이미 있다.
- Windows는 모니터를 제거하거나 해상도를 바꿔도 창 크기를 유지한 채 남은 모니터로 옮기기만 하는 것으로 알려져 있다(CI 러너에서는 모니터를 제거할 수 없어 테스트로 확인하지 못했다). 전체화면
  창은 `WM_DISPLAYCHANGE`를 받아도 이전에는 아무 처리도 하지 않아, 새 모니터를 덮지 못하거나 모니터 밖으로
  넘치는 영역이 남았다.

## 결정

1. `windows.setFullscreen`에 `monitorId`를 추가하지 않는다. 지정 모니터 전체화면은 `center`(`monitorId`)나
   `moveToAnchor`로 창을 옮긴 뒤 `setFullscreen({ fullscreen: true })`를 호출하는 조합으로 얻는다.
2. 전체화면 창이 `WM_DISPLAYCHANGE`를 받으면 지금 가장 가까운 모니터의 전체 영역으로 다시 맞춘다. 제거된
   모니터의 창은 보통 Windows가 옮긴 모니터를, 해상도가 바뀐 모니터의 창은 같은 모니터의 새 영역을 채운다.
   모니터 선택은 메시지 시점의 창 위치로 하므로, Windows가 창을 옮기는 시점이 이보다 늦으면 다른 모니터를
   고를 수 있다.
   이미 맞으면 아무것도 하지 않는다. 최소화된 창은 최소화 중에는 건드리지 않고 복원될 때 다시 맞춘다. 저장한 일반 위치, 크기와 스타일은 바꾸지
   않으므로 해제 동작은 그대로다. Z 순서와 활성화는 바꾸지 않는다.
3. 제거된 모니터가 다시 연결돼도 전체화면 창을 원래 모니터로 되돌리지 않는다. 전체화면은 창이 놓인
   모니터를 따르는 상태이고 되돌릴 위치를 따로 기억하지 않는다.

## 근거

- 두 프레임워크가 다르다. Electron은 전체화면에 모니터 인자가 없고 Tauri는 2.12부터 별도 API를 더했다.
  다르면 Electron을 따르고, 코어는 작게 두며 모니터 선택은 이미 있는 배치 API(`monitorId`)가 맡는다. 전체화면
  계약은 불리언 하나로 유지하고, 쓰는 곳도 없다. 별도 모니터 지정 API가 필요해지면 `setFullscreen`을
  바꾸지 않고 추가할 수 있다.
- 디스플레이 변경 때 다시 맞추는 부분은 위 프레임워크 동작과 무관하게 전체화면의 정의("모니터를 채운다")를
  유지하기 위한 보완이다. 이전에는 모니터를 제거하면 앱이 `isFullscreen`은 `true`인데 화면 일부만 덮는
  창을 받았다.
- 다시 연결 때 원래 모니터로 복귀하는 동작은 복귀 시점을 정하는 추가 상태가 필요하고, 일반 창의 복원 좌표
  보정(`readNormalMonitorInfo`)과 달리 전체화면은 저장할 일반 위치가 영역이 아니다.

## 결과

- 공개 계약, 권한, 이벤트 변경은 없다. 전체화면 창의 bounds가 디스플레이 변경 직후 새 모니터 영역으로
  바뀐다.
- 다중 물리 모니터에서 실제로 모니터를 제거하는 경로는 CI 러너에서 만들 수 없다. 테스트는 Windows가 하는
  이동을 `SetWindowPos`로 재현하고 `WM_DISPLAYCHANGE`를 보내 재맞춤을 검증한다.
