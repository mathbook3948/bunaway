# 앱 빌드는 웹 프로덕션 빌드부터 앱 산출물 게시까지 책임진다

결정일: 2026-10-07

## 배경

Vite 앱의 `build.frontend`는 생성물인 `web-dist`를 가리킨다. CLI가 먼저 이 경로를
검증하면 깨끗한 체크아웃에서는 앱을 빌드할 수 없다. 기존 출력이 있어도 웹 빌드를
실행하지 않으면 이전 UI를 새 앱에 포함할 수 있다. `package --build`도 같은 문제가 있다.

## 결정

1. v1 `bunaway.json`의 `build.command`에 선택적 웹 프로덕션 빌드 명령을 둔다.
   `dev.command`와 같은 실행 파일, 인자 배열이며 프로젝트 루트에서 실행한다.
   shell 해석 없이 환경과 stdout/stderr를 이어받고 `bun`은 CLI의 실행 파일로 해석한다.
2. 프로덕션 `build`는 설정, 정책, 설치된 프레임워크와 실행 환경을 검사하고
   웹 빌드 명령을 실행한다. 종료 코드 0을 확인한 다음 웹 출력과 시작 페이지,
   앱 소스 및 SDK 참조를 검증하고 앱을 빌드한다. 출력 존재 여부로 명령을 생략하지 않는다.
3. 명령을 생략하면 기존 정적 자산 빌드를 유지한다. 웹 출력 정리와 증분 빌드는 외부
   도구가 담당한다. CLI는 파일 시각이나 자체 캐시로 웹 출력이 최신인지 추정하지 않는다.
   `build.frontend`가 앱 출력이나 잠금 경로와 겹치면 웹 명령 실행 전에 거부한다.
   아직 없는 출력도 기존 상위 디렉터리의 실제 경로를 확인한다.
4. `package --build`는 동일한 전체 빌드를 한 번 호출한 뒤 채널 패키징을 실행한다.
   채널, 메타데이터, 플랫폼, 어댑터 검증은 웹 빌드 전에 수행한다.
   `package` 단독 실행은 앱 소스와 웹 출력 없이 기존 앱 산출물을 검증해 패키징한다.
5. 웹 명령 실패나 생성물 검증 실패 시 다음 단계를 실행하지 않는다. 이전 프로덕션
   앱과 채널 산출물은 유지한다. 외부 도구가 수정한 웹 출력은 롤백하지 않는다.
6. 같은 대상의 빌드 잠금을 웹 빌드 시작 전부터 앱 게시까지 유지한다. 다른 빌드가
   웹 출력을 바꾸거나 패키징이 읽는 앱 산출물을 교체하지 못하게 한다.
   웹 명령의 하위 프로세스가 같은 앱의 전체 빌드를 재호출하면 명시적인 재귀 오류로 거부한다.
   SIGINT와 SIGTERM으로 중단하면 실행한 명령과 하위 프로세스를 정리한 뒤 잠금을 해제한다.
   Windows는 기존 Job worker를, POSIX는 별도 프로세스 그룹을 사용한다.
   POSIX 명령은 SIGTERM 전송 후 200ms 동안 기다리고 SIGKILL을 전송한다.
   최초 자식의 종료뿐 아니라 그룹의 실행 중인 프로세스가 모두 종료했는지
   최대 5초 동안 확인한다. 자원을 해제한 좀비는 정리 완료로 취급하며,
   프로세스 목록을 조회하지 못하거나 기한을 넘으면 빌드를 실패로 처리한다.
   macOS에서 종료된 그룹의 신호 조회가 EPERM을 반환할 수 있으므로,
   종료 확인은 `/bin/ps`의 그룹 ID와 프로세스 상태를 기준으로 수행한다.
7. 모든 생성 앱의 `dev`, `build`, `package`, `validate`, `doctor`는 앱 CLI를 실행한다.
   Vite 기반 앱은 웹 도구용 `dev:web`, `build:web`, `preview`를 제공하고
   `dev.command`, `build.command`로 연결한다. 메모 예제도 같은 형식을 사용한다.
8. `dev`, `doctor`, `validate`는 웹 프로덕션 빌드 명령을 실행하지 않는다.
   `validate`는 준비된 프로덕션 자산을 검사하며 파일을 생성하지 않는다.

## 기존 결정과 마이그레이션

ADR 0007의 단일 설정과 정책 분리, ADR 0010의 공통 앱 정의 및 Windows 우선 모델을 유지한다.
ADR 0009에서 별도 범위로 남긴 프로덕션 빌드 자동 실행은 이 결정으로 구현한다.
Next.js SSR 패키징과 다른 플랫폼 호스트의 지원 범위는 바꾸지 않는다.

기존 Vite 앱은 웹 `build`를 `build:web`, 웹 `dev`를 `dev:web`으로 옮긴다.
앱 스크립트에는 `build: bunaway build`, `dev: bunaway dev`를 지정하고
`build.command: ["bun", "run", "build:web"]`, `dev.command: ["bun", "run", "dev:web"]`을 연결한다.
명령을 생략한 기존 v1 설정은 정적 자산을 사용하는 방식으로 계속 동작한다.

## 검증 범위

계약 테스트는 최초 웹 출력 생성, 반복 빌드 갱신, 명령 실패와 출력 누락,
재귀 호출, 개발 모드의 명령 미실행, 기존 산출물 패키징과 빌드 잠금을 검증한다.
웹 출력과 앱 출력의 경로 충돌, SIGINT/SIGTERM 중단 후 하위 프로세스 정리와 빌드 재시도를 검사한다.
정상 종료, 오류 종료, 취소 시 SIGTERM을 무시하는 하위 서버의 포트를 즉시 다시 사용할 수 있는지 확인한다.
배포용 CLI 묶음에는 이 ADR을 포함하며 필수 파일 검사에서 누락을 거부한다.
Vite, React, Vue, Svelte와 메모 예제는 실제 웹 도구를 실행하고 앱에 포함된 자산을 검사한다.
테스트용 네이티브 입력과 설치 파일 단계를 사용한 계약 검증은 실제 Windows/macOS 창,
네이티브 런타임 다운로드, 서명 및 설치 검증을 대신하지 않는다.
